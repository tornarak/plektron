# `harness` — every verb, every action

The complete surface. `harness/tests/test_cli_surface.py` holds this file and
the click command tree together: an action or a flag in one and not the other fails
the suite, in both directions. That gate exists because for most of this
project's life nothing pinned the CLI at all — no test touched it — so the
surface drifted silently into 21 top-level verbs whose flags formed subcommands
nobody had named.

Read `--help` for the reasoning behind a flag; read this for what an action
touches and what its exit code means.

## Conventions

**Two tiers.** A *group* names what the command touches; an *action* names what
it does to it. Every action that names a page takes a `PP-NNN` ref — part, and
scan index within that part — and rejects a bare integer, because the printed
folio is not derivable from the scan index.

**Refs are plural.** `REF [REF ...]` everywhere, so a batch is one invocation
rather than a shell loop. Three actions are singular and say why in their entry:
`tei context` (the payload is one page's collation prompt), `proposal set` and
`proposal replace` (their flags name one entry of one proposal). A flag that names
something only one page has — `ocr zoom --only`, `--out`, `zones check --lines`,
`proposal --path` — refuses a second ref rather than picking one.

**One ref emits what it always did; several pool.** The records gain `ref` as
their first field and land in one table, which is the shape `emit.py` argues
for. An action emitting two tables emits two pooled tables; a list-valued field
becomes its own ref-keyed table, since a nested list degrades the whole outer
table to the verbose form. `tei validate` is the exception and prints one
rendered report per ref, `# REF` separated, because prose does not pool. The
aggregating actions — `ocr corrections`, `proposal marks`, `zones diff`, `zones
paragraphs`, `corpus normalize` — take refs as a *scope* and return one report
however many were named. **Exit is the worst across refs**, and every ref is
parsed before any work is done, so a typo in the fifth cannot leave four pages
written.

**A corpus run is `--all`, never an omission.** Where an action has a
corpus-wide form, the flag says so and its help names *what it enumerates* —
"every page" is four different sets here. Naming nothing is a usage error.
`--all`, refs and `--itinerary` are three ways of naming a work-list and exactly
one may be used. Six actions are plural but deliberately have no `--all`, each
saying why: `ocr crops`, `ocr sheets`, `ocr zoom`, `zones delete`, `tei state`,
`tei seam`. **`--all` does not clobber prior work without `--force`** — `ocr
predict` and `zones predict` skip what a store already holds, `ocr restore`
skips a page whose ground truth is newer than its decision, `ocr blot` a page
whose blot is newer than its ALTO. `zones blot` repaints unconditionally: skip
policy there waits on the dependency graph, which is a sprint of its own.

**Report by default; `--commit` writes.** It is the only write-enable, and it
gates exactly the authored stores: `gt/`, `tei/`, `models/`, and the split and
exemption sidecars. Derived output writes on invocation — crops, sheets, zoom,
blots, `mz/` predictions, the `zones/` view, `review.html`, the assemble scratch
— because there the write *is* the action and the same command rebuilds it.
`proposal.json` is a working file of a live pass, kept with a `.prev` and a
journal, and its editors write directly. The two interactive editors (`zones
edit`, `ocr review`) save without `--commit` too: the save click in the
browser is the human act the flag exists to demand, and a flag typed before the
page was ever seen would attest nothing.

**Exit codes.** `0` clean · `1` a documented gate failed · `2` usage error or a
caught exception. Measurement never gates: `zones check --store mz`, `zones
score`, `zones diff`, `zones paragraphs`, and everything under `find` and
`lexicon` always exit 0.

**A closed set is written `{a,b,c}`, and the gate reads it.** One spelling, on
flags and positionals alike, because `test_cli_surface` holds every
`click.Choice` against its fence in both directions — a value the action rejects
and a value the fence omits are both caught. It went in reading three spellings
(`{gt,mz}`, `gt|mz`, and prose) and found seven drifts on its first run, of which
`views build FARM` was the one no hand-written fence could ever have tracked: five
of its farms are generated by a comprehension over `LEAF_KINDS`. So the
canonical form is not a style rule — it is what makes the values checkable at all.

**One meaning per flag name.** `--store {gt,mz}` names one of a group's two real
stores. A closed set of two, **never a free path and never the read view** — the
view is not a store, and naming it would blend a ratified page and an unratified
one under one exit code, which is the whole reason the set is closed. Omitting
the flag is how a caller asks for the view, i.e. "whatever is current for this
page". It appears in `zones` and in `ocr`; `ocr review` is the only action with a
store *default* (`mz`), because its bare diff needs an independent witness and
the view stops being one as soon as the page has ground truth. `--force`
overwrites existing output. `--out` redirects a
write. `--commit` writes. An action name reused across groups means the same
kind of act: `ocr blot` and `zones blot` both paint a page's raster, and the
group carries which recipe.

**Three output modes, and the default is whether stdout is a terminal.** Down a
pipe it is **TOON** — the compact tabular encoding, and what every example in
this file and in the skills shows. At a **terminal** it is an aligned table,
with columns of numbers right-justified, section rules between a verb's several
tables, and nothing ever truncated: the console is built at the table's own
natural width and a line too wide for the screen runs off the edge rather than
losing a character (`--pager` is how you read the rest of it). **`--toon` forces
TOON at a terminal**, which is how a human reproduces exactly what a skill's
model saw. `--json` gives indented JSON.

**Colour is by type, not by verdict**, and the palette is rich's own `repr.*`
theme rather than one invented here: a null is dim, the two booleans take rich's
green and red, numbers are cyan, headers bold. The renderer knows a cell's type
and nothing about its meaning — it cannot tell `keyed: false` (an unread page)
from `ok: false` (a gate failed) — so a scheme claiming to say which would be a
judgement the display layer is not entitled to make. The exception is `tei
validate`/`tei header`, whose reports print `RESULT: PASS`/`FAIL` themselves;
painting those asserts nothing the text does not already say. `NO_COLOR` beats
`FORCE_COLOR` beats the TTY test.

`--json` and `--toon` are mutually exclusive, and both are on every action
alongside `--root` and `--pager`; the four share the trailing
`--root --json --toon --pager` line of each fence below rather than being
restated per entry.

**Long sweeps draw a progress bar on stderr, and `--all` is the rule.** Every
action that takes `--all` reports the item it is on, how many are done and how
long it has taken — that flag being exactly the statement that the work-list is
however big the store is, which is the only durable criterion here. How long a
verb takes is a fact about a machine: the corpus is read on more than one, and a
sweep that is a second on a workstation is not a second on a laptop. So the
question the rule asks is not "is this slow" but "does the corpus decide the
size", and `test_cli_surface.test_every_corpus_wide_action_reports_progress`
holds it against the parser, so a new `--all` action cannot arrive silent.
Several verbs without `--all` report too — `ocr crops`, `ocr sheets`, `ocr zoom`,
`ocr numbered`, `train score zones`, `train install zones` — which is never a defect; the
rule is a floor. The exceptions are `agents usage` and `agents transcript`, whose
`--all` enumerates this project's sessions in `/tmp`, reaped between runs: a bar
whose appearance depends on when the machine last cleared its temp directory is
not a property of the verb.

**Where `--jobs` appears the sweep is pooled, and it means two different things.**
Threads on the raster sweeps — `zones check`, `zones paragraphs`, `zones blot`,
`ocr gaps`, `ocr blot`, `fig crops`, `views build`, `scans info`, `scans census`,
`scans audit`, `scans space` — where the per-page cost is a PNG decode and the
inflate releases the GIL. **Processes** on the model sweeps — `ocr predict`,
`train score`, `train install` — and on `scans extract`, where the work is
single-core CPU-bound inside scipy, shapely or mupdf; the model sweeps cap on free
VRAM as well as cores, `scans extract` on cores alone.
On the two `train` actions the flag is **zones only**, since only that track
segments a checkpoint in memory; naming it on another track exits 2.
`ocr edit` takes it for the measuring pass `--unsettled` runs before it binds.
`--jobs 1` is the control arm everywhere and builds no pool at all.
`test_the_progress_paragraph_names_every_pooled_action` holds that list against
the parser, since which kind of worker a flag spawns is the one thing about a
pooled sweep the parser cannot say.

**The four `scans` read sweeps are threaded for a machine this is not.** Locally
they are 0.5–1.8 s and most of that is the interpreter starting, so on this
workstation the flag buys nothing measurable and `parallel.py`'s own rule would
exclude them. They carry it for the VPS with the corpus on NFS, where each page's
`stat` and header read is a network round trip and the sweep is latency-bound
rather than CPU-bound — threads absorb latency whatever the GIL is doing, because
a syscall releases it. **That is reasoning, not a measurement**: no NFS mount was
benchmarked, and the honest claim is a predicted win rather than a demonstrated
one. What *was* measured is the round-trip count, which fell on its own: `info`
opened each raster twice and stat'd it twice, and now opens once — 3062 `openat`
to 2224 over 832 pages.

The bar appears only when stderr is a terminal and only once the work has run for
about half a second, so a short run stays silent and a redirected one is
byte-identical to a run with no bar at all. That is what lets the rule be
mechanical rather than a judgement about cost that has to be revisited every time
the corpus grows. stdout is untouched: `harness … > file` holds exactly the
payload.

**The pager is opt-in: `--pager`, `$PAGER`, default `less -SRFX`.** It was on by
default in table mode on git's reasoning — `-F` prints and exits when the content
already fits, so short output was supposed to pass straight through — and the
default is now off because the cost falls on the ordinary case: a table that fits
went through a subprocess and a pipe to arrive looking the same, and one that did
not took the terminal from someone who had not asked. `-S` chops rather than
wraps, which is what makes a wide table readable at all — columns stay aligned
and you scroll sideways — and `-R` carries the colour through. Table mode only,
so a pipe is unaffected. **`zones edit` and `ocr review` refuse it**: they print
a URL and block on a server, and a URL inside a pager on a command that does not
return is a URL nobody reads.

**`--json` swaps the serializer, not the payload** — except on `tei validate`
and `tei header`, where it swaps a rendered human report for the structured
verdict. Both are marked below. Several actions print two tables rather than
one, because TOON collapses a uniform record list and degrades on a ragged key
set, so two key sets must be two tables.

**`--json` is always exactly one document.** Where an action prints one table it
is that table, bare. Where it prints several they become one object keyed by
section — the first taking the action's own name, the rest their own:
`zones check REF --json` is `{"check": {…}, "zones": [...]}`, `corpus normalize`
is `{"normalize": {…}, "would_convert": {…}}`, `tei validate` with several refs
keys each report on its ref. It used to emit N documents on one stream with `#`
comment lines between them, which `json.load` rejects — 15 of 58 measured
invocations — on the one flag whose purpose is being parseable. TOON output is
unchanged either way, including those `#` lines.

Two things to know before consuming it. **The key set follows which sections had
content**, so an action whose second table is empty this run omits its key: use
`.get()`. And the object is emitted **whatever the exit code is** — `views
check` and `tei validate` legitimately return 1 with a full payload.

**Argument validation is the parser's.** Constrained values carry a closed
choice set or a validator; a conditionally-required flag is required. Where two
flags are contradictory the command **refuses** rather than preferring one —
`--json` with `--toon`, `tei seam --continues` with `--fresh` — because
precedence standing in for rejection is what the one-tier CLI was retired for.
A flag whose scope is narrower than its action says so in its entry here:
`zones check --ink` is a sweep flag, `--lines` a single-page one.

**Shell completion.** The parser is click (with `cloup`), so completion comes off
the tree itself — every group, action, flag and closed choice set. Add to your
shell rc:

    eval "$(_HARNESS_COMPLETE=zsh_source harness)"     # or bash_source / fish_source

**`--help` is Markdown, rendered.** These entries and the `--help` text are the
same prose; `**bold**` and backticks are shown as emphasis rather than printed.
Actions are grouped into sections (`harness zones --help` splits the store from
the segmenter), and the four globals sit in their own block below an action's own
flags. `NO_COLOR` turns the colour off; a pipe does too.

**`harness tui`** exists when `trogon` is installed — a form-filling terminal UI
over the whole tree, built by introspecting it. Not a declared dependency (it
pulls `textual`, and has had no release since 2024-10), so
`uv run --with trogon harness tui` is the whole cost of trying it.

## tei

The TEI store, its structural ids, and the seam state folded out of the
committed files. There is no `boundaries.json`: the files are the record.

**Two stores, and they mean different things.** `mz/tei/` is what the rules
produced from `gt/zones/` + `gt/ocr/`; `tei/` is what a reader signed. There is
deliberately **no view** over the pair the way `ocr/` covers the OCR stores — a
view exists to give one name to a page's current best reading, and here naming
them apart is the entire point of `tei diff`.

### tei generate [REF ...]
**Does** builds a first-draft TEI page into `mz/tei/`, by rule. Paragraph boundaries from the keyed `MainZone-P`/`MainZone-Continued` labels and from nothing else; `<pb n>` from the running title's folio; each ToC heading the printed folio opens here, and whose title a block prints at its front, marked `<milestone unit n resp="#mz">`; apparatus zones and caption lines dropped; `MarginTextZone-Notes` split at its printed markers, each note emitted at the foot with its `@n` and each printed marker in the prose wrapped in `<ref type="note" n resp="#mz">`; figures emitted as `<figure n><figDesc>` where their boxes sit; `MainZone-Quote` → `<quote>`; every ratified `tier1_terms` hit wrapped in place as `<foreign index="N">…</foreign>`, the adjudicated glyphs present and the language absent; every printed cross-reference marked as `<ref type n cRef resp="#mz">` over the numeral alone.
**Reads** `gt/ocr/`, `gt/zones/`, `gt/fig/`, `data/readings.md`, `data/toc.json`, `data/authorities.json`, the entity and lexicon stores — every one of them tracked, and no raster.
**Writes** `mz/tei/chukchi-PP-NNN.xml` — derived, gitignored.
**Exit** always 0. A page it cannot build reports `written: false` with the verb that fixes it; that is a worklist line, not a failure of the run.
**Note** **no `--commit`.** The conventions reserve it for the authored stores and this writes `mz/`, exactly as `zones predict` and `ocr predict` do. `--force` is the guard instead, and it guards something specific: a baseline a collator has already copied is one half of `tei diff`, so replacing it mid-review makes that comparison a lie.
**Note** **a sweep reads the six page-invariant stores once, not once a page.** `generate.Stores` carries them — the entity store and its two derived alias tables, the authority names, the printed sigla, and `data/readings.md` — and `build` constructs its own only when given none, so a single-page call is unchanged. It read all six per page until a profile of `--force` put `entities.load` alone at **68% of the run**: 30 ms over 482 files, 691 times, 19,280 `parse` calls. Hoisting them took the corpus sweep from **50.1 s to 8.1 s**, output byte-identical over all 691 pages. Same act `tei validate` performs for `lookup.index` and the entity store, and for the same stated reason — the loop hoisting its own invariant, never a cache.
**Note** **it authors nothing the stores already hold, and guesses nothing they do not.** Every judgement it cannot make leaves a comment naming itself — `unresolved zone (MainZone-Other)` for the catch-all that holds headings, tables, verse and captions alike; a note whose marker reads nowhere in the prose or reads in two places; a figure's place in the prose. Clearing those comments is what review *is*.
**Note** **a heading is linked by joining the ToC to the folio the page prints, and the folio only chooses which title to look for.** `data/toc.json` prints which folio opens each heading, the running title prints which folio this is, and where a block then begins with that heading's own title — word-sequence equality, anchored at the front of the block, set off by the compositor's own mark (`TITLE. — `, or the line end) — three printed witnesses agree and the milestone is a rule's. 126 of the 128 headings the ToC opens on a generated page link this way, with **no ambiguous case at all**: scoping to the folio is what removes the three titles the book prints twice (`Names`, `Anui Fair`, `Taboos`), which matching against the whole ToC has nothing mechanical to choose between. Not `starts_here`, which `collator.md` forbids leaning on — that mark is keyed to a *predicted* folio; this is the printed one, and even so the heading on the page is the whole of the evidence a heading is there. A page printing no arabic folio says `ToC join did not run`, which is a finding about this page's inputs and not about the book.
**Note** **a block that is nothing but a heading stops being a reader's question.** `MainZone-Other`'s `rank: null` says the store cannot tell a heading from a table from verse from a caption, so the generator normally declines too — but where the join consumes the *whole* block, that question has a printed answer and the comment and the block both go. 14 blocks over the corpus. The printed text is not carried across beside the milestone: a page file is div-less, so `<milestone>` is TEI's heading here and it holds an id, not words — `data/toc.json` holds the title and the reading view resolves it, which is why `stores.render`'s cache names the ToC among its inputs. The words are still in `gt/ocr/`, where the page's own words live.
**Note** **a head the printer ran into its paragraph is marked `<label>` where it stands, and carries no `@rend`.** The book sets its two deeper levels run-in (`SEAL-HUNTING. — The Maritime Chukchee …`), so those words *are* on the page and the milestone beside them renders as a bare anchor rather than setting the heading twice. The label says which words are the head — the boundary the join already found — and nothing about how they look: this reads no raster, so naming small caps or italics would be asserting the print off the ToC's level. How each of the four levels sets is `edition.css`'s, keyed on the milestone's `@unit`, and which of the two shapes arrived is in the markup rather than in the level, so a chapter head the compositor happened to run in still comes out right.
**Note** **an expected heading that is not printed is a named question, and it names its cause.** `expected milestone for chVIII (Food) not found on this page` says the ToC opens it at the folio this page prints and no block begins with its title. Where the head *is* in `gt/ocr/` on a line no band covers, the comment says that instead and sends the reader to `harness zones edit` — 2 of the corpus's 2 refusals are that, and both are findings about `gt/zones/` rather than about the page.
**Note** **a `Continued` band joins the paragraph above it.** Both labels used to map to `p` with a block per band, so a paragraph running across a band boundary came out broken mid-sentence — 15 of them over the 274 generated pages. The other 213 `Continued` bands are page-initial and still open a `<p>`, there being nothing above them on their own page to join. A figure whose box falls inside a paragraph is emitted *after* it for the same reason the merge exists.
**Note** **the footnote rules are the printer's marks, so the generator applies them.** A note begins where its superscript is set and anchors where the same character stands in the body: character identity, not inference. `@n` is the digit (`¹` → `n="1"`), the glyph and any thin space before it are consumed since the element stands in for the marker, and 241 of the corpus's 250 notes place this way. The 9 that do not are the refusals — a marker that reads nowhere, or in more than one place — and each says which.

**Note** **a note begins at its marker, and a line head is not the only place the printer sets one.** Where two notes are short the compositor runs them onto one line, and cutting at line heads only lost three of them — `2-018`, `2-038`, `2-056`. Nothing said so, which is what made it worth fixing over the other note faults: the second note's words stayed inside the first's element, the body's `²` was left plain because no note existed for it, and `validate` compared marks against notes with both sides missing the same note. A page that had lost a footnote read exactly like a page that never printed one. An interior marker carries a second witness the head cut does not need — whitespace on both sides *and* a digit exactly one more than the note currently open — because a mid-line superscript can be a figure's locant. It cuts on 3 pages and nowhere else.

**Note** **a chapter cross-reference is marked too**, `type="chapter"` over the roman, on the permissive scan the plate uses: `Chapter` is furniture and `Compare Bogdanovitch, Chapter V.` is refused by the same authority guard. 19 printed, 1 another author's, and all 18 of the rest name a roman `data/toc.json` holds. A chapter named by its title (`See chapter on shamanism.`) is deliberately not matched — `docs/edition.md` has why.
**Note** **figures are placed by geometry and meant to be moved.** `context._figures_on_page` withholds geometry from the *model* on purpose, because placing a figure is not the collator's competence; this reads it anyway, a rule being unable to be persuaded by what it sees. The box puts the figure on the right part of the right page; the anchor the edition wants is where the prose says "(Fig. 87, a)", and the comment at each figure says so.
**Note** **a cited name is linked to the work, on the printed citation form.** `Nelson` is a man and a book and the entity store says so, which is why `auto_forms` withholds a link and the generator asks — 250 times over the corpus. A page locator attached to a name is what a citation is, so `Nelson, pp. 27, 28` resolves to `source:nelson-1899` and `Nelson. Fig. 22, b, shows a sled` does not. Two human-keyed tables must agree — `Authorities Quoted`'s printed sigla, and the `authority:` on a `source:` entry — and the work has to be an entity that already claims the form, so the rule chooses among the store's claims and never adds one. 123 citations resolve, 181 mentions stay prose, 5 refuse because the page prints a discriminator the store does not match. `harness/citations.py`, re-derived by `validate`.
**Note** **a name the compositor broke across a line is linked like any other.** The join keeps the hyphen it broke across, so `Chuk-` / `chee` arrives spelled as the store does not spell it — but a compositor's hyphen is the last thing before the measure ran out and the word's own is anywhere else, and the position is in the ALTO. Refusing the link on the ground that "nothing can tell that hyphen from the word's own" put 54 candidates over the corpus in front of readers and **not one sat anywhere but a line end**; the rule now writes 31 links and asks 4 questions, all 4 about forms that were ambiguous for their own reasons. A hyphen the store lacks sitting *mid-line* is still a candidate, and its comment names the two things it can be. `entities._explained_by_break`, one definition for six call sites; `docs/edition.md` has the reasoning.
**Note** **a cross-reference is marked here rather than found at serve time**, and it is the same act as an entity link: a rule reads printed text, applies a store a human keyed, and stamps `#mz` on what it wrote, which `validate` re-derives on every run. It used to be scanned out of the served HTML, where no collator met it and nothing checked it — and the failure it can produce is a *working* link to the wrong picture, the book restarting its figure numbering at 1 on every plate. What the mark holds is the scan (`@type`, `@n`, and the scoping `@cRef`) and never the resolution: which picture a number names is a join over `gt/fig/`, which moves. Another author's plate is not marked at all, on `data/authorities.json`'s own names — `Sauer, Plate XIV` collides with this book's Plate XIV outright.

**Note** **a page cross-reference is scanned on the deictic, not on the locator**, and it is the one kind that has to prove itself before the guard rather than after. 268 page locators are printed across the generated corpus and only about a quarter are this book's — the rest close a citation, and `p. 24` carries nothing for the authority guard to read: scanned permissively, 155 of the 268 survived it, and every survivor would have opened a real leaf of this book under prose that reads correctly there. So the *construction* is matched — a cue (`See`, `Compare`, `cf.`) opening its own clause and reaching the locator with nothing between — and anything richer prints plain, including page references that are this book's (`See Fig. 110, p. 190`, `Compare the Oˊnmɪlɪn Group, p. 26`). 71 marked, `type="page"` and no `@cRef`, resolving through `apparatus.folio_index` at serve time as every other folio link does. `harness/figrefs.py`'s `_PAGE_HEAD` has the measurement and the two near-misses that shaped the rule.
**Note** **the `opens:` witness is never generated.** It records what a reader saw on the raster, and deriving it from the zone label would leave `tei seam` comparing a value with itself. The label goes in as `<!-- zone-opens: … -->`, the *other* witness; the missing `opens:` is a `validate` error the collator clears by looking at the page.
**Note** **a lang-less `<foreign>` is deliberate and is a `validate` error.** `tier1_terms` is a floor over inventory marks with no language awareness — it fires on a German surname carrying a combining diaeresis exactly as on a Chukchee form — so naming a language would be inferring one from the shape of a word. The wrap says only "a ratified token sits here", and the gate turns each into a question with two answers: assign the language and let `tei expand` write the adjudicated glyphs in, or unwrap because it was never a foreign form.
**Note** **the page is a pure function of the tracked stores, and reads no raster.** `zones.paragraph_starts` reads first-line indents off the scan and used to split a keyed band it read as holding two paragraphs — a measurement adding structure on top of a human's assertion, in a file that recorded no difference between them; on `1-160` a speck of dirt in the gutter took the page's margin, every line then measured as indented, and 20 paragraphs appeared the keying never had. Reporting them as comments instead of cutting failed the same test one level up: every finding that check makes is answered by editing `gt/zones/`, so a ruling had nowhere to live and returned on every run, and the generated page depended on a derived, untracked tree — a fresh clone built *different TEI* from identical stores. The check is `zones paragraphs` now. What is left here depends on `gt/zones/`, `gt/ocr/`, `gt/fig/`, `data/readings.md` and the entity stores, all tracked, so the same inputs give the same bytes.
```
--all     every page holding both gt/ocr/ and gt/zones/
--force   replace an existing baseline [off]
--root --json --toon --pager
```

### tei diff [REF ...]
**Does** what review changed: the generated baseline against the collated page. Element counts as `before->after` where they moved, `gen_comments` (generator questions still unanswered), `lang_less` (wraps still unjudged), `text_same`, and `drifted`.
**Reads** `mz/tei/`, `tei/`, and both generator inputs (to recompute the live stamp).
**Writes** —
**Exit** always 0 — measurement.
**Note** **`drifted` is checked first and makes every other column noise.** It compares the reviewed file's stamp against what the rules produce from *today's* stores, so a baseline regenerated after the collator copied it is reported as such rather than as work somebody did. A diff whose witness may have moved has to say so.
**Note** **`gen_comments` is the row that answers "is this page finished".** Each generator comment names a judgement the rules could not make, so one still standing is a question outstanding — whatever else changed. The absence of edits does not say this: a page legitimately finished with no changes looks identical.
**Note** an aggregate, like `zones diff`: refs scope the table rather than multiply it, and the rows already carry `ref`.
```
--all     every page holding a generated baseline
--root --json --toon --pager
```

### tei context REF
**Does** the whole per-page input contract for the collation pass — everything about the page that is *not* in the page. The page itself is `mz/tei/`, copied to `tei/` by `claim`.
**Reads** `tei/`, `ocr/`, `zones/`, `gt/fig/`, `data/*.json`, `data/readings.md`.
**Writes** —
**Exit** always 0.
**Note** **`page_state` and `catmus_draft` are gone, and `generated` replaces them.** The draft was the pass's input while it authored TEI from plaintext, and `page_state` existed solely so the pass could see the rank of that input — the same bytes arrived whether a human had adjudicated every line or CATMuS had read it once. `tei queue` now refuses a page without `gt/ocr/`, so the rank is one value and a field reporting it is a constant every sibling pays for on every page. A second, lower-ranked copy of the page's text sitting beside the file under review would be worse than redundant: it is the two-witnesses-that-are-one hazard pointed the wrong way.
**Note** **`stem` and `output_path` are gone too**, and the reason they were there is the reason they should not have been. They were justified as redundancy against a write to the wrong path — but that is the guard hook's job, enforced mechanically on every call, and a prompt variable cannot enforce anything. What the redundancy actually bought was a second place for a path to be right or wrong.
**Note** **`tier1_terms` rows carry a `key` as well as an `index`, and they address different things.** The `index` names a token on *this* page and is what `tei expand` writes the ratified string in by; the `key` is the lexicon handle, and is what `{…}` expands anywhere else — `entity alias` and `proposal set` take it, so a Tier-1 toponym can be named without keying a glyph of it. A key is printed only where it resolves back to the very form beside it: a bucket the book spells two ways refuses, and an empty cell means "type this one". Resolved at `min_pages=1`, unlike `tei expand`: that floor guards writing a barely-attested form *into* a page, where naming a form is a different act and a gazetteer page like 1-359 is nearly all hapaxes — at the default it came back empty for fifteen of twenty terms.
**Note** **`page_ref` and `root` remain and are the validator's, not the model's.** `validate` builds its own context and reads exactly these two back: `root` for the full ToC id set (300-odd ids nobody would put in a prompt), and `page_ref` to re-read `tier1_terms` **from the store** rather than from this dict — which is what keeps the `#gt` provenance check a second witness instead of the same one twice.
**Note** `running_title` is the page's own statement of what page it is — `{text, folio, folio_from, bracketed, lines}` — and it is the **second witness** to `expected_folio`, which is a prediction from the preceding transcribed page and knows nothing about this one. The two disagreeing is the signal. The folio is looked for in the head line, then in a bracketed number at the foot of a chapter opening (`QuireMarksZone`), then in the old vocabulary's `NumberingZone`; `folio_from` says which answered. Nothing is repaired: a number that does not parse cleanly leaves `folio` null and stays in `text`, on the same "null means go and look" contract `expected_folio` keeps.
**Note** **`toc_window_folio` names which witness centred the window**, `{folio, witness}` over `expected_folio` / `running_title` / `none`. `toc_window` filters ToC entries by distance from the folio, and `expected_folio` is a prediction from the preceding *collated* page — so at the front of any run it is null, the distance test never fires, and the window falls back to `believed_open`, itself a fold over collated pages and likewise empty. It came back empty, no heading could match an entry not in it, and the pass turns every unmatched heading into an unresolved comment: `1-075` opens the trade chapter with two headings and produced neither. The page's own running title now centres it instead — better evidence anyway, since the page saying what page it is outranks a neighbour's arithmetic. **`expected_folio` is deliberately not filled from it**: that is the prediction, and writing this page's folio into it would manufacture the second witness and leave `<pb>` checked against itself. `witness` is what separates an empty window meaning "nothing near this folio" from one meaning "no folio to be near".
**Note** `figures_on_page` is `{n, caption}` — one record per **printed figure**, `n` being the number the caption itself prints. **Placing a figure is not the collator's competence**; finding where the prose says "(Fig. 87, a)" is. So the pass writes `<figure n="87"/>` and the *build* joins that to zones through `data/readings.md`, and nothing about geometry reaches the model. Two earlier shapes failed the same way: raw `zone_id`s (an opaque string a model cannot check, with the `GraphicZone`/FigDesc pairing left to it — on `1-151` that produced a correct anchor plus a permanent known-false orphan comment about the caption zone), then a page-local ordinal over pictures, which is worse than it looks because **the zone count is not the figure count in either direction** — `1-207` sets fig. 87 *a, b, c* in two boxes with `a` and `b` sharing one, and several boxes routinely tile one irregularly-shaped figure. `n` is null where the caption prints no number and where a figure has no caption at all (`3-006`, `3-007`); neither is an error and neither is referenced from the text. `bbox` went because nothing read it — the collation output carries no geometry.
**Note** `tier1_terms` is `{index, line, text}` — the Tier-1 tokens on this page a human has already keyed, from `gt/ocr/` and never from `mz/` or the view. The pass names one by `index` rather than retyping it; `tei expand` writes the ratified string in. Empty on the 802 pages with no ground truth. What counts as Tier-1 here is `detectors.NON_ENGLISH_HITS` (an inventory glyph or a straight apostrophe), not `INVENTORY_CHARS` alone, which omits U+0027 — the spirant and pause mark, one keystroke from the U+2019 in `LOOKALIKES`. The list is a **floor**: an unmarked ASCII inventory member (`c`, `s`, `j`, `x`) is undetectable and has to be typed, which costs little for a structural reason — what makes a token undetectable is having no marks, and what makes it dangerous to retype is having marks. One token per handle; all 30 spans in committed TEI are single tokens, so a range is built against a real instance rather than guessed at.
**Note** `ocr_lines` is `{index, text}`, and **`index` is what `@facs` cites**. It carried the ALTO `@ID` as `line_id`, a currency no harness verb accepts: `ocr zoom --only` has always taken the index, so acting on a citation meant translating it by hand first. Neither form resolves as a TEI URI today — there is no `<facsimile>` in the corpus — so nothing conformant was given up.
**Note** the three zones that can carry a folio (`context.APPARATUS_ZONES`) leave `ocr_lines`, and `tei generate` drops them from the body — they arrive as `running_title` and as `<pb n>` instead, so the information is restructured rather than discarded. Out of `ocr_lines` for a sharper reason than the body's: that list is the set of `@facs` pointer targets, and a running head, a folio or a signature line is never in the TEI body, so citing one would be a mistake by construction. A **caption** line leaves the body only, since it stays citable. The same filter still scopes `detector_flags`, which is what keeps a hit on a running head out of a payload whose body will never contain one.
**Note** **one of the three singular actions.** The payload is one page's collation prompt, built to be handed to one model for one page; a merged stream of them is not consumable by the thing it exists for.
```
--root --json --toon --pager
```

### tei validate [REF ...]
**Does** the gate on a page's TEI — output contract, `@facs` resolution, a
`@resp` rank on every Tier-1 span.
**Reads** `tei/`, plus everything `context` reads.
**Writes** —
**Exit** 1 on FAIL — the worst across refs, so one failing page fails the batch.
**Note** a Tier-1 span that is **neither glossed nor identified** is a warning, plus the metric `tier1_unglossed`. Glossed means a `<gloss target>` points at its `xml:id`, and nothing else — a span with no id is unglossed exactly, since the id scheme's own rule is that an id exists iff something points at it, so there is no containment fallback to write. Identified means a `<name>` with a declared `@type`, or an entity `@ref` on the span or its wrapper; a bare `<name>` does not clear it, deliberately and unlike `names_untyped`, because "a name of some kind" places a native word nowhere. A form the same page glosses elsewhere does not warn again. A **warning** and not an error: the book leaves forms bare, and no model may write a gloss the page does not carry.
**Note** **every `#mz` claim is re-derived here, and there are two kinds of them.** An entity link is re-derived from `entities/` — the entry still exists, is still ratified, the alias is still uncontested, the text still matches; or, where the form is contested and the page *cites* it, that the locator is still printed after the name, the sigla still resolve it to one work, and that work's entry is still this one. A `<ref>` cross-reference is re-derived from the page's own text: block by block, the same scan the generator ran, with the same `Authorities Quoted` guard. Both directions are checked and the asymmetry is deliberate — a mark the text no longer supports is an **error**, a printed reference carrying no mark is a **worklist** line, since deleting a mark the sentence does not support is exactly what the collator is shown it for. The block cut matters: an anchored `<note>` is scanned as its own block and puts its printed marker back where the element stands, or `illustrated by Nelson.¹ Fig. 22` reads as `Nelson.` in front of this book's own figure and the guard refuses a mark the rule correctly wrote. Metrics `figrefs` and `figrefs_unmarked`.
**Note** `--json` swaps the rendered report for `{ok, errors, warnings, worklist, metrics}`.
**Note** **the one action that does not pool.** Its payload is a rendered report and prose does not tabulate, so several refs print several reports under `# REF` lines. One ref prints exactly what it always did, with no header.
**Note** **every page carries one `<!-- opens: … -->`**, immediately after `<pb>` and ahead of any other comment, from the closed set `indented` / `flush to the measure` / `no witness`. It is the seam's third witness — the first line's indent — and the only one that does not survive into the TEI: the previous page's tail is in its own file and this page's opening text is in this one, while the indent is on the raster. The collator has the image; the coordinator writing `@part` does not, and re-deriving it means reopening a page to answer a question already answered. **Witness, not verdict**: `@part` is the verdict and `tei seam` is the only thing that writes one, so the two are not one fact stated twice. Checked as the first *comment after* `<pb>` rather than the first node — a comment is not an element, so the "pb is first" rule steps over one placed before it, and starting the walk at `<pb>` is what keeps a fixed form from quietly becoming two. `no witness` is in the set because a heading or a plate has no measure to judge against, and left to the comment's absence that answer is indistinguishable from a collator that never looked.
**Note** `--schema` adds the **conformance** check — is this actually TEI — against the committed `data/tei_all.rng` (P5 4.12.0). It catches what no project rule can: an invented attribute, a value of the wrong datatype. The two are complementary and neither subsumes the other — every project rule is expressible in conformant TEI, so the schema is silent on all of them, and a file can satisfy all of them while using an attribute TEI never defined. **On by default** here, off in the library function `validate()`, because compiling `tei_all` costs ~17 s once per process and the test suite calls that function hundreds of times; validating a page afterwards is ~0.3 ms, so a corpus sweep pays the compile once. `tei_all` and not `tei_lite`: the smaller customizations are strict subsets, so one would reject markup this project legitimately writes, and a gate that fails correct input teaches a reader to ignore it. Run it **after `tei expand`** — `index=` is not a TEI attribute, which is what makes an unexpanded page detectable, so it fails here too.
```
--all        every collated page in tei/
--ratified   expect '#ed' instead of '#llm'; a remaining '#llm' becomes a worklist line [off]
--schema     also check the file is conformant TEI, against data/tei_all.rng [on]
--no-schema  skip conformance — the escape for a tight loop, the compile being ~17 s
--root --json --toon --pager
```

### tei expand [REF ...]
**Does** verifies a collated page's Tier-1 forms against `tier1_terms`, drops `index=`, and stamps `#gt`. Fills an empty handle where it finds one.
**Reads** `tei/`, `gt/ocr/`.
**Writes** `tei/`, under `--commit`.
**Exit** always 0.
**Note** the generator puts the adjudicated string in when it builds the page — `<foreign index="7">Uweˊlen</foreign>` — and the reviewer adds the language; this confirms the string still is what `gt/ocr/` says before rewriting the rank, and reports a disagreement rather than overwriting it. **The model's judgement is which token and what language; the glyphs are never its to originate.** The handle used to arrive empty and be filled here, which was right when the pass authored the page from a plaintext draft; once a rule was making the copy, the emptiness bought no fidelity and cost the reviewer a lookup before it could judge a word it could not see. Retyping `ɪᵋplɪˊlᴇ` character by character puts §5's two residual classes back on the table (a dropped U+0323, an `ɪ` read as `i`), and both are unfalsifiable downstream — the form still looks like a form, no lexicon knows it, no second reader exists, and CATMuS reads 0% of the inventory.
**Note** **`gt/ocr/` only.** `tier1_terms` is empty on the 802 pages with no ground truth, so there is nothing to expand there and that is correct: a list built from `mz/ocr/` would be garbled forms offered to be copied verbatim, which is this failure inverted rather than avoided. On those pages the pass reads the raster, writes its best attempt and flags the line.
**Note** a handle naming no term is left **exactly as it is** — not dropped, not guessed at. `tei validate` errors on a surviving `@index` and names the missing step rather than a dangling reference, `@index` not being a TEI attribute. Removing it would leave a Tier-1 element holding whatever the pass typed, indistinguishable from one that never asked.
**Note** a handle on an element that **already holds text** is a conflict, not an override: two claims about the same glyphs, reported with neither written. Same for a handle on an element with no Tier-1 `xml:lang` — English is not transcluded.
**Note** an expanded span is written **`resp="#gt"`** — *adopted*, transcluded whole out of adjudicated ground truth. `#llm` is false about it (no model chose those characters) and `#ed` is false too (no human read this document); the responsible act happened one artifact upstream and this records where. It is **not a promotion**: the human act the firewall requires did happen, at the raster. `#gt` is not a third point on the `#llm < #ed` order — its authority over glyph identity is an editor's, so it does not sit below `#ed`, and its subject is a different artifact, so it is not `#ed`.
**Note** the rank is **verified, not accepted.** `tei validate` checks every `#gt` span for membership in the page's `tier1_terms` — whole-token by construction, so a dropped final mark cannot pass the way it would past a substring test (`Qeˊñ` is a substring of `Qeˊñu`). Two consequences: a `#gt` claim on a page with no ground truth fails and says so, and correcting the ground truth under an adopted span makes it fail rather than go stale, which is the property a written-once attribute could not have.
**Note** a page with no handles reports `resolved: []` and is not an error — every page collated before this existed, and every page with no native forms.
**Note** with more than one ref and `--commit`, every page is previewed before any is written — the same up-front rule `ocr restore` and `tei ids` keep.

```
--commit  write the ratified forms [off — reports what would change]
--root --json --toon --pager
```

### tei header
**Does** the gate on `tei/corpus-header.xml` — that the ranks it declares are exactly the ones `tei validate` enforces.
**Reads** `tei/corpus-header.xml`.
**Writes** —
**Exit** 1 on FAIL.

**The four browser tools share one server.** `edition serve`, `zones edit`,
`ocr edit` and `ocr review` are one FastAPI app in one process listening
on four ports — 8731 review, 8732 zones, 8733 lines, 8734 edition — so `--port`
names *this editor's door onto it* rather than a server of its own. **Each door
admits one editor**: a request for another editor's prefix is refused with a 404
naming the port that owns it, so a stale tab or a mistyped path cannot write
through a tool nobody opened. Three consequences worth knowing at the command
line:

  * **A second invocation joins the running server** rather than failing on a
    held port. It hands over its session — the itinerary, the queue, the walk —
    prints `(joined the running server)` and opens a tab. Which is what the four
    separate processes used to give for free, and what one process binding all
    four ports would otherwise have taken away.
  * **A leftover process holds every port, not just its own.** A `zones edit`
    nobody stopped will refuse an `edition serve`, and says which port and which
    editor is holding it. Exit 2, the usage-error code.
  * **The handoff still crosses ports, and only it does.** A second invocation
    posts its session to the *target* editor's port, so `/session/{editor}` is
    exempt from the isolation above, along with `/stop` and `/static` — those
    three belong to the process rather than to a page. Everything else is scoped
    to the door it arrived at.
**Note** `--schema` checks conformance too, as on `tei validate` and on by default. The header is a bare `<teiHeader>` and `teiCorpus` requires a `TEI` child, so there is no conformant container for it — it is wrapped in a minimal `<TEI>` **in memory** to be checkable, never on disk, since inventing a container there would settle the assembly scheme by accident. This found the first defect on its first run: `version="stock"` on `<application>`, where `teidata.versionNumber` is a pattern that does not match it, in a file read by hand more than once.
```

--no-schema  skip conformance — the compile is ~17 s
--root --json --toon --pager
```

### ocr grep PATTERN [REF ...]
**Does** lines matching a regular expression, across whichever pages are named — the corpus text search. Measurement; never gates.
**Reads** the `--store` store, or the view, `gt/lines/_ink_exempt.json`.
**Writes** —
**Exit** always 0, a search that found nothing included. Nothing here is a gate, and an absent form is not a defect.
**Note** **the pattern is normalized to NFD before it compiles.** The store is NFD corpus-wide and a pattern typed or pasted anywhere else may not be: a composed `č` would match nothing and report a clean corpus-wide negative, which is the worst answer this verb could give. Never NFKC — it destroys two inventory glyphs.
**Note** **the `scope` row prints on every run, empty result or not.** A search that found nothing has two readings — the corpus does not say this, or the pages searched do not hold it — and only `store` and `pages` separate them. **Note** case is significant by default. This corpus sets Tier-1 forms with case that carries information, and a native form is more often sought exactly than approximately; `-i` folds it.
**Note** `--context N` adds the surrounding lines, carrying `hit: false`, on `lexicon lookup --context`'s reasoning — `Kuluˊči` alone is a string, "around Kuluˊči Bay" is a place. **Note** **`grep` over `gt/ocr/*.xml` is not this, and it answers a clean false negative.** ALTO holds one word per `<String CONTENT=…>`, so a form the page prints is in the file as several attributes with markup between them and a literal search for it matches nothing — not an error, not an empty store, a *zero*, which reads as "the corpus does not print this". Four forms were ruled unattested that way and all four are in the gazetteer. This verb assembles the line before matching, which is the whole reason it exists; the same holds for `mz/ocr/`, and for the same reason `find`'s searches go through a verb rather than through a path.
**Note** **`lexicon lookup` is the other search and is not this one.** That one is over *ratified native forms*, reached by a typeable ASCII key and folded across the axes this pass gets wrong; this one is over raw line text, reaches English prose, and knows nothing about spelling variants — a word the book sets two ways answers here twice and there not at all.

```
--root --json --toon --pager
```

### ocr gaps [REF ...]
**Does** bands of ink no TextLine covers — the dropped-line detector. A band is a place to look, not a verdict.
**Reads** the `--store` store, or the view, `scans/`, `gt/fig/`, `gt/zones/`, and both `_ink_exempt.json` layers.
**Writes** —
**Exit** always 0.
**Note** `--all` is the corpus dropped-line sweep, at a raster read per page. It reads through the view unless `--store` narrows it, which is `ocr pages`' rule — a machine-read page is workable, and this verb neither gates nor publishes a rate.
**Note** each band reports the `zone` containing it, or empty for none, resolved by overlap against `gt/zones/`. A page with no zoning yields no containment and every band reads out-of-zone — the honest degradation, not a gate; it is `ocr edit` that requires zoning, not this.
**Note** **authority runs downstream only, and `layer` names whichever ruled.** Zoning is the first stage of accounting for the page's ink and recognition is the last — `ocr blot` over a finished page should leave a blank leaf — so `gt/lines/_ink_exempt.json` settles any band, in a zone or not, while `gt/zones/_ink_exempt.json` settles only what is already outside every zone. **Note** **Flagged, never suppressed** — an exempted band still reports, carrying `exempted`, its `note` and its `layer`, because dropping it would make this the one place a wrong call could hide. Earlier this verb read no ruling at all, and an OCR-side reader re-adjudicated from the raster a band a human had already settled.
**Note** a **corrected** band is the one thing that does drop out, since the box now covers the ink — so a `pages_corrected` table reports each correction with its zone, position, size and whether anything is keyed in it. **Note** **a ruling carries which of two dispositions settled the band, in `reason`.** Without `covered_by` it is `not_type` — the ink is not printing. One disposition used to carry both claims, and the note people wrote said the opposite of the heading it was filed under — `1-051` still reads "half of undersized folio line" under a ruling meaning "not type". There is deliberately no way to resize a line instead: the extent is not what makes it that line.
**Note** **`covered_faults` is the half `not_type` could never have.** A ruling that ink is not printing rests on the paper alone and nothing here can weigh it; a ruling that ink is covered by line N names something the store can be asked about, so it is checked — `no_line` where the index is not in the store, `empty_line` where it is there and keys nothing, which means the reading really is missing and the exemption is hiding what it claims to account for. What it cannot check is whether N's text is the *right* text; that is a reading, and the strangulation rule in the reader contract covers it.

### ocr edit [REF ...]
**Does** the line-correction editor in the browser — the human end of `gaps`, and `zones edit`'s sibling one stage down. Adopt a band as a line, rule it not type, or rule it already keyed by a line whose box strangled it; the verdicts in one sitting, because deciding between them is one act.
**Reads** the `--store` store, or the view, `scans/`, `gt/zones/` and `gt/lines/` with both `_ink_exempt.json` layers, `gt/fig/`, `data/zones_config.json`.
**Writes** `gt/lines/` and `gt/lines/_ink_exempt.json` on save. **No `--commit`** — the save click is the human act, the same contract `zones edit` and `ocr review` have.
**Exit** 2 if nothing supplies a start page.
**Note** **it draws and never keys.** A recovered line's text is adjudicated in `ocr review` like any other line's and written by `restore`; duplicating that machinery here would be a second place a reading could be originated, and this store exists on the argument that its writer cannot originate one.
**Note** **a box in no zone is refused, and the refusal names `zones edit`.** Ink no region covers is a defect in the *zoning*, not a line this editor can adopt — recording a line inside no region would leave the region missing. **Note** `b` toggles the blotted view, rendered on demand with **both** ruling layers painted, so what is left is what nobody has settled. That is deliberately the opposite of `ocr blot`'s default, which stays an independent witness.

The overlay's stylesheet and the panel's key list are both *generated* from it, so a rebound key moves in one place and the help cannot lie about the tool.
**Note** **the panel is a control surface, not a legend**: every action's row does the thing when clicked, so it is reachable without knowing its shortcut or having kept one. A key may be set to `null` — the shortcut comes off the keyboard, the control stays. A reason recorded once through a prompt and never shown again is a record nobody can check, and the whole argument for requiring one is that a year later it is all that separates a ruled artifact from a hidden mistake.
**Note** **`cover_band` picks the covering line by clicking it, never by typing an index.** The overlay draws no line numbers, so an index typed into a prompt is a number a human cannot read off the page — they would be guessing, and a guessed reference is the silent wrong answer the field exists to make checkable. ### ocr claim
**Does** takes the next unclaimed ref off `review/_queue.txt` and prints that page's block — the ref, what the four-store survey found (line and zone counts, and which of the two things a `gaps` band means on this page), this page's own crop geometry, and the forms the pages just before it were adjudicated to hold, from between `<!-- prompt:begin -->` and `<!-- prompt:end -->`.
**Reads** `review/_queue.txt`, `review/_claims/`, `dispatch.md`, the four stores, `gt/ocr/` for the nearby forms.
**Writes** `review/_claims/PP-NNN`, stamped with the local time. Block to stdout as plain text.
**Exit** 0 with a block; 1 when the queue is empty or every ref on it is taken.
**Note** **takes no ref, and that is the point** — the page arrives from a tool result rather than from a prompt that would then differ between siblings. `O_CREAT|O_EXCL` is the whole lock: the kernel decides which of several readers created the marker first, so there is no window between the check and the take. Readers are dispatched simultaneously and cannot see each other, so a lock resting on politeness rests on nothing; eight concurrent claimers over a three-ref queue return three distinct refs.

**A claim is never released.** A reader that dies holding one leaves its page unread and its claim standing, which is the honest state rather than a silent retry — `reconcile` names the ref, and re-queueing it is a decision somebody makes. Exit 1 on an empty queue rather than an empty success: a reader handed silence at exit 0 has been told nothing, and picking a page for itself is exactly what a silence invites.

**The nearby forms are offered as handles, never as text** (`lookup.nearby`). A reader can only look up what it thinks to look up, and this says what the neighbourhood has recently been keyed as so it knows what is worth a `lexicon lookup`. Reaching for a handle writes `as_typed`, so leaning on the corpus is recorded where a pasted string would be indistinguishable from an independent reading.

**A word the book sets more than one way is shown as both spellings with their counts, and keyed as neither.** Refusing to pick a side is not a reason to conceal that there are two — a reader shown nothing reads its own page as though the word were settled. No row of such a bucket carries a key, so the block still cannot resolve an ambiguity, and the cap is per bucket rather than per row because half a contested pair read as a lone form is worse than showing none of it. What the list is *for* is standing text and lives in the agent body, not here — the block carries only the list.
```
--root --json --toon --pager
```

A ceiling alone left 1 and 3 legal and readers used them as places to hesitate; measured over one six-page batch, **236 crops were taken and not one was at the default 2×** — every call overrode it, 226 to 4× and 10 to 3×. Two of those pages were never finished: their readers spent 80 turns at two turns a crop (issue, then read the image) and had none left to write with. So the middle rungs are gone, and what replaces the prose is arithmetic from the page's own median line: at 2× one crop returns ~38% of a line and four fit a sheet; at 4×, ~19% and two. A whole line is 3 strips at 2× and 7 across two sheets at 4×.

**`--reason` is required, and it is required of a model rather than of a person.** Nothing about any single crop in that batch looked wasteful; the waste was only visible as a count, after the page had failed. A reason makes the sequence legible in `agents transcript` — where re-aiming a miss reads differently from asking the same question louder — and asks the caller to have a question before it has an image.

**`--zoom` is capped at 4 by the parser, not by prose.** At 300 dpi a character stands about 30 px, so at 4× every ink pixel is already a 4×4 block and there is no source detail left: what a higher number returns is the resampler's opinion, not the paper's. That was a rule in the pass doc for months and was broken anyway — `2-245` spent ten calls at 6× on a shape question, and the first reader dispatched under `queue`/`claim` went to 6× nine times and settled a laryngeal identity on one of them. A confident answer at a magnification carrying no more information than the one below it is worse than an unresolved one, because nothing downstream re-opens it. A doubt that survives 4× **is** the finding: put it in `note`.

**A span is widened, never obeyed literally, and that is deliberate.** A strip is a fixed `window` of source pixels and the sheet is padded to `--client-w` regardless, so a span narrower than one strip renders inside white space you have already paid for. It is therefore expanded symmetrically to fill the window — sliding rather than shrinking at a line edge — and then both edges snap outward to the nearest blank pixel column, bounded, so **no glyph is ever cut**. The rendered span, not the requested one, is what the label and filename record: two requests that widen onto the same region are one picture and must share one file.

This exists because clipping does not cost a bad image, it costs a *re-call*. `2-134` took ten zoom invocations, most of them the same doubt re-aimed after the previous span cut the word in half. Widening absorbs a few points of aiming error for free; it cannot absorb twenty, and a doubt that needs *locating* rather than resolving belongs at `ocr sheets --only`.

**`@P` names one point and is the form to reach for; `@LO-HI` names a range.** A range asks for two numbers about a word whose extent the caller cannot see yet, and the second number is the one that goes wrong: a span too narrow is widened to the window anyway, and a span off-centre misses and costs a re-call. `1-041`'s reader spent three crops framing one word — `23@45-65`, then `23@70-90`, then `23@60-75` — where `23@60` is one. A point asks only where the word *is*, which is the part a reader can actually see from a composite, and the window is a fixed width of source pixels regardless. A range narrower than one crop is reported back as such, with the figure it was widened to.

**The edges are exact, and that retires the guess entirely for the two commonest doubts.** A span is slid rather than shrunk at a line boundary, so `N@0` is the head of the line and `N@100` its tail *whatever the line's length* — no estimate, no re-aim. A footnote reference marker is `@100`; its opener at the foot of the page, and a folio set hard against the left margin, are `@0`. These are the positions the pass returns to on nearly every page, and until they were written down readers were arriving at them by trial: `1-039`'s folio took five crops, four of them margin-widened, on a line whose number sits at one end of a 62px box.

**`@LO-HI` names a percentage of the line's width, and it is where the saving at this rung is.** A doubt is about a mark, not a line, and a mark is a few percent of a full measure — `3-063`'s footnote openers sat in the first characters of their lines, so `42-43` rendered four strips apiece of which three bore on nothing, where `42-43@0-25` renders one each. Percentages, not pixels: the caller is reading a report, not measuring a raster, and a pixel span would demand a measurement nobody has taken. **One line may be named at several places and renders one crop each** — `1@0 1@100` is a line's two ends, one call. That was refused for a while on the ground that unioning two spans returns the whole-line hull, which is true of a union and was the wrong conclusion: two places are two pictures, nothing is merged, and three readers in one batch each typed exactly this and were told to pick one and come back. A whole-line request absorbs the places on that line, since it already contains them. `ocr sheets` refuses a span outright — it shows whole lines and has nowhere to honour one.

Each sheet is named for the lines it holds and the settings that drew them — `zoom2-26-27.png` is lines 26–27 at `--zoom 2`, `s` marks `--smooth`, and a line whose strips straddle two sheets takes a `-b` suffix. **Two selections over one page therefore cannot overwrite each other**, and an overlapping selection reuses the sheet it already agrees with. They could: sheets were numbered `-001` upward per call, so a second `--only` replaced the first's images while the first's returned index went on naming them — three parallel calls yielded one call's pictures and three reports of them. Finer overrides (`--window`, `--overlap`, `--client-w`, `--height`) are *not* in the name and do reuse it.
```
--store {gt,mz}  which store to read [omit: the ocr/ view]
--reason TEXT why this crop, in a few words (required)
--zoom {2,4}  display px per source px, as delivered [2]
--window N    source px per strip [derived from --zoom; overriding upward breaks the scale]
--client-w N  px the reading client shows per image [1450]
--overlap N   px shared by consecutive strips [60]
--height N    max sheet height in px [1600]
--smooth      Lanczos instead of nearest-neighbour [off]
--out PATH    write elsewhere [review/PP-NNN/zoom]
--root --json --toon --pager
```

### ocr review [REF ...]
**Does** adjudicate reading proposals in the browser.
**Reads** the `--store` store, or the view, `review/PP-NNN/proposal.json`, `scans/`.
**Writes** `review/PP-NNN/decision.json`; `review/PP-NNN/review.html` under `--html`.
**Exit** 0.
**Note** the **first action to take more than one ref**, for a reason the rest of the CLI has since caught up with: its cost is a human's attention rather than a process's. `--all` is the pending-adjudication queue — every page holding a proposal and no decision. One server runs over the whole batch, one page on screen at a time, reached by navigation — never several pages merged into one document, since a field belonging to a page other than the one you think you are keying is this pass's oldest failure. (`--issues` is the single, guarded exception; see below.) **Adjudicated-ness is read off the disk** (`decision.json` exists), never held in the process, so a reload, a second tab or a restart cannot contradict it; a re-run therefore resumes the batch rather than restarting it, and a page that already carried decisions shows done and stays reachable from the strip. `Done` advances to the next unadjudicated page and stops the server only on the last one. A single ref renders and behaves exactly as before — no strip, no navigation.

Each line carries a **`+ note` button** and, once asked for, a note field: the adjudicator's own record, saved into `decision.json` as `note` beside `text`. **Opt-in in both places** — a field on all 45 lines would be 45 empty boxes competing with the 45 that matter, and an empty `note` written on every line would make "which lines were remarked on" unfindable, the key existing being the only way anyone asks. Distinct from `proposal.json`'s `note`, which is the reader's account of its own work; these live in different files so a human ruling is never mistaken for a model's. A note is not an edit, so a page saved with only notes reports `0/N edited` and `restore` is a no-op on it.

**The entry boxes are set in Brill by default, and the type is a knob.** A review is an hour of comparing a crop against a box directly under it, so the face is an ergonomic parameter: the Memoirs are a Brill, and matching the entry to the printed face makes that comparison two renderings of one design rather than a translation between two. The fallback stays DejaVu Serif, which keeps its own argument — a single-storey `g` with a short descender, so a U+0323 under the bowl stays legible where a tighter face crowds it, which is the one thing Brill is worse at and worth knowing when a dot is the question. Nothing is fetched: the families are locally installed, and a remote webfont can substitute a face missing a glyph, which is the same failure as a box in a terminal — the text looks fine and is not what it says. `--font` is *prepended* to the fallbacks rather than replacing them, so an uninstalled name still renders.

**The three flags decide where a page starts; the page itself carries live steppers.** Size and box height move without a reload and persist per browser, because the right size for a face is something you find by looking at it beside a crop rather than by predicting it at a command line — and Brill runs small for its em, which is why a face change alone was not enough. `reset` returns to the values the server was started with, not to a constant, so it never quietly undoes a flag. `--box-lines` is a floor: the box still autogrows past it.

**`--issues` is the one mode that merges pages into one document, and it is a patch tool.** It takes a worklist — `PP-NNN:LINE issue text` per line, from a path or from stdin for `-`, `#` comments skipped — and serves every listed line on one page, each with its issue, its crop, and a read-only context line either side in reading order. It is the fourth way of naming a work-list and is refused alongside refs, `--all` or `--itinerary`. Three things hold it to the invariant it crosses. **It saves whole or not at all**: a payload short of the list is refused, so a half-filled form cannot leave some lines patched and the rest silently as they were. **Every listed line needs a ruling** — a note, not a text edit; the reading arrives pre-filled and most flagged lines will not need it changed, so what a flag actually owes is a verdict, and *that's fine* is a finding rather than a non-answer (two quick buttons fill the commonest two, and the text stays editable afterwards). **Each field carries the prior text the server sent it**, and a save whose prior no longer matches the store is refused naming both — which is what catches the incident the one-page-at-a-time rule exists for, a browser restoring textareas *by position* after a crash, where naming the ref in the payload does not, since a positional refill lands in fields whose server-rendered labels never moved. It **patches only**: a ref with no `decision.json` is refused at the command line rather than at the save, because merging a few edited lines over a proposal would write every *unlisted* line as though a human had read it. The write still goes through the ordinary decision path with the ref's whole line set, so `restore`'s "refuses on any missing line" stays true and `edited` is still computed against the proposal.

The header links to the **full page scan**, new tab — the crops say what a line sets and cannot say what is around it, which is what settling a speck or a dropped line needs. Served from `/scan/<ref>`, scoped to the session's refs like `/p/`; `--html` writes a relative path to `scans/` instead, since a browser will not follow `file://` from an http origin.
```
--html    write review.html per ref instead of serving  } mutually exclusive
--issues PATH  serve one document of flagged lines      }
               (`PP-NNN:LINE issue`, `-` for stdin) instead of a page at a time;
               patches only, each line needs a ruling, saves whole or not at all
--all     every page with a proposal and no decision
--port N  this editor's door onto the shared server [8731]
--font NAME     entry-box family, prepended to the fallbacks [Brill]
--font-size PX  entry text size [24]
--box-lines N   lines a box holds before it grows — a floor, not a cap [1]
--store {gt,mz}  which store to read [mz — the bare diff needs an independent
                 witness, and the view is not one once the page has ground truth]
--root --json --toon --pager
```

### ocr restore [REF ...]
**Does** writes adjudicated decisions into `gt/ocr/`, keeping the source geometry. Reports `mode=restoration` or `mode=revision`.
**Reads** `review/PP-NNN/decision.json`, the `--store` store, or the view, `gt/lines/`.
**Writes** `gt/ocr/` under `--commit`, **and relinks that page in `ocr/`** — the promotion is the write plus the relink, the same pairing `ocr predict` has for what it writes into `mz/ocr/`. The `view` field reports which store the view now names, `""` on a preview. Also `gt/lines/` for a page carrying corrections, which `corrections` counts.
**Note** **each line's text goes to the store that line came from.** A page's lines are the ALTO's plus `gt/lines/`'s, so this — still the only writer of ground-truth *text* — has two files to write: the ALTO's own lines by position, a correction by its `corr_` id, since the fragment is ordered by geometry and a box may have been nudged since. `gt/ocr/` never gains the corrected line; a second copy would be two records of one line, free to disagree. A correction with no decision is a partial restore exactly as an unadjudicated ALTO line is.
**Exit** 0 when it runs — `geometry_drift` and `text_mismatch` are reported, not gated. It **refuses** (exit 2) in four cases, none of them a judgement to weigh: no decisions at all; **any line without one**; a line without exactly one `String`; an unlicensed mark in the adjudicated text (§2.6).

**A revision is a whole-page act, and the second refusal is why.** `decision.json` must cover every line, so there is no path that edits one word of a finished page: revising `gt/ocr/` means a `proposal.json` for the whole page, adjudicated, then `restore --force`. That is deliberate — a partial write is ground truth with invisible holes — but it means a page carrying ground truth and **no proposal** cannot enter the loop at all. `2-030` was in that state, adjudicated by the eScriptorium route before this pass existed, until it was read through in 2026-08; every page in `gt/ocr/` has a proposal now. The constraint stands whether or not anything is currently caught by it.
**Note** the view is the right default here rather than a convenience: it resolves to `gt/ocr/` for a keyed page (source is the target — a `revision`, which needs `--force`) and to `mz/ocr/` for a predicted one (source ≠ target, target absent — a `restoration`, which does not). That is the correct source in both cases without the caller choosing, and `mode` reports which ran.

**`--all` is every page holding a `decision.json`, and it asks a sharper question than `--force` does.** Every page in `gt/ocr/` holds text, so the bare guard would refuse the whole store and a sweep that refuses everything is not a sweep. So it skips a page whose ground truth is **already newer than its decision** — that page has been restored since it was adjudicated and there is nothing to write — and restores the rest, carrying `force` on the adjudicator's behalf: the timestamps establish the same intent the flag does. `--force` under `--all` means the other half, *ignore the mtime test*, which is the same "do it anyway" the flag always meant. A skipped page is named in a `skipped` table, never silently. Deliberately not keyed on the *proposal*'s mtime: a proposal is a reading, not an adjudication, and re-authoring one licenses no write.

With more than one ref and `--commit`, **every page is checked before any page is written** — a dry pass runs the whole refusal set first, so an unadjudicated line on the fourth page cannot arrive with three pages of ground truth already replaced.

Two tables describe what the human did, and they are separate because a note is not an edit. `edits[]{line,proposal,decision}` is the text that changed; `notes[]{line,note}` is every line the adjudicator remarked on, **edited or not** — the commonest note sits on a line whose text nobody touched (`2-036`'s speck, ruled "ink smudge" and left empty), so a list keyed on `edited` showed it nowhere and the ruling appeared in no report about the page. Neither table gates, and the note never reaches the ALTO: `decision.json` is its record.
```
--store {gt,mz}  which store supplies the line geometry [omit: the ocr/ view,
                 which is gt for a keyed page and mz for a predicted one]
--all       every page holding a decision.json, skipping those whose ground
            truth is already newer than it
--force     overwrite a target that already holds text; every page does, so a revision needs it [off].
            Under --all it carries the same intent one step further: ignore the mtime skip too
--commit    actually write gt/ocr/ [off — previews the report]
--root --json --toon --pager
```

### ocr predict [REF ...]
**Does** zones to text in one pass — baseline segmentation, then recognition, structured by the zones the `zones/` view supplies. `blla`'s own regions are discarded and the seven declared zone types replace them, so a line arrives knowing whether it sits in a running title, a paragraph, a footnote or a signature line. `--all` sweeps every page with zones and is resumable.
**Reads** `scans/w-figs-blotted/`, `zones/`, the two models, the split marks. A page with no blot is refused.
**Writes** `mz/ocr/` (derived), and relinks that page in `ocr/`. **Never `gt/ocr/`.** One `<String CONTENT>` per `TextLine`, the shape `gt/ocr/` has — the two stores sit under one view and a consumer reads either without asking which.
**Exit** always 0 — a skipped page is reported, not a failure.
**Note** the input is the blotted raster, as `zones predict`'s is, so artwork raises no baselines. Nothing is lost to it: the blot fills the *declared* figure box and not a pixel more — the pad was rejected precisely because body text sits hard against an inset figure on pages like `1-283` — so the type survives and only the pictures go. Captions go too and should: they live in `data/readings.md`. That is what lets `tei context` drop the running head and the signature line from the collation draft while the store keeps every line the page sets — including the folio, which shares the running-title zone.
**Note** stock CATMuS reads ~91% of the ASCII and **0% of the transcription inventory**. This store is a witness to line geometry and to English, and to nothing else.
**Note** **a worker never writes to the terminal, and the summary says if it tried.** A `spawn`ed child inherits the parent's fd 2, and rich redirects `stderr` only for Python-level writes *in the parent* — so anything a worker emits lands between two frames of the progress bar, leaving rich's cursor accounting wrong and the count apparently frozen while `mz/ocr/` fills normally. It presented as two faults and was one. Each worker's fd 2 is now `dup2`'d to a file of its own before the models load (`dup2`, not `sys.stderr =`, because scipy, shapely and torch all have C in them), and the pool reads those files when it closes: `stderr_lines` and `stderr_log` in the summary, both empty on a quiet run, and the directory removed when nothing landed in it. Nothing is silenced — an empty capture is what makes a non-empty one worth reading.
**Note** **the recognizer runs under kraken's new polygon extractor, and every page in this store was produced that way.** `models/blla.mlmodel` predates it, so kraken warns "Enforcing use of the new polygon extractor for models trained with old version. Accuracy may be affected." once per worker process. Stated here because it is a property of the pinned model rather than of any page, and filtered in the workers by message — never by category — so the capture stays empty in the ordinary case while the next unseen warning still reaches it. `--jobs 1` raises it in-process, where rich catches it and prints it above the bar.

**Exit** always 0 — measurement. An outlier is a page to re-read, never a page to correct by ratio. Refuses (exit 2) only when a named ref has no source file.
**Note** takes several refs, like `ocr review`, and "batch" means only that — the refs you pass. Most pages of this book carry a handful of Tier-1 terms, so a coordinator hands it every ref of a pass at once and gets a sample worth holding against the corpus. `dispatch.md` used to prescribe eyeballing `lexicon marks` here; this is that comparison computed, and `lexicon marks` could not do it — corpus-wide only, and grouped by base letter, so it cannot express `ɪ`/`i`, which is not a mark on a base.

**Note** **`traps[]{ref,line,token,candidate,seen,refs}` is the fourth arm and the only one that does not select Tier-1 tokens first.** The other three judge a population; this asks who left it. A form keyed with a glyph *outside* the inventory carries no inventory member, so it is never selected, so the page reports `tokens: 0, types: 0` and every other arm goes quiet on a wholly wrong reading — indistinguishable from honest English prose. So this one walks every token, folds `detectors.TIER1_TRAPS` (`’ ‘ ' ´ ʼ ʻ` → U+02CA, `·` → U+02D9, `ı` → U+026A, `– ‐` → U+002D), and reports where the folded form is one the store already holds. It needs no knowledge of the notation, only of what has been ratified. **Not leave-one-out**, unlike every other arm here: it asks whether the corpus knows the word, so a sibling page in the same batch is a good witness — `3-199`'s `Ke’rek` is answerable by `3-178` keying it correctly an hour earlier. Matching is casefolded on both sides, a name being sentence-initial on one page and medial on another. A folded form the store has never seen is **not** reported: this is a lookup, not a reading, and inventing a candidate nobody witnessed is the failure the whole module exists against.
**The other three arms are not equally strong.** `rare[]{ref,form,count,lines,position,corpus_pct,corpus_n,spec}` lists every occurrence of a form whose confusable the corpus almost never sets — bare `g` at 6.1% of Tier-1 `g`, 8 occurrences on 4 pages. Deterministic, no statistics. **One row per (ref, form) carrying a count**, because a keyer repeats a slip along a page (13 dropped dots on `2-040`, 14 on `3-004`, then a tail of 1–3): four bare `g` on a page is one finding of weight four, not four independent hits. Which contrasts can reach this arm is **derived from the prior at run time**, not declared — plain `i` at ~34% of its axis never qualifies and does not need to.

`conflict[]{fold,form,source,ref,lines,count,in_batch}` finds one word spelled two ways. Fold collapses every contrast axis then casefolds; a bucket whose **casefolded** spellings differ is a hit. That suppresses `äˊmmê`/`Äˊmmê` while catching `Iᵋplɪˊlɪ`/`ɪᵋplɪˊlɪ`, because `casefold("I")` is `"i"` but `casefold("ɪ")` is `"ɪ"` — U+026A has no case mapping. Scoped to folds the batch touches: the store carries standing `i`/`ɪ` inconsistencies of its own and re-reporting them every run would bury the batch's news. `in_batch` separates the batch disagreeing with itself from the batch disagreeing with ground truth.

**One row per (fold, form, page), carrying `lines`** — so two rows sharing a fold *are* the conflict, and each says where to go. The row used to be one per fold with the spellings packed into `batch_forms`/`store_forms` and no line numbers at all, which told an adjudicator a word was keyed two ways and left them to grep for it. `source` is `batch` or `store`; a `store` row has no `lines`, because the prior is `(ref, token)` off the ALTO and carries no line — look it up with `harness ocr lines`, and none is invented. `proposal check` still raises **one issue per fold**, since a word keyed two ways is one fault however many places it surfaces.

**No exemption applies here.** A conflict in a proposal is a *reader's* disagreement and `proposal.json` is the record of what they wrote — never rewritten after adjudication, because `edited` is computed against it. Silencing one would delete the measurement. `data/marks_exempt.json` rules on ground truth and is read only by `lexicon conflicts`.

`ratio[]{scope,contrast,position,types,expected_pct,prior_pct,gt_min_pct,gt_max_pct,band_n,outside}` points and never decides. **Types, not tokens** — the marks are lexical, not independent, and a per-character binomial flags 19 page-base cells over 29 already-adjudicated pages (`2-036`'s 10% `ɪ`-share is `Pehiˊttin` ×4). `outside` is a rank against the band, never a p-value.

**`scope: ALL` is the refs you passed, pooled — nothing more**, and it is emitted only when you passed more than one. Most pages of this book carry a handful of Tier-1 terms, so one page is rarely a sample worth a verdict; pooling a coordinator's returned jobs gives a body of native text large enough to hold against the ground-truth corpus. Over a single ref it would restate that ref's own row, so it is absent, and that ref's rows are shown however thin they are — a table that is silently empty says nothing and looks clean.

**Read the per-ref rows against `ALL`, and `ALL` against `prior_pct`.** They answer different questions. One job adrift while the others sit on the prior is that reader, on that page. *Every* job leaning the same way, so that `ALL` itself parts from the prior, is **systemic** — the prompt or the keying spec, not anyone's reading. That second finding is the one nothing else in the loop can see, and it is why the pooled row exists.

The band is the **per-page** spread over ground-truth pages clearing `--min-types`, and it is a fixed property of the store: it does not move with how many refs you passed. It is the right reference for a per-ref row and a conservative one for `ALL`, since a pooled share is a weighted mean of its members and varies less than any of them — `ALL` outside it is a strong signal, not a marginal one. `band_n` says how many pages it came from, which is not always many: the `g` axis clears `min_types` on 6 pages of the store. A band of fewer than two is no band, and `outside` reads `?` — as it does under `--min-types`, and never blank, since an uncomputed verdict must not draw in the same column as a computed one.

`prior_pct` is the whole prior pooled, by the same type-level rule as `expected_pct` so the two columns are in one unit. `rare`'s `corpus_pct` is deliberately *occurrence*-level: "how often does the corpus set a bare `g`" is a different question, and 6.1% is the figure `keying_spec.md` §5.1 publishes.

**`position` is why the small caps are split into two contrasts each.** Word-medially an ASCII cap is essentially never right — 2 in the store against 509 medial small caps — and `detectors.MEDIAL_CAPS` already says so with a sharper claim than a share could. Word-initially both are ordinary: 63 ASCII caps (`Alaˊyon`, `Ilhiˊnin`) against 55 small caps (`ɪnp-luˊwleñ-yiˊᵋlhɪn`, `ᴇnmɪtaˊhɪn`), and frequency is the only handle. So `smallcap-i` (lowercase) counts everywhere and `smallcap-I` (uppercase) counts word-initial only.

**A hyphen inside a Tier-1 token does not make the next element word-initial**, and reading it that way is how `Hɪtoˊ-Lap` passed twice: the element-initial position sent it to `smallcap-l`, whose prior is 7 ASCII `L` against 0 `ʟ` and so endorsed the capital. `detectors.medial_cap_positions` is the one definition of the rule, gated on the token carrying an inventory glyph so that English compounds (`Baffin-Land`, `Chukchee-Eskimo`) stay word-initial as they should.

**The prior is leave-one-out, and it stopped being density-selected**; `prior_note` says the second half in every report. Leave-one-out unconditionally: after `restore` a page's ground truth *is* the adjudicated descendant of its own proposal, so a prior containing the page under test compares a proposal against its own output — the two-witnesses-that-are-one failure in a fourth place. On density, this line used to say `gt/ocr/`'s pages were chosen for Tier-1 density (median 13 types, range 2–56) and that the prior was therefore about dense pages rather than a population estimate. That was true of 29 pages; the store now holds **476 with a median of 3 types**, and the maximum has not moved (range 1–56) because the densest pages were already in. It leans dense at the top and is otherwise the ordinary body of the book, so the caveat is now much weaker than it was — and the `ratio` arm is silent on the majority of pages rather than a quarter of them, which is why a batch and not a page is the pooling unit.

**A page whose reading degraded to ASCII contributes no tokens and every arm goes silent on it**, which is why `pages[]{ref,source,tokens,types}` carries one row per ref whether or not anything was found. `types: 0` beside a page whose zones promise Tier-1 content is itself the finding.
**`--all` says less than a batch does**, which is the one place in this CLI where the corpus form is the *weaker* reading. The prior is leave-one-out over `gt/ocr/`, so pooling every proposal in the repo drives the sample towards its own prior and the `ratio` arm goes quiet. It is there for the `rare` and `conflict` arms, which are deterministic and gain from breadth.
```
--all            every review/ page with a proposal
--decisions      read decision.json instead of proposal.json — the last state
                 before restore writes [off]
--min-types N    types a scope needs before ratio judges it [data/marks_config.json]
--rare-max PCT   a confusable at or below this share of its axis is rare enough
                 to list every occurrence [data/marks_config.json]
--root --json --toon --pager
```

### proposal check [REF ...]
**Does** cross-checks `resolved` against the codepoints `text` actually contains; flags a straight apostrophe, a dot-prone bare suffix, a note whose `class` is outside the closed set (doubt/semantic/print/draft/layout/artifact) or absent, a line ending in sentence punctuation the draft does not end in, a note naming a lexicon key the line then types by hand, and — via `marks` — a rare form or a word spelled two ways against the store.
**Reads** `review/PP-NNN/proposal.json`, plus `gt/ocr/` and `data/marks_config.json` for the two corpus arms, the lexicon index where a note could name a key, and the `ocr/` view for the line indices.
**Note** **the named-key arm tests the expansion against the line, not whether a key was mentioned.** It fires only where the proposal itself wrote the key — a brace in a `note`, where braces do nothing, or a bare key beside the word — *and* `text` already holds exactly what that key expands to. So a reader that read its page against the corpus and kept what it saw is silent by construction: `3-085`'s `Eiñeˊwg̣i` against a ratified `Eiñewg̣i`, `3-092`'s capital `Tatk-Omruˊwg̣ê`, `3-103`'s `Mɪˊs˙qän` against `Mɪˊs˙qᴀn` all expand to something the line does not contain. The general form of this arm — every hand-typed form a lookup could have supplied — is deliberately absent: it would fire on ordinary reading on nearly every Tier-1 line, and its only reading would be "use a handle here", which is pressure off the raster. Measured over chapter XX's twenty-seven pages, the narrow arm found eight, on five pages. Advisory, because a handle is a saving and not a reading.
**Note** **a line index the store does not have is a defect.** A proposal is keyed by the ALTO's indices and `restore` joins on them, so a key naming no `TextLine` is text with no box to land in — `restore` drops it, silently, and the reading is lost with nothing saying a reading was lost. It belongs in the reader's report and nowhere on disk: the line store is the upstream source of truth, a proposal is downstream of it, and nothing downstream may propose a line into existence. A human gives the band a box in `ocr edit`, and the index exists from then on. A top-level `segmenter_missed` block — the retired field that used to carry this inside the proposal — is itself a defect; an empty one `proposal fix` strips silently, a non-empty one a human must disposition. Resolved through the view **and the `gt/lines/` overlay**, so a page reads against `mz/ocr/` before a restore and `gt/ocr/` after, plus every correction already drawn — a keyed correction is therefore not an orphan, which is the whole point of giving the line a box. A page with no ALTO at all is skipped rather than condemned — absent is not wrong, and every line would fire on a clone whose view was never built. This cannot see the neighbouring fault, a stray reading appended to a *real* line's text (`1-037`'s folio); that one is the reader contract's.
**Writes** —
**Exit** 1 on a **defect**, on any ref — one dirty page fails the batch, which is the contract a gate must have or a batch would launder a failure. Never on an advisory alone, unless `--strict`.
**Note** **the exit code is also printed, as a closing `verdict` section** — `exit` and a `means` line naming why it is what it is. A groundtruth-reader is refused shell operators, so `$?` is a fact about its own work it cannot obtain, and it was spending turns on `proposal check REF; echo "EXIT: $?"` to get it — four such reaches across three readers in the `1-064`–`1-069` batch, a turn apiece against a budget of eighty. Relaxing the operator rule to admit one idiom would buy back one fact and give up the property that makes the surface auditable; printing the fact costs a row. And `means` carries what `$?` cannot: **the two exit-0 cases are not the same result** — nothing found, versus advisories found and deliberately not gated on — and only the second leaves the reader work to do, in the line's `note`. `corpus normalize` closes the same way, for the same reason and the same readers.
**Note** the corpus arms are `proposal marks`'s two **deterministic** ones, run over the single page so a reader catches its own slip before writing its report. `ratio` is deliberately not among them: one page is a poor sample and it is the arm that cannot decide, so folding it into a per-page gate would assert exactly what `marks` refuses to. A repeated form is one issue naming its other lines, not one issue per occurrence — a keyer's single habit is one fault. The prior is leave-one-out here too, so a revision is not checked against its own descendant. Where `data/marks_config.json` is absent (a fresh clone), the arms are skipped and the rest still runs.

**Overlap with the suffix check is wanted, not deduplicated**: a bare `-gɪn` yields both a `bare suffix` and a `rare form` issue on the same line. They reach one defect from different directions — a measured shape and a corpus share — and a second witness this cheap is what the governing principle asks for.

**Two severities, and only one of them gates.** A **defect** claims something *is* wrong and is the reader's to fix: `resolved` naming codepoints the text lacks, notation with no `resolved` at all, a straight apostrophe, an unpaired footnote marker, a note class outside the closed set or asserting nothing, an added line-final comma. **That last one gates only while the line says nothing about it** and drops to an advisory once the line carries a `note`: eleven instances across 93 proposals were on no page and in no draft, but a comma the recognizer genuinely dropped is a real correction, so the reader discharges it by looking and then either deleting the mark or saying what it saw. An **advisory** is measurement — a corpus share saying "go look": a rare form, a dot-prone bare suffix, a word spelled two ways. **A note with no class is the one advisory that is not measurement**, and it is an advisory anyway: the class only picks the badge, while the part that fixes the failure it exists for — a noted line is never dimmed in review, the way a Tier-1 line never was — happens without it. Gating there would make an observation the reader cannot confidently classify cost the note itself, and the reader who resolves that by writing nothing has been made worse by the check. The rule is that **a gate must be satisfiable by the actor it gates**, and an advisory is not: a rare-but-correct form cannot be made common, and the second witness in a spelling conflict is another page, which the firewall forbids a reader to open. It gated anyway until the severity split, and eight of eighteen failing proposals failed on advisories alone — so `check` exiting 1 stopped distinguishing a mistyped mark from a rare surname, and the reading brief had been rewritten to teach readers that exit 1 is sometimes fine. An advisory still prints, at the same volume, in the same table; it just stops claiming to be a gate. `--strict` gates on both, for a sweep meant to chase every prompt.

**Every issue is one record shape — `line, issue, severity, token, context, detail` — whatever detector raised it** (`proposal_check.ISSUE_FIELDS`, and the `issue()` constructor is the only way one is built). `line` is `-` for a page-level finding; `token` is the flagged string where there is one; `context` is where it sits on the line; `detail` carries anything else as text, including the codepoint sets both `resolved` arms report and the footnote arm's `explained:` note. The six detectors each used to name their own fields, which made the list ragged, and a ragged list of records is not a table — TOON silently degrades it to the nested form, so a corpus sweep printed 265 findings as 51 KB of indented blocks and pooling two refs tripped the emitter's list guard. **No field holds a list.**
```
--all        every review/ page with a proposal
--path FILE  proposal file, one ref only [review/PP-NNN/proposal.json]
--strict     gate on advisories too — for a sweep meant to chase every prompt,
             not for a page pass, where a rare form that is simply rare would
             make the gate unpassable [off]
--root --json --toon --pager
```

### proposal fix [REF ...]
**Does** expands every `{key}` handle in a `text` field to the ratified form, recording the line as typed in `as_typed`; then applies the one unambiguous correction — a single mark `resolved` names that `text` lacks, swapped for the single mark `text` has that `resolved` lacks.
**Reads** the proposal, and `gt/ocr/` + `data/marks_config.json` when a line carries a handle.
**Writes** the proposal, in place.
**Exit** always 0; raises on a handle that does not resolve, and writes nothing.
**Note** nothing to clobber under `--all`: it repairs only what is already wrong, so a page with nothing to fix is untouched.
**Note** **the expansion is here because this is the path a reader takes.** It lived only in `proposal set` for as long as the handle existed, and over one measured day of 63 readers it fired zero times — they author `proposal.json` with `Write` (63 whole-file writes against 16 `proposal set` calls, all of those later edits), so a handle typed per the contract would have reached the store as a literal brace. Four readers looked a form up, were handed its key, and retyped the glyphs by hand — the act the handle replaces, and the one that produced three `ᴇ` U+1D07 → `ᴀ` U+1D00 slips on a single name across three pages that day. `fix` runs on every page and already writes, so this costs no new step.
**Note** expansion runs **before** the mark swap: the swap reconciles `text` against `resolved`, and a line still holding a brace would be reconciling a handle against a codepoint list.
**Note** **nothing half-expands**, same rule as `proposal set` and `ocr restore` — one unresolvable handle refuses the whole page, because `fix` writes and a half-expanded page reaches the adjudicator looking finished.
```
--all        every review/ page with a proposal
--path FILE  proposal file, one ref only [review/PP-NNN/proposal.json]
--root --json --toon --pager
```

### proposal codepoints [REF ...] [LINE]
**Does** names every non-ASCII character in a line's field, or in every line of the page.
**Reads** the proposal.
**Writes** —
**Exit** always 0.
**Note** **`LINE` is a trailing bare number, and the plural refs stay.** This was a `--line` flag on the argument that a variadic positional cannot tell an index from another ref — which is not true here: a ref is `PP-NNN`, a bare number is refused as one corpus-wide with its own message, and the two token shapes are therefore disjoint. The flag cost more than it bought, because `set` and `replace` take their `LINE` positionally and a reader reaches for all three in the same breath; one of them did, guessed the positional, and lost two turns to a usage error. Omitting `LINE` names every line, which is the more useful default besides — asking what a proposal actually contains rather than confirming one line at a time.

```
--root --json --toon --pager
```

### proposal set REF [LINE]
**Does** sets one line's field, or many lines' in one write when `LINE` is omitted. NFD-normalized on write, and `{key}` handles in a `text` value are expanded to the ratified forms `lexicon lookup` names.
**Reads** the proposal, `gt/ocr/` when a value carries a handle, and stdin when `--value`/`--values` is absent.
**Writes** the proposal, in place.
**Exit** 0; 2 if a handle does not resolve.
**Note** **a handle is expanded here, on write, and that is the whole reason the field exists.** `text` gets the ratified glyphs and `as_typed` keeps the line as the reader wrote it, so the proposal and the decision go on comparing like with like. Expanding when the review server *serves* the line would do the same job for the adjudicator's eye and wreck the measurement behind it: every handled line would differ from what it is measured against, `save_decisions` would record a human edit nobody made, and `ocr corrections` would grow classes the tooling manufactured — `'` → `ˊ` and `^` → U+030C among them, which is not merely noise but noise shaped like the corpus's real error classes.
**Note** **nothing half-expands, and a bulk write dry-runs every line before writing any.** One unresolvable handle refuses the whole call: a partly-expanded line records neither what was read nor what was meant, and a partly-authored page cannot be told from a finished one. Same rule as `tei expand` one stage later and as `ocr restore` across refs.
**Note** `as_typed` is **cleared** when a handled line is later keyed by hand, because a provenance record that outlives its provenance is worse than none — the review UI would badge a hand-read line as a corpus match for good. Only `text` is expanded; a note may mention a handle without meaning it.
**Note** **the bulk form is a budget fix, not a convenience.** A reader issues a command and reads its result as two separate turns, so a single-line write costs two of `maxTurns: 80`. `1-101` — a two-column numbered list of native names, nearly every line wanting Tier-1 keying — spent 23 `set`, 3 `replace` and 14 `Edit` calls over 21 distinct lines, hit the cap exactly, and was cut off mid-correction. One line was touched twice, so it was not thrash: forty corrections arriving one per turn on a page needing forty corrections. The class of page this fails on is the vocabulary list, which is the densest Tier-1 material in the book. It reports `changed` and `unchanged` per line, because re-sending a whole page most of which was already right is the ordinary use and a bulk write that says only "ok" cannot be checked.
**Note** **`--values` exists beside stdin because the reader cannot reach stdin.** Its guard refuses any unquoted operator, so `<` and `|` are both unavailable inside a reading pass. Same pairing as `--value` and stdin on the singular form, at a different scale.
```
--field {text,resolved,note,class}  which field [text]. `class` takes the
                              closed note vocabulary — doubt, semantic, print,
                              draft, layout, artifact — and a value outside it
                              is exit 2 at the write
--value TEXT                  the replacement; omit to read stdin [stdin]
--values TEXT                 a {"line": "text"} object, used instead of LINE [stdin]
--path FILE                   proposal file [review/PP-NNN/proposal.json]
--root --json --toon --pager
```

## zones

Three stores — `gt/zones/` (human, tracked), `mz/zones/` (machine, derived),
`zones/` (the view, gt winning) — and the segmenter trained on the first.
`save_zones` takes no store argument at all, so writes cannot name anywhere but
`gt/zones/`. The only route from `mz/` to `gt/` is a human in the editor.

The sidecars are `gt/`-only and take no store: the three split lists,
`_rule_exempt.json`, `_ink_exempt.json`, `_ink_cache.json`. They record
judgements about *pages*, and there is no such thing as the machine store's
opinion of which pages are held out.

### zones check [REF ...]
**Does** the gate. Named pages in full; `--all` sweeps every keyed page.
**Reads** the `--store` store, `data/zones_config.json`, the `gt/` sidecars, and `scans/` when ink runs.
**Writes** `gt/zones/_ink_cache.json` (derived) when it reads a raster.
**Exit** 1 if any named page has errors and `--store gt`; **always 0 under `--store mz`**, which is measurement.
**Note** **named pages always ink-check, however many.** `--ink` is a sweep economy — ~0.20 s a page against ~1 ms for the file-level checks — and naming two pages must not quietly buy a weaker check than naming one, since this is the only check that can see a *missing* zone. Pooled, `errors`/`warnings`/`uncovered` become counts in the row and each gets its own ref-keyed table; one ref prints the report exactly as it always did.
**Note** **`exempt-holds-zones` is the error behind `exempt => no zones`.** A ruled leaf has no text column, so ruling one clears its `gt/zones/` ALTO and any `mz/zones/` prediction, and the kind in the split lists is the whole record that a human looked. A page still carrying a file predates that rule or arrived by hand; re-saving the ruling in the editor clears it. The `mz/` arm is the one with teeth — a segmenter asked about a leaf finds a column anyway, and 32 predictions that outlived a ruling held 98 zones against 1 in ground truth, several of them paragraphs on blank paper.
**Note** **`--all` sweeps `settled_refs`, not the store census.** A ruled leaf holds no file and is still a page somebody has been through, so a sweep built on the files alone would drop all 115 of them and report less work as more done. `keyed` on the row means settled, which a ruling answers as fully as keying does.
```
--store {gt,mz}  which store [gt]
--all            every page a human has settled: keyed zones or a ruled leaf
--itinerary LST  scope the sweep to a work-list [whole store]
--ink            SWEEP ONLY: read every raster for ink no zone accounts for [off; always on for named pages]
--lines          SINGLE PAGE ONLY: every zone's lines of type [off; costs a second raster decode]
--jobs N         worker threads; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```

**Writes** `gt/zones/` on save — no `--commit`, the save click is the human act.

### zones predict [REF ...]
**Does** runs the trained segmenter into `mz/zones/`. Input is always the blotted raster, since that is what the model was trained on.
**Reads** `models/bogoras-seg/`, `scans/w-figs-blotted/`, the split marks.
**Writes** `mz/zones/` (derived) — never `gt/`.
**Exit** 1 if any swept page lacked a blot. A single ref exits 0.
**Note** an exempt mark does not stop a named ref — naming a page is the request — but an existing prediction does, unless `--force`: the mz file's sha256 is the store's only witness to which model wrote it. **Several named refs go through the sweep** so the model loads once, carrying that override with them; without it a named plate would be dropped in silence by the command that named it. Under `--all` the exempt ruling holds, which is what it is for.
**Note** **`--decode` defaults to `dp`, and used to default to `raw`.** On identical weights the three decodes score 61.3%, 80.1% and 90.8% precision, so leaving the argument off was worth more than any retrain has been — in the wrong direction. It cost a corpus sweep: a re-prediction taken with the old default replaced a dp-decoded store with a raw-decoded one, and the ~20% fall in zone count that followed was read as a property of the rasters it had just been run against. Each arm now names its decoder in the file's `processingStepDescription`, so a store can be asked rather than assumed.
```

--force          re-run over pages that already have a prediction [off]
--itinerary LST  predict over a work-list [every page with a blot, minus the ruled leaves]
--model PATH     the segmentation model [models/bogoras-seg/zones-seg.safetensors]
--decode {raw,dp} the segmental DP over the page plus the paragraph split, or blob vectorisation [dp]
--device DEV     torch device [auto]
--root --json --toon --pager
```

## lexicon

Two halves. **The store** — `new`, `check`, `show`, `ratify` — is `lexicon/`,
one entry per Tier-1 form an editor has written a note about; it takes the
`--commit` discipline and `check` exits 1 on a defect. **The reports** are
frequency arms over the native corpus in restored `gt/ocr/`, plus `glosses`,
which reads committed TEI instead; those are report-only and exit 0.

An entry is deliberately thin. The identity is the **exact surface form**, NFD,
carrying no language — a form only becomes `ckt` when a collator judges it, and
most of the corpus is unjudged, so an id holding a language would leave those
forms unaddressable in a store whose premise is that Americanist notation is
phonetic and a form is readable before anyone knows its language. Everything a
card shows except the note is derived on every load: the pronunciation by rule
from the notation, the attesting pages and printed lines from `gt/ocr/`, the
language and the printed gloss from committed TEI. A copy of any of it here
would go stale in the direction that hides it — the entry would still read as an
entry.

### lexicon new FORM
**Does** scaffolds an entry at `status: proposed`. The file name is a slug you choose; the default is `handle_key` reduced to `[a-z0-9-]`.
**Reads** `lexicon/`. **Writes** `lexicon/<slug>.md`, with `--commit`.
**Exit** 0, or 1 if the file exists.
**Note** the slug is **not** the key. Over the corpus's 609 attested forms `handle_key` yields 23 pairs differing only in case (`Aiˊwan`/`aiˊwan` → `ai'wan`), which a case-insensitive filesystem collapses, and 34 keys containing `:`. It is also non-injective by design, so a check of the form "the heading re-keys to the filename" would pass on *both* of a colliding pair while only one file can exist. A human names the file; `check` refuses two names a filesystem might not tell apart.
**Note** `--see` is a pointer and never a claim that two forms are one word. The book sets `Čeˊwɪn` and `Čeˊwin`, and `data/marks_exempt.json` rules that ambiguity real; nothing in this store overrides that ruling.

### lexicon misses
**Does** frequency-ranked `lexicon_miss` tokens, for bulk approval — a proper noun into `entities/`, anything else into `data/lexicon_extra.txt`. Two lists: `tokens` is what neither source accounts for, `suppressed` what the entity store already does.
**Reads** `gt/ocr/`, `data/lexicon_extra.txt`, `entities/`. **Named, not the view**: every recognizer error in `mz/ocr/` is a token no dictionary carries, i.e. a `lexicon_miss`, and this list feeds committed human-edited stores that suppress the detector meant to catch them.
**Writes** — **Exit** 0.
**Note** `suppressed` exists because the entity store is the *second* source and could otherwise absorb a name silently. Detection runs against the dictionary and `lexicon_extra.txt` alone; each hit is then re-tested against the store's canonicals and alias forms, so what the move to `entities/` took off this list is on it, named. A Tier-1 form in either source is inert regardless — `lexicon_miss` tests only ASCII components of length > 3.
**Note** **`--common N` asks the other question**, and exists because the dictionary is a floor in the sense CLAUDE.md means: it accounts for every proper noun English happens to spell the same way as a word — `Wolf`, `Frost`, `Bering`, a man called `Ten` — which is precisely the class of entity candidate the default arm cannot see. So the flag drops the dictionary and `lexicon_extra.txt` and reports every token the corpus prints, less the N commonest word forms and less what `entities/` accounts for. The result is a **worklist and not a finding**: most of it is ordinary English, and the reader is scanning for the proper nouns. Measured on today's 275 restored pages at N=1000: 8,237 distinct forms, 1,030 cut, 7,462 reported, 205 suppressed and 17 held back as sentence heads. `scope` carries `forms` and `spellings` both, because either alone reads as the other — the cut ranks folded forms and the rows are spellings, so more spellings than forms can survive it without anything being wrong.
**Note** the flag changes **which lexicon counts as accounting for a word**, and one thing about what counts as a word. The shape floor is the same call with an empty lexicon — still alphabetic, still longer than three characters, still split on the internal hyphen and apostrophe — but it runs `admit_foreign=True`, which is the one axis the two arms differ on. Which is also why the stoplist is ranked over *reportable* tokens only: `the`, `of` and `and` never reach this report, and ranking over raw tokens would spend most of N on words that were already invisible.
**Note** **`admit_foreign` exists because the shared floor was hiding names, and it hid taxa first.** As a detector `lexicon_miss` is ASCII-only for a good reason — a non-ASCII token is the *inventory* branch's business and this branch's silence is deliberate — but as a worklist floor that same test silently said "this is not a word" of `Œstrus`. A Latin binomial is where this book keeps its ligatures, so what it cost was `Salmonidæ`, `Coregonidæ`, `Œstrus`, `Œdemagena` and `chamæmorus`, none of which had ever appeared in any report; `Coregonidæ` is printed once, at 1-188, and names a fish family the entity store did not hold. **The axis is not ASCII**: dropping `isascii` outright takes `forms` from 9,367 to 9,860, five hundred of them the corpus's own Tier-1 romanizations, which are not English word forms. What widens is *a word carrying no inventory mark* — measured on one corpus with one call, both settings, **+80 forms and +31 rows, no ASCII row moving**. Eight are the ligatures and 23 are Russian (`нерпа`, `ларга`, `лахтакъ` off 1-151, beside the `акипка` the store already holds as an alias), which is wanted: this list feeds two stores that hold Russian. `test_lexicon_tokens.py` holds the two floors apart in both directions, as `test_lookalike_scope.py` does for the lookalike tables.
**Note** **N is a request; the cut lands on a frequency boundary.** Splitting a tie by sort order would stoplist one word and keep its equally frequent neighbour on nothing but alphabet, so every form as frequent as the Nth is cut and `scope.cut` says how many that was — 1,027 for a requested 1,000, at a `floor` of 11 occurrences. Asking for more than the corpus has forms cuts all of them and reports nothing, which is the honest answer to the question as asked. The cut folds case (`The` and `the` are one word for a stoplist) where the rows do not (`Frost` and `frost` are two findings, one of which may be a person).
**Note** the stoplist is **the corpus's own frequency table and not an imported list**, and its tail is printed back as `boundary` — the twenty least frequent forms N swallowed, which is the part that says whether N was well chosen. The head is a count, because a thousand rows of `which`/`their`/`reindeer` at a terminal every run is noise; a stoplist nobody can see at all would be the defect this group already refuses in a whitelist.
**Note** **two things `--common` has to fold, because dropping the dictionary exposes them.** Both were invisible while the dictionary did the filtering, and each turned one name into two findings or into a hundred. **A possessive is not a form**: `EDGE_PUNCT` cannot reach the apostrophe in `Orion’s` — the token ends in `s`, so the strip stops before it — and a name the book mostly sets possessively ranked twice. It is folded, so the count and the `first_seen` are the name's own; an apostrophe *inside* a compound (`Raven’s-Beak`, `cat’s-cradle`) is untouched. **And a capital at a sentence head is the printer's**: `Nevertheless`, `Nowadays`, `Regarding`, `Meanwhile`, `Owing` were the largest single noise class in the report. Every row now carries `initial`, how many of its occurrences opened a sentence, and a row seen **more than once**, whose occurrences are **all** initial, and whose form the dictionary carries, moves to a third list, `sentence_heads` — 17 of them at N=1000, led by `Nevertheless` and `Nowadays` at six each.
**Note** **the drop takes all three conditions and never any alone**, because each on its own is wrong in the direction that loses a name silently. On position alone, a toponym that happens never to fall mid-sentence disappears. On the dictionary alone, so does `Wolf`, `Frost` and `Bering` — what this flag exists not to do — and the word list is not a test for ordinary English anyway: it carries `allen`, `ross`, `parry`, `peters`. **And without the repetition floor the other two are not evidence at all**: "every occurrence opens a sentence" is a coin that came up heads once, and the first cut without it held back `Birch`, `Goose`, `Ross`, `Peters`, `Rudolf`, `Walruses`, `Ptarmigans` and `Hildebrand`, each seen exactly once. The floor costs most of the filter's reach — 152 of 169 were singletons — and is still right, because what survives it is what *ranks*, and because `initial` is on every row: a reader who wants to skim the singletons can, on evidence the report shows them rather than on a rule applied behind their back. `sentence_heads` is a list beside the others rather than a silence — `suppressed`'s argument exactly. A line break is not a sentence break: the scan walks the joined draft, since asking "first token of its line" would call every line's opening word a head, which is most of the page.
**Note** **the possessive fold is `--common`'s alone and must stay there.** `detect_all`'s tokenizer is the obvious place for it and is the wrong one: U+0027 survives that strip deliberately because it is the spirant mark, so folding a trailing `'s` there would delete a Tier-1 character from every flag in the corpus. Only this branch is asking about English word forms.
**Note** `suppressed` catches more under `--common` than under the default arm, because `entity_forms` contributes each *component* of a multi-word name: `Bering Sea` accounts for a bare `sea`, and a person called `Wolf` would be suppressed by a `Wolf Creek`. That is the same rule both arms use rather than a second one invented here, and the list is printed for exactly this reason.
```
--common N       report every token instead of the dictionary misses, less the
                 N commonest word forms and less what entities/ accounts for.
                 Bare, N is 1000 [off]
--root --json --toon --pager
```

### lexicon lookup QUERY...
**Does** finds a ratified native form by a typeable key and shows the lines it was printed on, so a form's sense is readable without opening the page — `Kuluˊči` alone is a string, "south of Kuluˊči Bay" is a place. The key is what a reader writes in braces for `proposal set` to expand. Match is a substring of the key, the fold, the form, or the key's bare reduction, so `kulu` reaches it. A non-ASCII query is matched as its key too (`marks.handle_key`), so the form as the book prints it reaches it as well.
**Note** **a miss is a fact about the query before it is one about the corpus**, and two shapes produced silent wrong negatives. The printed form matched nothing, because the bare reduction drops a small cap whole (`Taˊn˙ñɪn` → `tannn`) while its key spells the letter `i_` and keeps the `i` — the corpus's commonest glyph, parting the two sides the reduction exists to align. And a hyphenated compound the corpus holds only as its elements returned nothing with every element ratified; the elements are now retried **after** the whole misses, and `split` names them, so a widened search says so rather than answering a question nobody asked. `3-125` hand-keyed `Taˊn˙ñɪn` against ten occurrences on six pages for the first reason, and generalized the one miss across four lines. The floor line still holds on top of both: a form carrying no inventory glyph is invisible here whatever the query.
**Reads** `gt/ocr/`, `data/marks_config.json`. **Writes** — **Exit** 0.
```
QUERY...       any substring; several are an OR, and one call is one index
               build — a page's whole unglossed vocabulary belongs in it
--min-pages N  withhold the key from a word attested on fewer pages than this.
               Counted per fold, so it can never hide a conflict [1] — a hapax
               still gets a key
--context N    lines of surrounding text per matched form [2]
--root --json --toon --pager
```
**Emits** `scope` (the queries, the floor, `forms_indexed`, the standing `floor` caveat, and how many forms could not be keyed), `matches` (one row per form: `key`, `form`, `count`, `pages`, `refs`, `ambiguous`, `why`), and `context`.
**Note** **the key is marked ASCII and deliberately not pretty** — `Kuluˊči` is `Kulu'c^i`, `Kavraˊlɪt` is `Kavra'li_t`. A plain-ASCII key would spell the second `kavralit` and teach an `i` that is not there, to a reader who will key it from memory on a later page: `fold` collapses exactly the axes this pass gets wrong most often, dropped U+0323 being the largest single correction class and `i`/`ɪ`/`I` the largest family. So every non-ASCII character leaves a visible marker and the key cannot be read back as a spelling. Case passes through — it is legible at any zoom, unlike the dot-below, and lowercasing collided on 11 of the 499 forms.
**Note** **a word the book spells more than one way yields no key at all**, and a ruling in `data/marks_exempt.json` does not restore it. That ruling says the ambiguity is *real* — the book setting one word two ways rather than a keyer slipping — which is the strongest possible reason to refuse to pick a side. `Čeˊwɪn` (1-042) and `Čeˊwin` (1-052) are the live instance, and 1-042's reader flagged the disagreement rather than harmonizing to the older page's ground truth; a lookup answering with one spelling is a machine for erasing that.
**Note** **the floor counts pages per fold, over all a word's spellings together, and ambiguity is judged before it applies.** Per-form would delete that same instance rather than refuse it — one page each, both below the default — so a floor could hide a conflict. It may withhold a handle from a form the corpus barely attests; it may never do the other thing.
**Note** the `floor` row is printed on every run because **an empty result is not a corpus-wide negative**: selection requires an inventory glyph, so a native token carrying no mark at all (a bare `c`, `s`, `j`, `x`, `h`) is invisible here by construction. `unkeyable` counts forms carrying something the marker table does not reach — two today, both English possessives on a native name.

### lexicon ipa [FORM...]
**Does** imputes IPA for a keyed native form, by rule. Feeds the pronunciation line and the speaker on a lexicon card in `edition serve`.
**Reads** `gt/ocr/` (with `--all`). **Writes** — **Exit** 0.
```
FORM...        a keyed form, NFD or not; several are several rows
--all          every native form in gt/ocr/ instead of the named ones [off]
--partial      only the forms that did not fully resolve [off]
--root --json --toon --pager
```
**Emits** `scope` (`forms`, `complete`, `partial`) and `forms` (one row per form: `form`, `ipa`, `state`, `unresolved`, `hedged`, `grades`).
**Note** **nothing here is evidence, and the firewall is not what is at stake.** The table reads no scan and proposes no glyph — it is applied to a form a human already keyed and ratified. What is at stake is the other failure mode: a pronunciation that reads as authoritative because it is spelled in IPA. So the card labels it imputed, and `state` goes `partial` the moment a character falls through.
**Note** rows are graded. `myth` is Bogoras's own account of his notation in the front matter to *Chukchee Mythology* (1910); `key` is the printed key at Part 1 p. 10, which supplies the unmarked ASCII sorts that account does not reach (`c` is English *sh*, `j` is French *jour*, `x` is *Bach*) and the seventh member of the palatalization series. **Note** **five sorts have no row on purpose** — `š`, `ë`, `ṛ`, `ḷ` and plain `g`. Each has a *gloss* in the p. 10 key and no IPA value, and turning "like *a* in *make*" into a symbol is a judgement rather than a lookup. They fall through, are named in `unresolved`, and `--partial` is the worklist. Likewise U+0027, which is both the spirant and the pause mark and which `keying_spec.md` says outright not to propose: it is refused rather than read in one direction for the sake of a complete-looking answer.
**Note** stress is dropped. U+02CA follows the stressed vowel where IPA's `ˈ` precedes the stressed *syllable*, so placing it needs syllabification and any rule for that is a guess. It still does work on the way out: `au` is one diphthong and `aˊu` is two vowels, because longest match sees the mark between them.

There is nothing there to silence: the conflict is the measurement. Only a conflict in ground truth is a claim about the corpus, and only that can be ruled on.

## entity

The encyclopedia: one markdown file per entity at `entities/<class>/<slug>.md`,
identified as `class:slug`. It is the referent of every `@ref` in the corpus and
the source of the alias vocabulary `tei generate` applies by rule.

**An alias may declare its language**, from the vocabulary in `harness/langs.py`
— `ckt`, `ru`, `la`, shortest BCP-47, the same string a page writes in
`xml:lang`. It is optional and blank means *unstated*, which `check` counts as
`aliases_untagged` and never gates on; a code outside the vocabulary is an error,
because that is a typo rather than a gap. The column records the fact and nothing
infers from it — in particular an alias suppresses `lexicon_miss` whatever its
language, exactly as before.

**An identity is always class-prefixed.** `person:jochelson` is the man and
`source:jochelson-yukaghir` is the book he wrote; the same string names both on
the same page, and a scheme without the class could not hold them apart. The
class lives twice — as the directory and as the first half of the heading — and
`check` compares them, because a file whose role lives only in its directory
name is the shape that cost this project 18 pages.

Human-authored and tracked, so `--commit` gates the two actions that write.

### entity alias ID FORM
**Does** add one alias row to an entry that exists. The form may be given as a **lexicon handle in braces** — `{Kulu'c^i}` — which is expanded to the ratified form the corpus prints; a literal form is normalized to NFD and otherwise trusted. Parses the file before writing, so a bad `--lang` or a duplicate form fails as a message.
**Reads** `entities/`, committed `tei/` and `mz/tei/` when the new form is rule-linkable, and the lexicon index only when the form is braced. **Writes** the entry, and under `--commit` every page that gained a link plus every draft rebuilt. **Exit** 0, or 1 on a refusal.
```
--lang CODE  the language the form is a name in, from `harness/langs.py`. Omitted means unstated, which most of the store says and which is a different claim from a wrong code
--auto {yes,once,no}  how widely a rule may link the form: `yes` every occurrence, `once` the first on each page and the rest bare, `no` never and a reader is asked on every hit [no]. On a ratified entry `yes` and `once` license a link, so the corpus pass runs
--note TEXT  the note cell — where the form is attested, or why it is `no`
--commit  write it; without this the row is reported and not added
--root --json --toon --pager
```
**Note** **this verb exists for the form's fidelity and for nothing else.** A `link:` or a `within:` is a line of ASCII that a text editor sets as well as a flag would, and wrapping those would add a surface without removing a way to be wrong. An alias is a *native form*, and typing one by hand is where this store gets hurt: a precomposed `й` against an NFD store matches nothing, an `i` for an `ɪ` is the corpus's largest correction family, an apostrophe for `ˊ` is one keystroke. None of the three is visible in the file afterwards.
**Note** the braced form inherits `lookup expand`'s rules whole: a key the book spells two ways resolves to nothing, and **nothing half-expands** — a row with one bad handle is not written rather than written wrong. `tei context`'s `tier1_terms` furnishes the key for every Tier-1 form on a page, which is where the handle comes from. Expanded at `min_pages=1`, matching that column.
**Note** a duplicate form is refused with a message rather than left to `parse`, which refuses a form listed twice and would otherwise break the file this had just written.
**Note** **the scaffold's placeholder row is replaced, not written under.** `entity new` emits `| | | no | |` so the alias table has a body; `parse` reads it as nothing at all, and left standing beside a real form it reads as an alias whose form went missing — a claim no human made and a worse one than the empty table it stood for. Safe to drop because it is the only empty-form row the store tolerates: put a note in that same row and `parse` refuses the file, so nothing erased here was ever written by hand.
**Note** **an auto form on a ratified entry runs `entity ratify`'s page pass**, for the same reason and by the same code: the rule links what the store held when the generator ran, and adding a licence afterwards left the form linked on no collated page and present in no draft — silently, `tei validate` having nothing to say about a link a page *lacks*. Collated pages are relinked and drafts regenerated, the split being `relink.py`'s.
**Note** **the trigger is `auto_forms`' own answer** and not its three conditions restated. A form is rule-linkable when exactly one entity claims it, that claim is not `auto: no`, and the entity is ratified; asking whether the form came out of `auto_forms` tests all three at once and cannot drift from them. `once` licenses exactly as `yes` does — the two differ in how many of a page's occurrences take the link, which is `entities.rule_links`' business, not this one's. `licensed: false` — a collision, or an entry still proposed — means no page can change and the pass does not run. A form claimed twice is `entity check`'s to gate, and it does.

### entity new ID
**Does** scaffold an entry at `status: proposed`. Nothing mints one ratified — a form a rule may link has to have been read by a human first, and `entity ratify` is that act. Parses the result before writing, so a bad `--within` fails as a message rather than as a file.
**Reads** — **Writes** `entities/<class>/<slug>.md` under `--commit`. **Exit** 0, or 1 if the entry already exists.
**Note** **there is no `--since`.** Both stores carried one — the page whose reading prompted the entry — required on the argument that an apparatus store which cannot be traced back to a page is unauditable. That argument was right and its answer got better: the card derives *every* page the entry is attested on, from the corpus, on every load. **A `since:` is satisfied by typing a plausible ref and a derived attestation list is not**, so the field was the weaker witness while keeping out entries the book plainly contains whose attesting page is among the 558 not yet transcribed. `entity occurrences --all` is where an unwitnessed entry shows now, as a row reading 0 and 0.
```
--canonical NAME  the display name, written into the heading. Not an alias unless you also pass it as one. Required
--alias FORM  a form that means this entity, added at `auto: no`. Repeatable. Raising one to `auto: once` or `auto: yes` is a separate act, in the file or the browser, because it licenses a link nobody will be asked about. A native form is the NFD surface spelling, never a lexicon handle key — the key is a fold and collides on purpose
--lang CODE  the language every `--alias` on this run is a name in. Left off, they are filed with the language unstated
--within ID  the entity that contains this one, `class:slug`. The atlas's whole structure, and the only thing that puts a location somewhere rather than merely on a map
--part-of ID  what this entity *belongs to*, where `--within` says where it *is*. A subgroup of a people, a work inside a larger work. Nothing drawing a map reads it; a `people:` with no geography of its own falls back along it for a bound, which is the one place the two meet
--geo MEMBER  where this entity is: a point `LAT LON`, a shape in `data/geo/` `kind:slug`, or another entity `class:slug` whose extent it takes. Repeatable, and the field is the union of its members. Identifying a name Bogoras wrote in 1904 with a polygon a modern service returned is a human's act, which is why a shape is typed rather than matched by name — `watershed:main` and the English word are one keystroke apart. `geo list` names every shape
--authority KEY  the entry in `data/authorities.json` this entity is the work of, e.g. `steller1774`. What puts the printed title on the card without the entry restating it
--commit  write it; without this the file is reported and not created
--root --json --toon --pager
```

### entity locate ID
**Does** set or replace an existing entry's `geo:` members, its `frame:` box, or both. **The act that puts a name on the map**, and it is a human's: a coordinate for a toponym Bogoras wrote in 1904, or the judgement that two sourced polygons are one speaker area, is an assertion about the world no rule may make. Re-parses the file before writing, as `entity new` does, and refuses a member naming a shape `data/geo/` does not hold or an entity the store does not.
**Reads** `entities/`, `data/geo/index.json`. **Writes** the named file under `--commit`. **Exit** 0, or 1 if the entity does not exist.
```
--geo MEMBER  a point `LAT LON` — two WGS84 decimal degrees, latitude then longitude, negative longitudes west as the store's sources write them, the shift into the atlas's continuous window being the reader's; or a shape in `data/geo/` `kind:slug`; or another entity `class:slug`, whose extent this one takes. Repeatable, and it **replaces rather than appends**: every `--geo` on one run is the complete new member list
--frame "W S E N"  four WGS84 decimal degrees, west south east north, saying where the map should look. Longitude first, unlike a `--geo` point, because it is a box; east may exceed 180
--commit  write it; without this the change is reported and not made
--root --json --toon --pager
```
**Note** at least one of `--geo`/`--frame` is required, and together is the normal case rather than a conflict. What is refused is the invocation that names an entity and changes nothing.
**Note** **`--geo` replaces the whole member list.** A flag that only appended would have no way to take a member off, so the run states the field entire and the reported `was` column joins every member it is displacing.
**Note** **`--area` is gone**, and `geo:` absorbed it. The two were one question with two spellings — a shape where the other held a point — and `parse` carried a rule forbidding a record to answer it twice. A composite `area:` is now simply several `--geo` members, and needs no canonical sorted spelling because there is no union to name.
**Note** **`--frame` is where the map looks; `--geo` is where the thing is.** It overrides whichever frame would otherwise have been derived and nothing else — `extent_of` is untouched, so an ancestor still sizes itself on the real geometry, and every member is still drawn. Two cases earn one, and both are defaults being wrong rather than missing: a container with no shape takes the union of everything beneath it, so `place:russian-far-east` reached 103°E and 41.7°N on the strength of the Lena and the Amur; a shape frames on its *parent*, which is what makes a shape mean something, but `place:chukchi-peninsula` is dense with villages and Chukotka's box packs them into a corner. A declared frame descends: the children of a framed entity frame on it, or the field would fix one page and leave every page under it drawn to the box just declared wrong.
**Note** singular ID, because the flags name one entity's fields — the same reason `proposal set` is singular. A new action rather than a flag on `entity new`, because creating an entry and amending one are different acts and `new` exits 1 on an entry that already exists.
**Note** the worklist it answers is `geo verify`'s `unlocated`.

### entity check
**Does** the store gate: every file parses, every class is known, every heading agrees with its directory and its filename, every `within:` resolves, is acyclic and has one of the four geographical classes at **both** ends, every `geo:` member resolves — as a shape in `data/geo/` or as an entity — and no `geo:` chain cycles, no form is rule-linked (`auto: yes` or `auto: once`) for two entities at once, and every alias's `lang` is in the vocabulary. Collisions that are not errors are reported anyway — an ambiguous form is the normal state, and the generator surfaces it as a question rather than resolving it.
**Reads** `entities/`, `data/geo/index.json`. **Writes** — **Exit** 0 clean, 1 on any defect.
**Note** a `geo:` member **resolving** is gated here and everything *geometric* is `geo verify`'s. Resolution is a fact about names, like `within:`; whether a child's shape actually falls inside its parent's is a fact about two delineations, and a gate there would reject true rows on the strength of a coarseness the source declared in advance.
**Note** **the three edge kinds are walked separately** — `within:`, `part-of:` and `geo:` — so a cycle message names the field a reader has to go and edit. A cycle that *crosses* two of them is deliberately not gated: `extent_of`'s path guard makes it terminate rather than hang, and an error naming no single line is one nobody can act on.
**Note** **`within:` is geography's alone.** It answers what terrestrial thing contains this one, which `geo verify`'s nesting check can test and the atlas walks. What a thing belongs to is `part-of:`; whose extent it takes is a `geo:` member. Two peoples were filed inside a village to borrow a box, which cost them their place in their own ethnicity's extent.
```
--root --json --toon --pager
```

### entity rename OLD NEW
**Does** move an entity to a new identity: the file, its heading, every `within:` and `[[wikilink]]` in the store that names it, and every `@ref` in a **committed `tei/` page**. With `--canonical`, files the old display name as an alias — `detectors.entity_forms` splits canonicals into the corpus's proper-noun dictionary, so retitling without it would drop the book's own spelling out of the dictionary and start reporting it as a transcription candidate. Skipped where the entry already lists the form, since `parse` refuses a form listed twice.
**Reads** `entities/`, `tei/`, `mz/tei/`, and `gt/ocr/` + `gt/zones/` for the drafts it rebuilds. **Writes** the moved file, every re-pointed entry, every collated page and every rebuilt draft under `--commit`. **Exit** 0, or 1 on a usage error.
```
--canonical NAME  the new display name; the old one is filed as an alias
--commit  write it; without this every edit is reported and none is made
--root --json --toon --pager
```
**Note** it **rewrites the collated pages and does not refuse them**, and names but does not touch `mz/tei/`. This used to refuse, on "a rule may not rewrite a page a human signed" — which conflated two things. That rule protects what a page *asserts*; an `@ref` asserts "this string names that entity", and a rename changes neither side of it, only the spelling of the pointer between them. Leaving it behind is what breaks the assertion, since the ref then resolves to nothing — which `tei validate` calls worse than no ref at all. `mz/tei/` is derived, `tei generate` brings it back, and rewriting it would only race the next regeneration.
**Note** **so it runs the generator instead**, on exactly the drafts holding the old ref, once the store has moved. Naming them and stopping was a hand-off with no receiver: nothing ran the regeneration the table implied, so until something unrelated did, those drafts carried a `@ref` resolving to an identity that no longer existed — and `edition serve --drafts` renders them. Scoped by the refs already found rather than through `relink.refresh_drafts`, which asks `occurrences` for pages holding an *unlinked mention*: the right question after a ratify and the wrong one here, where the pages are known by name and an already-linked mention is precisely what has to be reached. A draft that cannot be rebuilt — no `gt/ocr/` — reports `regenerated: false` with the reason and does not fail the rename, `ratify`'s rule and for its reason.
**Note** the class may change **only where the `<name @type>` does not**. What a page asserts is its `@type` — a reader saw a place-name — and whether that name denotes a point (`place:`) or a region (`land:`) is a fact about the store that no page ever recorded, so a move within one type leaves every collated page true. Across types it is refused: `place:` → `water:` is toponym to hydronym, the ref would contradict the type beside it, and that is a re-reading of the page rather than a rename. In practice the licence is exactly `place:`↔`land:` and `water:`↔`river:`, which is the split the geographical classes were made by; the 54 entries were migrated through this verb, one invocation each.
**Note** this is cheap only while the corpus holds few `@ref`s. It is the verb that makes an identity decision reversible, which is why the modern-romanization pass could be made at all.

### entity sigla
**Does** carries `Authorities Quoted`'s printed sigla onto the `source:` entries — as the entry's name, and as alias rows. **The siglum is how the book names a work**: a footnote sets `Maydell, I`, and the entry was called `Maydell 1893`, a string printed nowhere in the volume. Adds and renames; never removes a row a human wrote.
**Reads** `data/authorities.json`, `entities/`. **Writes** the `source:` entries under `--commit`, plus every page an added `auto` form links, exactly as `entity ratify` does. **Exit** 0.
```
--commit  write them; without this every change is reported and none made
--root --json --toon --pager
```
**Note** **the name is `[Cited, MAYDELL, I, II.]`'s and the aliases are its spellings.** A two-volume work is one work, so the name joins the volumes; the aliases split them, because a footnote cites one volume at a time. Each volume yields two rows, comma and no comma — `Maydell I, p. 331.` and `Maydell, I, pp. 627-680.` sit in the same apparatus, which is the fact `parse_citation` was built around, so the comma carries no information and both spellings are the store's.
**Note** **a bare surname is left entirely alone — no alias, and no rename either.** It is already the entry's row, and it is the one the *alias table* cannot decide: `person:nelson` claims `Nelson` too, and an alias is a context-free string match. It is not undecidable — `Nelson, pp. 27, 28` is the book and `citations.py` links it on the locator, which is 64 of the corpus's 130 `source:` links. The rename follows from what a siglum is worth as a heading rather than from ambiguity: `Maydell, I` says which work, `Steller` does not, and the guard was written on the alias half only at first, so 17 entries came out titled `Steller`, `Nelson`, `Murdoch`. What the sigla add is the *uncontested* half: `Boas, Central Eskimo` is claimed by one entry, so it links by the ordinary alias rule with no citation evidence needed, and the mark covers the siglum whole instead of stopping at the surname.
**Note** `auto` is `yes` only where nothing else in the store already claims the form — `entity check`'s own rule, applied before the row is written rather than left for it to catch afterwards.

### entity ratify ID...
**Does** `proposed` → `ratified`, **and applies the links that ratification licenses to every collated page**. **The human act**, and the only thing that lets a rule link the entry's forms without asking — so it means the entry has been read against the pages it claims, not that it looks plausible.
**Reads** `entities/`, committed `tei/`. **Writes** the named files and every page that gained a link, under `--commit`. **Exit** 0.
```
--commit
--root --json --toon --pager
```
**Note** the page pass is why this is one act and not two. `tei generate` links every auto form the store held *when it ran*, and collation follows generation — so an entry ratified afterwards left plain text on every page already collated, invisibly, because `tei validate` re-derives the links a page *has* and had nothing to say about the ones it lacks. Both directions are checked now: validate reports the gap as a worklist line, and this closes it.
**Note** **collated pages are relinked; drafts are regenerated.** A draft carries the generator's own questions beside its text, so applying the link without answering the comment would leave a fresh `<rs>` next to a note saying no rule may write one — two halves of a file contradicting each other with neither marked stale. `tei generate --force` rebuilds both from the same store in one pass, and it is scoped to the pages that mention the entity rather than sweeping the corpus on every ratify. A page a collator has claimed is in `tei/` and so is not a draft, which is what keeps the force from moving a baseline under a review in progress. A draft that cannot be rebuilt — no `gt/ocr/` — is reported still out of date rather than raised: ratifying an entry is not the act that should fail because a derived file will not build.
**Note** it rewrites the page source rather than round-tripping a parse tree, so everything the rule did not touch comes back byte-identical and the diff is exactly the links. `harness/relink.py` names the four things it will not do — text already inside an `<rs>`, text inside a `<name>`/`<foreign>`/`<term>` (a Tier-1 handle is *enclosed* by a reference, never pierced by one), a segment carrying an XML entity, and a match crossing an element boundary — and reports each rather than skipping in silence.
**Note** without `--commit` the page rows are a preview of what ratifying would apply, computed against the store as it would be.

Measurement; never gates.

**Note** **committed `tei/` alone.** `entities.occurrences` takes its page list from its caller, and the reading view passes a wider one — the drafts too, under `edition serve --drafts` — so that the card can show mentions before anything is collated. ## geo

The compiled shape store at `data/geo/` — watersheds, language areas and the
coastline the atlas draws — and the geometry checked against the hierarchy a
human authored.

**The store is built by `tools/build_geo.py`, not by this group.** Its sources
live outside the repository (`scratch/`, which is gitignored, and a symlink into
a download directory), so the compiled store is **tracked** and nothing here
writes. That is the split `scans/` has: a `tools/` script builds from what only
one machine holds, the harness reads what is committed. `data/geo/SOURCES.md`
is the provenance record and carries the one licence condition — Asher 2007 is
CC BY 4.0, so its citation is in the corpus `teiHeader` as well.

**A shape id is `kind:slug` and a kind is never an entity class.** `langarea:`,
not any live entity class: an entity file carries `within: place:chukotka` two lines from
`area: langarea:chuk1273`, and a reader who cannot tell the two apart by looking
is one keystroke from an `area:` that resolves as an entity reference.
`entities.parse` refuses a kind that collides.

### geo bounds ID...
**Does** the bounding box of each named region and their union — **the measurement a `frame:` is written from**. Takes entity ids and shape ids in one list. An entity's box is `geo.extent_of`: its own shape, else its own point, else the union of everything beneath it, which is what the atlas frames on; a shape's is the polygon's own. The union row carries `span_lon`/`span_lat` and a `frame` field spelled exactly as `entity locate --frame` takes it.
**Reads** `data/geo/`, `entities/`. **Writes** — **Exit** 0.
```
--margin DEG  degrees added on all four sides of the union
--root --json --toon --pager
```
**Note** the two vocabularies are told apart **by their prefix, with no flag**, and that is decidable only because a shape kind may never be an entity class — the rule `entities.parse` enforces so that a member spelt `kind:slug` cannot quietly read as an entity reference. The invariant pays for itself here.
**Note** `--margin` is **content, not breathing room**: `geomap.Frame` already pads a drawn map on every side, so this answers the different question of how much more of the world to show. Degrees rather than a percentage, because a percentage of a box 60° wide and 20° tall is two distances and the caller would have to know which.
**Note** longitudes are the store's shifted window — the same one `--frame` and `frame:` read — so the printed string pastes straight through.
**Note** an id with no extent is a **row reading null, not a silence**, and it does not enter the union. `place:cape-prince-of-wales` is named by the book and located by nothing, and it is the east edge of `place:northeast-siberia`'s frame: that edge was estimated by hand, and a tool that dropped the row would have made the estimate look like a measurement. An unknown id says which vocabulary it was looked for in.

### geo list
**Does** every shape in the store — id, kind, name, point count, area, source, and the entity that claims it. **Also the absences**: four speaker areas this edition sought in Asher 2007 have no polygon there — Siberian Yupik, Chuvan, Kerek and Tundra Yukaghir, two of them (`ypk`, `xcv`) Tier-1 codes — and they are rows here rather than silences, because an entity pointing at nothing and an entity nobody has got to yet look identical from outside.
**Reads** `data/geo/`, `entities/`. **Writes** — **Exit** 0.
```
--root --json --toon --pager
```
**Emits** `scope` (`shapes`, `claimed`, the longitude `window`, `absent`, `composites`), `shapes`, `composites`, and `absent`.
**Note** **a composite `area:` counts as a claim on each of its members.** A union is a fact about `entities/` and this census is a fact about `data/geo/`, so the unions are listed after the store's own rows and never among them — nothing mints a shape by naming one.
**Note** **the `absent` block holds two kinds of absence and says which.** It began as "a Tier-1 code Asher 2007 draws no polygon for"; it now also holds a feature no gazetteer in hand carries at all — Bering Strait, which is in neither Natural Earth layer at 10m. A row therefore carries `sought` and `source`, what was looked for and where, so the second is not read as the first.
**Note** longitudes are normalized into `[60, 420)`, so anything above 180 is west of the antimeridian and Chukotka runs continuously rather than tearing from +179 to −179. It is what lets every planar operation downstream treat a meridian-spanning shape as an ordinary one.

### geo verify
**Does** the geometry against the authored hierarchy, and the hierarchy against itself. Six reports, none of which gates.
**Reads** `data/geo/`, `entities/`. **Writes** — **Exit** 0.
```
--root --json --toon --pager
```
**Emits** `nesting`, `meridian`, `containment` (one row per child/parent pair that both carry an `area:`), `shared`, `unclaimed`, `unlocated`.
**Note** `meridian` **is the one finding here that is about the drawing rather than the world.** A publisher cutting a shape at 180 leaves two halves and `build_geo.prepare` welds them — when they meet. Natural Earth's 10m Wrangel Island left its halves 0.011° apart and its Bering Sea flush but unmerged, so the store held two rings where the world has one thing, and `geomap.paths` emits one stroked path per ring: a line down the middle of the shape, on every map that drew it. Nothing measured it; a reader found it by looking at the atlas. A ring that *crosses* 180 is welded and is the healthy case; a shape with more than one outer ring **ending at** the meridian is cut into pieces. One such ring is not reported — `langarea:chuk1273` stops where Asher drew it, with nothing to weld to — and composites are not walked, since `people:chukchi` abuts two shapes at 180 by a decision `SOURCES.md` records.
**Note** there was a `points` section — a `geo:` measured against its own `area:` — and it is gone because the case it reported is now refused: `entity check` will not accept a record carrying both. A shape is the location, `extent_of` never reads a point beside one, and a field nothing reads can only drift. It was tolerated for the river's sake, a basin plus its mouth; but that is two things, and if the mouth is worth naming it is worth an entry.
**Note** `nesting` **needs no geometry**, which is why it comes first: it speaks about every `within:` in the store, where `containment` can only speak about the pairs both of whose members somebody drew. A row is a `within:` whose two classes cannot both be true — a child under a `place:`, which is a point and contains nothing, or a settlement or drainage basin under a `water:`, which is open water. `land:` under `water:` is **not** a row: an island in a strait is exactly that and has nowhere else to be filed. `geo.NESTING` carries the table and the argument.
**Note** `unlocated` **is `unclaimed` from the other side** — entities inside a subtree the atlas can draw that carry no `geo:`, `area:` **or `frame:`**. A frame settles a row as surely as a shape does: it is an authored statement of where the map should look, written in exactly the cases where the derived box was wrong, so listing it asks for work already done. `unclaimed` says what the store has that nobody points an entity at; this says what the tree names that nothing puts on a map, which is the worklist a human supplying coordinates actually has. `entity locate` answers a row of it. Scoped by the tree rather than by class, because every person and source in the store is unlocated and always will be, and a worklist mostly made of rows nobody will act on is one nobody reads. `wants` distinguishes an entity that needs a coordinate from one already framed by its members — asking for a boundary for Chukotka is exactly what the atlas refuses to do.
**Note** it is **scoped to located subtrees and so has a blind spot**: a geographical entity with no `within:` and nothing located beneath it is on no subtree the atlas can draw, so it appears here not at all. There are 32 of those against 41 rows, and they are invisible to the atlas for the same reason. `tools/gazetteer.py propose --unlocated` takes the wider set — every `place:`/`land:`/`water:`/`river:` entry with no `geo:`, `area:` or `frame:` — which is what a human filling the store in actually wants.
**Note** **containment names the pair, never a culprit.** A basin delineated from a tributary's outlet is contained in its trunk's by construction, so this is a real second witness on the river chain — but a disagreement says one of two authored facts is wrong and the geometry cannot say which.
**Note** **the reading respects the source's own declaration of precision.** The delineator reverts to a coarse DEM above 50,000 km² and says so in the file; a coarse parent's boundary wanders by tens of kilometres, and a true tributary measured against one lands at 0.70–0.87 rather than 1.00. Every containment pair in the store today has such a member. Measured on the real shapes: relations the book and the map both support land at 0.68–0.82, and a river paired with a basin it has nothing to do with lands at 0.00–0.11 — so the floor sits in the gap, and `coarse` names the member that put it there.
**Note** a `geo:` point outside its own shape is reported **with the distance and is not a defect by itself**: a river's natural point is its mouth, which sits *on* the boundary the basin was delineated from. `water:anadyr` is 0.59° out, at the estuary.
**Note** a shape two entities claim is legal and reported — a people and a subgroup inside it may both point at one Asher polygon, and forcing a choice would be this edition deciding something the source does not. Nothing in the store shares one today: every case was a `language:` entry duplicating its people's claim, and that class is retired.

## edition

The reading view. Its own group rather than an action under `tei` or `entity`,
because it is over neither one: the page, the entities it links and the raster it
was read from are three stores, and the point of the view is that they are in one
place.

### edition serve
**Does** open the reading view on 127.0.0.1 — collated TEI in a main column, a stack of entity, note, map and scan cards beside it, plus the encyclopedia, its audit queue, and `/atlas`: the `within:` hierarchy as a navigable tree with each node drawn inside its parent's extent. Shows committed `tei/` only unless `--drafts`; a generated baseline is a draft nobody has read, and an end-user preview is the last place it belongs. Ratifying an entry in the browser writes `entities/` without `--commit`, as the other editors write their stores — the click is the human act, the store is tracked, git is the witness — and every write is rolled back if `entity check` would fail on the result. Blocks until the page or ctrl-c stops it.
**Reads** `tei/`, `entities/`, `data/geo/`, `scans/`, and `mz/tei/` under `--drafts`. **Writes** `entities/` on an explicit click. **Exit** 0.
**Note** `--drafts` is **read-only and marked everywhere it shows**: in the listing, on the page itself and beside every search hit, because a URL typed straight in skips the listing that would otherwise carry the warning. It reaches `mz/tei/` **by naming it** — `tei/` is a store and never a symlink farm over the generated one, since nine callers read "a file is in `tei/`" as "somebody collated this" and a link is indistinguishable from a signature to all of them (`test_tei_is_a_store_and_never_a_farm`). Entity attestations stay signed-only whatever this flag says: an attestation is a claim about a reading, and a draft has read nothing.
**Note** the atlas is **scoped to located subtrees** — a root is an entity with no `within:` that has somewhere to put on a map, itself or below it — otherwise every person and source in the store is an atlas root. A node with no `area:` and no `geo:` is framed by the union of what lies beneath it, and the map says so: no source draws a boundary for Chukotka, and a frame is a viewport rather than a claim.
```
--port N  this editor's door onto the shared server [8734]
--no-open  do not open a browser; print the URL and wait. For a headless run, and for the tests
--drafts   also show `mz/tei/` — the pages `tei generate` built and nobody has read. Every one is marked as a draft, in the listing, on the page and in search results. Read-only: this is a window onto the generator's output while it is being fixed, not a way to collate
--root --json --toon
```

### edition runs
**Does** the page-runs the reading view serves as one document instead of a leaf at a time — the printed Contents, List of Illustrations and Authorities Quoted — plus a census of what every leaf outside the transcription tracks was ruled, one row per leaf and per editor's leaf, and everything wrong with the declarations. Six scans of List of Illustrations are one printed list, and serving them as six pages is serving the binding rather than the book. Reports the folio count too: every folio link a run renders goes through the index, and that number says how much of the book the locator can reach at all.
**Reads** `data/runs.json` and each run's `source`, `gt/zones/` split lists, `tei/`, `gt/ocr/`, `gt/page-img/`, `scans/`. **Writes** — **Exit** 0 clean / 1 on a declaration that cannot be true.
**Note** the fatal set: a run over a leaf not ruled `apparatus` (`not-apparatus`), a leaf ruled `apparatus` that no run names (`apparatus-not-in-run`), a ref that is no scan, a span that is discontiguous or that two runs both claim, a `kind` with no renderer, a span its own store contradicts, a run leaf the store records no entry for (`unwitnessed-leaf`), two pages claiming one folio **at the same rank**, and an editor's leaf that is for a page still in the tracks or is a different shape from the scan (>0.5% aspect). A folio two witnesses of *different* rank disagree on is a **warning**: rank resolves it, and the disagreement is usually a misread running title worth seeing rather than a fault.
**Note** **`apparatus` is checked in both directions, and only one of them used to be.** A run's leaves must be ruled `apparatus` rather than merely be out of the transcription tracks: a plate in a run would render as a list of entries it does not have, and the looser test could not say so, a plate having left the tracks exactly as the Contents did. The other direction is new — the kind promises the leaf's content is held parsed somewhere and the run is what names which store, so a leaf ruled `apparatus` with no run has a promise and no reading behind it, and falls back to a bare scan.
**Note** `leaf_kinds` is the census — one row per `zones.LEAF_KINDS` member and how many leaves carry it. **Measurement, never a gate**, and it is the frame the rest of the report is read in: a run is a span of `apparatus` leaves, so how many of each kind exist is what says whether the runs cover what they should.
**Note** `plates_located` is a **measurement and does not gate**: a plate carries no number on its own leaf, so `figures.by_plate` derives it by matching the printed list's abbreviated caption against the keyed under-figure one. What would be wrong is a plate resolving to two leaves, and that resolves to none by construction — the reading view then prints it plain.
**Note** **three statements of one span, and they are not all checked the same way.** `runs.json`'s `refs` and the store's own `source.refs` must **agree** — both are declarations about the printed section, and a disagreement means one of them is stale. The per-entry `ref` fields are checked in **one direction only: the run demands full presence, and the store may hold more.** Every leaf a run names must carry at least one entry (`unwitnessed-leaf`), because a run declaring a leaf its store says nothing about renders an empty apparatus page and nothing else could report it. An entry naming a leaf **outside** every run is not a fault: Authorities Quoted is an open list, folio 9's asterism admits a work printed anywhere in the book, and the chapter XXIII footnote on `3-146`/`3-147` is a second bibliography of twenty-one numbered works. Gating that direction made the run the store's boundary and forced such a record to drop its `ref` — discarding the leaf it is printed on to satisfy a check about rendering. Nothing is needed to keep it off a leaf: `entries_for` resolves the leaf to a run first and returns `[]` when there is none. A store with no per-entry `ref` **at all** is still reported unrenderable, because `entries_for` has no fallback: a leaf shows what the store says was printed on it, and attributing a whole list to one leaf would be inventing that.
```
--root --json --toon
```

## corpus

Whole-corpus gates, and the census across every store. An action lands here only
if its subject is the corpus as a whole rather than one store. `state` is the one
that does not gate, and it belongs for the same reason the other two do: no
single store can answer it.

### corpus state PP-NNN [PP-NNN ...]
**Does** reports where each page has got to across every store at once, on one ladder: `scanned` → `zoned-mz` → `zoned-gt` → `ocr-mz` → `proposed` → `decided` → `ocr-gt` → `generated` → `collated`. `stage` is the furthest rung reached; `skipped` names the rungs below it that are **not**, so a page that took a route the pipeline no longer offers stays visible instead of being summarised away. **`zoned-exempt` is a terminus off the side of the ladder**, not a rung on it.
**Reads** the presence of paths only — `scans/`, `gt/zones/` + `mz/zones/` + the split lists, `gt/ocr/` + `mz/ocr/`, `gt/fig/`, `review/PP-NNN/`, `mz/tei/` + `tei/`. Never a file's contents, which is what makes it ~0.4 s over 832 pages and also why it cannot say whether a page's zoning is any *good*: that is `zones check`, and it costs a raster.
**Writes** —
**Exit** always 0. A census is measurement, not a gate.
**Note** **`--all` enumerates `scans/`, not any store.** A page no store holds is the most interesting row this verb has, and enumerating a store would hide exactly those — which is also why `absent` is a stage rather than an omission.
**Note** **`generated` is a rung because collation is gated on it** — `tei queue` refuses a page with no `mz/tei/`, so ground truth alone is not readiness and the ladder names the missing step. It is the only rung one command fills corpus-wide, so a count here is a to-do rather than a finding; `1-021` and `1-022` were collated before the generator existed and report it as a *skip*, which is exactly the retired-route case below.
**Note** **`skipped` is the point of the ladder.** `2-030` reached `gt/ocr/` by the eScriptorium route before the review loop existed; 18 pages carry `gt/ocr/` with no prediction behind them, the eScriptorium-shell cohort; `1-359` carries human zones with no `mz/zones/`. Each is a provenance fact no single store's verb could see. **A rung a route legitimately omits is not a skip**: `zoned-mz` first counted against every exempt page, which put 83 plates in the report and left `1-359` indistinguishable among them — 84 rows saying nothing where 1 says something.
**Note** **`zoned-exempt` is where a ruled leaf stops, and it is deliberately not a rung.** A plate, blank, cover, map or apparatus leaf is *finished* the moment somebody rules it: it holds no zone file — `exempt => no zones`, the mark is the record — and there is no text on it to recognize, propose or collate, so it will never climb another step. It was reported as `zoned-gt` until this stage existed, which put 115 leaves in the column a reader scans for work still pending. It is kept out of `STAGES` because that tuple is the ladder and `skipped` is "every rung below the furthest that is absent" — a rung no text page can satisfy would read as a skip on all 717 of them, the same defect one column over. `skipped` is cleared on an exempt page for the same reason: the rungs above are steps that do not apply, not steps it failed to take.
**Note** the same row, minus `ref`, is `page_state` in `harness tei context` — so a collation pass is never left inferring the rank of its own input. An empty `tier1_terms` means "no ground truth" on 802 pages and "ground truth with no marked forms" on `3-063`, and those call for opposite behaviour.
**Note** **`--refs` and `--limit` are the worklist pair** — a bare ref list in scan order, capped, which is what a dispatch loop wants and what saved every caller from re-deriving it. Both are **refused with `--tally`** (exit 2) rather than quietly ignored: a tally lists no refs, and a count taken over a truncated row set is a census that is simply wrong while looking exactly like one that is right. `--limit` is not the silent truncation this project forbids — the caller named the number, so the bound sits at the call site, where every other cost here sits. `corpus state --all --stage ocr-gt --refs --limit 2` is "the first two pages ready to collate".
**Note** **`--context` windows over `scans/`, not over arithmetic.** `PP-NNN` says nothing about how long its part is, so a window is applied to the observed index list rather than computed — which clamps it at each part's end for free, steps over a gap in the sequence instead of counting it as a page, and never crosses a part boundary. `1-362` and `2-001` are neighbours in the binding and nowhere else, and a context spanning them would assert a continuity the scan index does not carry.
```
--all           every scan in scans/, whether or not any store holds it
--context SPEC  also the pages around those named, by scan index within the same
                part: N each way, +N ahead, -N behind, -N+M both. Counts are
                inclusive; a sign binds only its own side, so 5+3 is refused
                rather than guessed at. No-op with --all
--stage NAME    only pages at this rung; repeatable. absent, scanned, zoned-mz,
                zoned-gt, ocr-mz, proposed, decided, ocr-gt, generated, collated
--skipped       only pages that missed a rung below the one they reached
--tally         counts per rung instead of the rows; every rung listed, empty ones
                included — nothing-has-reached-it and everything-has-passed-it are
                different facts
--refs          the bare ref list instead of the rows, in scan order [off].
                Refused with --tally
--limit N       at most N rows, from the front of the scan order [no cap].
                Refused with --tally
--root --json --toon --pager
```

### corpus normalize REF|PATH [REF|PATH ...]
**Does** NFD conformance, §2.9 spacing, §2.10 marker spacing (a body reference sets tight, a note opener sets marker-space-text), and the lookalike census across every store. It prints the census **and** what a `--commit` would rewrite — two tables, because they are two code paths and a preview agreeing with itself is no preview.
**Reads** every corpus store, deduped by real path (`ocr/` and `gt/ocr/` are two names over one inode).
**Writes** corpus files in place under `--commit` — raw source, never a parsed tree, so element and attribute order cannot move.
**Exit** 1 on NFD drift, an unlicensed mark, or spacing drift. The lookalike census does **not** gate: it is a worklist needing a human ruling on what the page prints. `--commit` always exits 0. Exit 2 for nothing named, for targets together with `--all`, or for a **named path that does not exist**. **Also printed, as a closing `verdict` section** — see `proposal check`; a clean scan and one whose findings do not block but which `--commit` would still rewrite are both exit 0 and are not the same result.
**Note** **the scope is a mixed positional list**, a `PP-NNN` ref or a path, and the two never collide because a ref's shape is closed. `harness corpus normalize 1-052 data/readings.md` scopes to both. It was `--path`, repeatable — a required file argument spelled as a flag, which is the smell the whole plural pass came out of.
**Note** **a path is checked for existence; a ref is not.** A ref fans out to five candidate files and most pages hold only some of them, so absence there is ordinary. A path typed out names one file, and the scoped walk starts from the corpus globs and *intersects* — so a mistyped or out-of-scope path contributes nothing and reports `files: 0` under a verdict reading "clean", which is indistinguishable from having passed. The pass depends on this: `/rebuild-groundtruth` normalizes `review/PP-NNN/decision.json` before restoring, and a clean verdict over a file nobody read is the one result that gate must never give.
**Note** **a named ref covers its own `proposal.json` where `--all` does not.** The corpus sweep excludes proposals on purpose (`normalize.PATH_ONLY_GLOBS`): a proposal for an already-restored page accumulates apostrophe hits that can never be resolved, so it would be permanent noise in a corpus-wide gate. Naming the page is the same explicit act `--path review/PP-NNN/proposal.json` was, so the mid-pass protection survives the change.
```
--all        every file the corpus globs reach
--commit     write the fixes; required to touch any file, scoped or not [off]
--root --json --toon --pager
```
**Note** **`--all` is ~8 s over ~2000 files and draws two bars, one per pass.** Two rather than one for the same reason there are two tables: a single bar spanning both would present two witnesses as one. It takes no `--jobs` — the sweep was benched twice, before and after a 2.2× optimization of `unlicensed_marks`, and is GIL-bound both times (`parallel.py`).

### corpus provenance

## fig

The figure and caption track in `gt/fig/`: one `GraphicZone` per picture and one
`GraphicZone-FigDesc` per caption, **freely-placed rectangles** rather than the
zone track's fixed-width bands of the measured column. The caption *text* is not
here — it is hand-read into `data/readings.md`, keyed by the last field of a
block id, and `harness corpus figures` is what reconciles the two stores.

Its own group rather than actions under `zones`, because the geometry regime
differs: a zone's x comes from the page's column and a hand-drawn width would be
a lie the trainer learns, while a picture's x is exactly what a human saw. The
two tracks share one editor and one keyboard (`harness zones edit`); they share
no geometry, no split lists and no exemption files.

**There is no view over `gt/fig/` and `mz/fig/`**, deliberately, where `zones/`
covers the zone stores. Every consumer of figure geometry names `gt/fig` directly
— `zones blot`, `ocr gaps`, `tei context`, the reader dispatch survey — and the
one thing a view would buy is the one thing that must not happen: `zones blot`
painting `scans/w-figs-blotted/` from *machine* figure claims, and the zone
segmenter then training on them. A proposal reaches a human through the editor,
which asks, or not at all.

### fig check [PP-NNN ...]
**Does** the gate. Named pages give their errors, warnings and exemptions in full; `--all` sweeps the store and lists only the pages with something to say.
**Reads** `gt/fig/` or `mz/fig/` per `--store`, `gt/fig/_rule_exempt.json`, the split lists, `data/zones_config.json`, `data/figure_numbers.json`, and each page's raster for its dimensions.
**Writes** —
**Exit** 1 if any page in `gt/` has an **error**, or if the figure-number patch table names a zone the store does not hold; 0 otherwise. Always 0 for `--store mz`, which is measurement.
```
PP-NNN...     which pages; several may be given
--all         every page the store holds
--store {gt,mz} which store to read [gt]
--root --json --toon --pager
```
**Note** **three errors, and the list is short on purpose.** A label the store does not declare; a `Shape/Polygon` that is not the rectangle its own bbox claims; a box off the raster. Each is unarguable — nothing could read the first, nothing does read the second, and the third describes part of a page that does not exist.
**Note** everything else is a **warning**: configured in `data/zones_config.json`, exemptable per page, never gating. `captions-lte-figures` is a fact about *this book* (414 pictures to 395 captions, and every caption-heavy page this store ever held turned out to be a segmentation fault). `picture-overlap` and `tiny-picture` were briefly written as errors, on the zone track's model, and that was importing a rule from a geometry regime that does not apply: zones partition the page and form a chain, so an overlap there is unrepresentable and can be refused, while figures are freely placed — an inset sits inside the frame it insets, two pictures on a plate may abut, and a 14×38 px box is suspicious rather than impossible. Over the migrated store the two produce exactly three findings (`1-189`, `1-334`, `2-085`), every one a real thing to look at and not one a thing the store must refuse to hold.
**Note** a corpus sweep of `gt/` also checks `data/figure_numbers.json`, the hand-keyed table for the three figures whose number no rule can derive (`docs/apparatus.md`). Each entry names picture zones on a leaf, so it is a claim about *this* store and is verified against it rather than trusted — re-box that leaf and the patch must fail, not go stale.
**Note** an exempted rule **still reports**, flagged, the way the zone track's do — a warning that vanished when excused would leave no way to notice the excuse had outlived its page. An exemption naming a rule the config does not declare is an *error*, since a typo would otherwise excuse nothing while reading as a considered judgement.

**Reads** `gt/fig/` and its sidecars.
**Writes** with `--commit`: removes `gt/fig/chukchi-PP-NNN.xml`, keeping one `.xml.prev` deep, and appends to `gt/fig/_journal.jsonl`. Without it, nothing.
**Exit** always 0; deleting what is not there is a row saying so, not a failure.

```
PP-NNN...     which pages; several may be given

--root --json --toon --pager
```
**Note** **the counterpart to the store's refusal of an empty page.** Absence of a file is how this store records "no figures here" — read that way by `zones blot`, `ocr gaps` and the reader dispatch alike — so an empty ALTO would assert the opposite of what it means, and a page whose last box was deleted has no other way to say so.

### fig extend [PP-NNN ...]
**Does** grows keyed pictures to cover the photograph the source PDF separated out, so nothing is left of a photo outside the box that describes it.
**Reads** `gt/fig/`, `data/pdf_images.json`.
**Writes** with `--commit` **and** `--max-growth`: `gt/fig/chukchi-PP-NNN.xml` through `save_figs`, keeping the `.xml.prev` and appending to `gt/fig/_journal.jsonl`. Without both, nothing.
**Exit** always 0, except 2 when `--commit` is given with no `--max-growth`.
**Note** **union only, never intersection.** A box that stops inside its photograph leaves an antialiased rim the blot then paints around; a box *larger* than its photograph is left exactly as it is, because some figures carry line work outside the JPEG — rules, lettering, a plate border, all living in the bitonal master — and contracting onto the rect would uncover them. 85 of this corpus's 371 photographs sit inside a box already, which is that rule earning itself 85 times.
**Note** **1:1 correspondences only, and that is the scope of the verb rather than a stage of it.** The photograph must overlap exactly one picture and that picture be overlapped by exactly one photograph. 14 figures here are one photograph spanning several keyed boxes — a figure the book letters *a, b, c* under one caption — and there is no correct mechanical answer for them: unioning each part with the whole rect makes them duplicates and destroys the grouping `figure_boxes` folds on, while apportioning the rect between parts invents boundaries the source does not draw. They report as `out_of_scope` and stay there; the editor is the remedy.
**Note** **`--max-growth` has no default, and `--commit` without it is a usage error.** The ceiling is a judgement about how far a mechanical rule may move a rectangle a person drew, and a default would make that judgement silently and then let it read as the operator's. A report run prints what every box would gain and the p50/p90/max of the distribution, so the number is chosen from the evidence. Measured over the 272 that move: p50 +0.59 %, p90 +1.74 %, max +9.81 %.
**Note** **refuses any page whose growth would change which caption goes with which picture.** `_gap` pairs a picture to a caption by distance, so growing a picture downward moves it toward one; the growth is far below any plausible gap, but that is a prediction and the diff is a fact. `figures.paired` is recomputed and the page is restored if it moved.
```
PP-NNN...        which pages; several may be given
--all            every page with a photograph in the manifest
--max-growth PCT largest area increase allowed on any one picture; required to commit
--commit         write gt/fig/; without it, report what would grow and by how much
--root --json --toon --pager
```

### fig crops [PP-NNN ...]
**Does** cuts every declared picture out of its raster — one PNG per `GraphicZone`, named `chukchi-PP-NNN-KKK.png` after the zone's own id suffix.
**Reads** `gt/fig/`, `scans/`, and `gt/fig-img/` to report which pictures a human has already replaced.

**Note** **no `--commit`, because the tree is derived** — `--commit` gates the authored stores, and `zones blot` is the precedent for a raster tree that writes on invocation. **Note** **one crop per box, not one per printed figure.** A union was tried first — the book calls `1-276`'s fig. 140 one figure and letters its parts inside a single caption, and the worst union measured only 1.75× the area of its parts. **Note** **enhancement is manual, and `gt/fig-img/` is where a manual one lives.** Nothing here sharpens, denoises or upscales: a crop is the raster's own pixels inside a box a human drew, asserted by a test against a gradient. Editing a file in `scans/fig-crops/` instead would lose it to the next `--force` with no copy anywhere, in a tree git does not carry — this repository's one catastrophic failure, re-enacted. The `human` count is reported on every run so a rebuild can never quietly shadow the work.
```
PP-NNN...     which pages; several may be given
--all         every page the figure store holds
--force       re-cut crops that are newer than both their inputs
--out DIR     where to write them [scans/fig-crops/]
```

### fig sheets [PP-NNN ...]
**Does** tiles every `GraphicZone-FigDesc` on the named pages onto contact sheets for reading — ~12 padded, upright strips apiece, each labelled with its `<ref>|<zone-suffix>` key — plus a `manifest.json` mapping every key to its sheet, strip index, orientation and pad.
**Reads** `gt/fig/` and `scans/`.
**Writes** `review/captions/sheets/` (derived).
**Exit** always 0. A page with no caption block contributes nothing rather than erroring; `fig check` is where geometry gates.
**Note** **the sheet is the unit of work, and the census is the argument.** 151 of the 250 captioned pages hold exactly one caption, 68 hold two; the median caption is 66 characters over one or two printed lines, and 34 of the 395 carry a Tier-1 glyph at all. The whole store is ~26 KB of mostly plain English. Dealing that out a page at a time — a directory, a queue entry and an agent apiece, as the line pass does — would be scaffolding standing in for a store; twelve strips to a sheet puts the corpus in **33 images**. The line pass is heavy because a page there is forty lines of dense phonetic type, which is a fact about that pass and not about this one.
**Note** **padded vertically, which is the opposite of `fig crops` and for the opposite reason.** A picture crop wants the picture, so a pad there pulls body prose in. A caption strip exists for somebody to *read the type*, and the commonest defect in this store is a box drawn round the wrong number of printed lines — the very failure that stripped the `TextLine`s from `gt/fig/` in the first place. A strip cut at the declared edge cannot show a line the box excluded, so the reader would reproduce the segmentation's mistake with no way to see it. The declared edge is **ruled on the strip** instead: between the rules is what the store claims, outside is context. `--pad 0` restores the old blindness and is offered only so the choice is visible.
**Note** **rotated plate captions are turned upright, by `paired`'s own discriminator.** A plate sets its caption rotated beside the picture, reading bottom-to-top — `1-049`'s three are 86×457, 92×506, 82×636 against a text figure's 610×96 — so `width >= height` decides it, exactly as `_gap` uses it to choose whether to look below a picture or beside it. Measured over the store, **64 blocks are portrait and the narrowest is 4.3× taller than wide**: there is no borderline case, so the test is unambiguous rather than a threshold anyone has to calibrate. The pad follows the reading axis, so a rotated caption is padded on x. **Rotation is presentation and reaches no store** — the manifest records `orientation` so a reading keys back, and `gt/fig/` keeps saying what it said.
**Note** **not the `scans/fig-crops/` farm, deliberately.** That farm's membership is computed by `crops_wanted`, which enumerates `GraphicZone` only, and it and `write_crops` must enumerate the same set or `views check fig-crops` reports drift against itself forever. Caption strips are review ephemera and live with the pass that reads them, so the farm is untouched and no membership question arises.
**Note** no `--commit`: the tree is derived, `fig crops`' rule.
```
PP-NNN...     which pages; several may be given
--all         every page the figure store holds
--out DIR     where to write them [review/captions/sheets/]
--per-sheet N strips per sheet [12]
--pad F       vertical pad as a multiple of the block's own height [0.6]. 0 cuts at the declared edge and hides exactly the defect the pad is for
--root --json --toon --pager
```

### fig witness
**Does** compares the fresh caption reading against `data/readings.md`, block for block on the `<ref>|<zone-suffix>` key both stores use, and classifies every one: `agree` (NFD-identical), `lines_differ` (same words, different printed-line division), `differ` (a character differs), and orphans either way.
**Reads** `review/captions/` — the adjudication where there is one, `review/captions/proposal.json` otherwise — plus `data/readings.md`.
**Writes** nothing.
**Exit** always 0. **Measurement never gates**, and here there is also nothing a caller could fix to make it pass: a disagreement is answered by a human ruling in `fig review`, never by editing either store toward the other — a store edited toward the thing being compared to it stops being a witness.
**Note** **`blind` is the report's load-bearing field and prints first.** "A comparison whose witnesses may be one witness must say so" (CLAUDE.md), and `docs/decisions.md` records the instance: `gt/ocr/` and `data/readings.md` corroborated three commas the machine had invented, because the caption text descended from the same recognizer pass, and only a fresh raster read separated them. A run whose reader had the old file open prints exactly this table and means nothing, so whether the reading declared itself blind travels with the numbers. Three-valued — true, false, and *unstated*, which is not the same claim as false.
**Note** **two ratified readings disagreeing is a finding, not an error.** `readings.md` is a human reading and so is the fresh one; which is right is settled against the scan, one caption at a time.
**Note** `lines_differ` is separated from `differ` because it is not a disagreement about the book: a caption's box decides where it wraps, so a moved line division is a fact about the segmentation.
```
--verdict {differ,lines_differ,all}  which rows to list [differ]
--root --json --toon --pager
```

### fig restore [PP-NNN ...]
**Does** writes the adjudicated caption text into `gt/fig/` — one `<String>` per printed line, inside one `<TextLine>` carrying the FigDesc block's own bbox. **This is the migration.**
**Reads** `review/captions/` (the ruling where there is one, the reading otherwise) and `gt/fig/`.
**Writes** `gt/fig/*.xml`, each with a `.prev` beside it and a line in `_journal.jsonl`, with `--commit`.
**Exit** 0, or raises on the refusals below. The report is the same with or without `--commit`, so a dry run answers "what would this change".
**Note** **the store is populated by restoring rulings, never by transcribing `data/readings.md`** — which is the whole point of having read the captions twice. What lands is what a human ratified against the scan, so the text can carry `#gt`: machine-shaped output a human confirmed, transcluded from its store and re-derived on every run. A caption in a markdown file could not claim that rank.
**Note** **the geometry is parsed and edited, never rebuilt.** `save_figs` goes through `zones.build_alto`, which mints a whole file from `{label, box, id}` — right for boxes and fatal here, since a rebuild is how the ids this text is keyed by would move. Every coordinate in the file afterwards is the one that was already there.
**Note** **one `String` per printed line, and the break is load-bearing.** 31 of the 196 multi-line captions carry a hyphen at the break and they are not the same hyphen: `Leaf-Tobacco`, `Netting-Shuttles`, `Ice-Scoop` are compounds a join must keep tight, while `Walrus-Hunt-ing` and `attach-ing` are wrap artifacts whose hyphen a join must drop. Nothing mechanical separates them, so the division is the evidence that the question exists. A line's own *indentation* is not: that is the compositor's, and `save_decisions` folds it away.
**Note** **geometry-less `String` is this corpus's universal practice** — 27,595 of 27,595 in `gt/ocr/` carry no `HPOS`. Several under one `TextLine` is the new part, and it is new because a caption's printed lines are a property of its one box: the segmenter that would have given each its own baseline is the one that dropped whole lines, which is why they were stripped in the first place.
**Note** **four refusals, `ocr restore`'s.** A block with neither a ruling nor a reading stops the page — a partial restore leaves holes `fig check` cannot see, since it can find an absent block but never an absent caption nobody expected. A target already holding text needs `--force`. An unlicensed mark (`detectors.MARK_LICENSE`, §2.6) refuses, catching what a human pass can miss rather than what it never saw. And `--commit` gates the write.
```
PP-NNN...     which pages; several may be given
--all         every page the figure store holds
--force       overwrite captions already in the store
--commit      actually write
--root --json --toon --pager
```

### fig review
**Does** serves every caption the two readings disagree on as one document — each with its own strip, `data/readings.md`'s reading beside the box, and the fresh reading in it — and saves the rulings into `review/captions/`.
**Reads** `review/captions/`, `gt/fig/`, `scans/`, `data/readings.md`.
**Writes** the adjudication into `review/captions/` — `decision.json`, one `.prev` and an append-only journal — on save.
**Exit** 0. A run with nothing to adjudicate says so and serves nothing rather than opening a browser on an empty page — resolved **before the socket is bound**, `ocr review`'s rule.
**Note** **this is `ocr review --issues` with a different block builder and a different store, and that is the whole design.** The issues page is already "every flagged field across many pages, in one guarded document", which is exactly what adjudicating caption disagreements is. A caption's key is a ref and a **zero-padded integer**, so it lands in the `(ref, index)` key space the template, `review-issues.js` and the save protocol already speak — no second template, no second palette, no second keyboard, no second save protocol. `review.review_context`'s block shape is reproduced key for key by `captions.review_context`, and `test_captions.py` holds the two together.
**Note** **the box opens on the reading that has *not* been ratified.** `data/readings.md` is the store today, so putting the fresh reading in the field makes letting it stand an act rather than an omission — and the old reading sits beside it read-only, where the line pass puts the previous line. A caption has no previous line; it has a second witness.
**Note** **every field needs a ruling, including "fine".** The page saves whole or not at all and refuses a blank note, `ocr review --issues`' guards and for their reason: on a document whose fields belong to different keys, a half-filled form is the one thing worth refusing outright. The prior-text check is carried from the first commit rather than after the first incident, every document here being cross-page by construction.
```

--port N      serve on this port instead of the editor's registered one

```

### fig zoom KEY
**Does** magnifies one caption block and slices it into overlapping strips sized so `zoom`× fills the client exactly, packed onto as few sheets as fit.
**Reads** `gt/fig/` and `scans/`.
**Writes** `review/captions/zoom/` (derived).
**Exit** always 0; a key naming no caption block is a usage error.
**Note** **for a Tier-1 glyph the contact sheet could not settle, and for nothing else.** 34 of the 395 captions carry a Tier-1 glyph at all — the store is ~26 KB of mostly plain English at a 66-character median — so the other 361 are settled at 1× and magnifying one spends images re-reading what has already been read. The stipulation is stated rather than enforced: a mechanical gate was built first and measurement killed it. `detect_all` flags every *correctly transcribed* Tier-1 form (`Uñiˊsak`, `Nuˊnlig̣ren`, `Valkaˊʟᴇn` all return `inventory_glyph`) and flags **nothing** on the partial reading a reader can actually type before they can read it — `Ka'ka`, `Kere?tkun`, `gin` and `qaa` all detect clean. Naming the question before the call is also what separates re-aiming a miss from asking the same thing louder.
**Note** **pad 0, unlike `fig sheets`.** The contact sheet pads to show a printed line the box may have missed; a zoom answers a question about a glyph *inside* the box, so padding would spend magnification on the neighbours.
**Note** 2× default and **4× the ceiling**, the project's rule: at 300 dpi a character is ~30 px and every ink pixel is already a 4×4 block, so past it a magnifier returns the resampler rather than the page. Nothing is sharpened, denoised or upscaled beyond the integral resize — filtering manufactures evidence rather than revealing it, and isolation is the whole benefit.
**Note** the region is `caption_strips`' own, so a zoom is the *same* block enlarged rather than a second guess at where it is. That is the point of the verb existing: the alternative readers reach for is `convert` with hand-typed pixel bounds, which no later reader can check and which names the wrong region the moment a coordinate is fat-fingered.

**Reads** the named farms' directories, plus the stores that decide each one's membership. Tests directories itself rather than going through a guarded enumerator — the verb that reports absence has to be callable in its presence.

Nothing here opens pixel data or the timestamps behind it, so `state: ok` must not be read as "up to date". This entry used to justify the column by calling the blot tree's freshness *uncheckable*, which was false: see `zones blot`. ## train

The three models this project trains, one **track** each: the zone segmenter
(`zones`), the figure segmenter (`fig`) and the text recognizer (`ocr`). Four
acts apiece — mint the held-out split, lay out the training set, install a
checkpoint, score one — which is what makes this a group rather than three.

Everything about the *stores* stays behind: `zones predict`, `fig predict` and
`ocr predict` write `mz/` and are inference; `fig propose` is a rule; `zones
blot` paints rasters; `check`/`edit`/`delete` are each store's own.

**TRACK is a positional with a per-action pool**, `views build FARM`'s shape and
for its reason — a selector spelled as a flag is what that group already decided
against, `--only` meaning "line indices" throughout `ocr`. A one-value pool
(`train remap zones`) is honest: it says the act exists and applies to one track,
which is not the same statement as the act not existing. `ocr` is absent from
`install` and `score` because the recognizer has never been trained and neither
action exists for it yet.

**No `--all`.** Relinking every farm is one coherent act, which is why `views`
has one; assembling three unrelated training sets is not, and "everything" on the
most expensive verbs in the harness would be a trap.

**A flag that does not apply to the named track exits 2 rather than doing
nothing** — `--batch` is ocr's, `--min-iou` is fig's, `--model`/`--decode`/
`--jobs` are zones'. This is the capability objection that kept `zones blot` and
`fig crops` out of the `views` fold, and the refusal is what answers it: nothing
became inexpressible, and asking for it where it means nothing is an error.

**`--model` means one thing here, and Phase 1 of the fold is why it could.**
`train score zones --model` loads a checkpoint and segments in memory. `train score fig
--model` accepted a path, printed it in the report and **never opened it** — the
comparison is always `mz/fig/` against `gt/fig/`, so the report named a model it
had not consulted. Under one verb the flag means "score this checkpoint in
memory" and is refused for `fig`. What `train score fig` reports instead is the
producer read out of the store itself, which is the question `--model` was
pretending to answer; `corpus provenance` is the census over those records.

**Nothing here trains anything.** `assemble` reports the `ketos` invocation and
returns; a run holds the GPU for hours and belongs in the operator's own
terminal. The loops are `.claude/skills/train-zones/`, `train-figures/` and
`train-ocr/`.

### train remark-eval TRACK
**Does** mints or extends a track's train/eval split — stratified per part, independent pages first, spread rather than taken off the front. **Additive**: a mark a human already made is never moved.
**Reads** *zones* — `gt/zones/`, the split lists.
**Reads** *fig* — `gt/fig/`, `gt/zones/`'s splits and `_ink_cache.json`.
**Reads** *ocr* — `gt/ocr/`, and the two split lists in it.
**Writes** *zones* — the split lists under `--commit`.
**Writes** *fig* — the two lists, with `--commit`.
**Writes** *ocr* — `gt/ocr/_train.lst`, `gt/ocr/_eval.lst` under `--commit`. Tracked — a split a model trained on is a record, not scratch.
**Exit** always 0 on every track — bookkeeping.
**Note** *fig* — the universe is **every page with a figure ALTO — exempt plates included** — plus the pages *witnessed* to have none. Exemption is a zone-track statement about the text column; plates are where figures live, so holding them out would hold out the corpus. Measured today: 252 positives, 506 negatives, and **44 of the positives are exempt pages**.
**Note** *fig* — **a negative is a keyed, non-exempt page whose ink verdict is `clean`, with no `gt/fig/` file.** The ink check is the witness — every band of ink accounted for by text zones alone, so there is nothing left for a figure to be. `1-191` is the proof it works: that check, not exemption status, is what exposed its undeclared photograph. A page whose bands were *excused* reads `ruled`, not `clean`, and is **unknown** rather than negative — an exemption makes the check read clean while hiding exactly the ink a figure would be. The live instances are `1-033`, `1-035`, `1-036`, all "scanner artifact".
**Note** *fig* — **the `unknown` count is reported, always.** The verdicts come from `gt/zones/_ink_cache.json`, which is derived and gitignored, and a stale entry reads unknown rather than clean — on a cold cache that is every page. A run that quietly trained on whatever negatives it happened to find would look exactly like a run on a small corpus, so the number is in the report and the note names `zones check --all --ink`.
**Note** *fig* — additive: a mark a human made is never moved. Held out has to stay held out, or the eval set drifts with whatever was keyed most recently and stops being one.
**Note** *ocr* — **the unit is the page, and this is the decision the track turns on.** kraken's own `--partition` divides the pooled *line* set and every recipe online uses it. Lines off one leaf share its ink weight, its wear, its bleed-through and the compositor's stick, so a model that has seen forty lines of a page has seen the conditions under which the other ten were printed. A line-level split then measures memorising a page rather than reading a new one — **and measures it high**, which is the direction nobody goes looking. `assemble` always passes `-t`/`-e`, which is what turns `--partition` off: kraken sets it to 1 when an evaluation set is named.
**Note** *ocr* — the default fraction is **0.10 against the two segmenters' 0.20**, because the unit here is a line: a tenth of 717 pages is ~3 000 held-out lines, where a tenth of the zone corpus would be a few dozen pages. Both tracks want an eval set big enough to separate two models; this one buys it for proportionally less of the training data.
```
TRACK         which model. One of: zones, fig, ocr
--fraction F  share to hold out [the track's own: 0.20 for the segmenters,
              0.10 for ocr, whose unit is a line]
--commit      write the split marks [off — reports]
--root --json --toon --pager
```

### train assemble TRACK
**Does** lays out a track's `train/bogoras-*/data/` from its split marks and **reports** the `ketos` invocation. Runs nothing.
**Reads** *zones* — `gt/zones/`, `scans/w-figs-blotted/`, the split lists.
**Reads** *fig* — `gt/fig/`, its split lists, `scans/`.
**Reads** *ocr* — `gt/ocr/`, the split lists, `scans/w-figs-blotted/`, `gt/lines/`.
**Writes** *zones* — `train/bogoras-seg/data/` — the page links, the folded ALTOs and `train.lst`/`eval.lst` — and makes the empty `train/bogoras-seg/model/` the reported command writes its checkpoints into. Pure scratch, clobbered freely, because the split a model trained on travels in that model's own manifest.
**Writes** *fig* — `train/bogoras-fig/data/` — symlinks, synthesized ALTOs for the negatives, and `train.lst`/`eval.lst` — and makes `train/bogoras-fig/model/`, where the run's checkpoints go. Pure scratch; clobbered on every run.
**Writes** *ocr* — `train/bogoras-ocr/data/` (pure scratch, cleared on every run) and `train/bogoras-ocr/model/`, the latter empty so the reported `-o` runs as printed — kraken creates the output directory it is given but not its parents.
**Exit** *zones* — 1 if any listed page has no blotted raster.
**Exit** *fig* — always 0.
**Exit** *ocr* — 0 clean, 1 if any page's blot is missing.
**Note** *fig* — **the raster is the raw `scans/` page, never the blot.** `train assemble zones` links `scans/w-figs-blotted/` so the zone segmenter cannot learn figure-shaped body zones; here the blot paints this model's *target* white, so training on it would ask the model to find something that has been erased. It is also why these are two models rather than one with four classes: they read different rasters.
**Note** *fig* — **a negative page's ALTO is synthesized here and stored nowhere.** `gt/fig/` never holds an empty file — absence is how it records "no figures", and `zones blot`, `ocr gaps` and the reader dispatch all read an existing file as "this page has figures". Verified against kraken 7.0.3 rather than assumed: an empty-region ALTO parses to a `baselines` container with no regions and `BaselineSet.add` accepts it as a page with none, which is what teaches the model that most pages are empty.
**Note** *fig* — the list entries are **relative and unresolved**. Resolving follows the symlink back to `gt/fig/` and silently trains on the store instead of the work dir — `train assemble zones` records that lesson and it applies verbatim.
**Note** *fig* — the command is **reported, not run**. Training holds the GPU for hours and belongs in your own terminal.
**Note** *ocr* — **the raster is the blot, the exact mirror of `train assemble fig`.** That track links the raw `scans/` because the blot paints *its* target white; this one links `scans/w-figs-blotted/` because that is what `ocr predict` reads. One rule, opposite conclusions: a model is trained on the raster it will be asked to read. A line polygon abutting an inset figure — `1-283` is the standing case — is dewarped with that figure's ink in it on the raw page and with white in it on the blot. A page with no blot is refused rather than substituted.
**Note** *ocr* — **two silent shrinks, and neither fails.** kraken's `_validate_manifests` reads `-F`/`-t`/`-e` line by line, keeps what `os.path.isfile` accepts and **logs the rest as a warning**, so a `.lst` written with the wrong relative prefix compiles a smaller dataset and exits 0 — compare the line count `ketos compile` prints against `train_lines`/`eval_lines` here, which already exclude the empty lines `--skip-empty-lines` would drop. And a `gt/lines/` correction is a box a human drew over ink the segmenter left unboxed: `lines.page_lines` appends it at read time, so every other consumer in the harness sees it and `ketos compile -f alto` cannot. Reported apart as `corrections_excluded` rather than folded into a total — the one place in the harness where the merged view would overstate a set, by exactly the lines somebody went out of their way to add.
**Note** *ocr* — paths in the lists are **relative to the repo root and unresolved**. Resolving follows the symlink back into `gt/ocr/` and compiles the store instead of the work directory, which is `train assemble zones`'s recorded lesson and applies verbatim.
**Note** *ocr* — **the baseline `test` is reported with the run rather than left to be remembered.** Command 5 scores `models/catmus-print-fondue-large.mlmodel` over the same eval manifest by the same command as command 4 scores the fine-tune. A CER for a new model is not a result on its own; it is a result against what the corpus is read with today, taken the same way.
**Note** *ocr* — flags verified against `ketos --help` **and** kraken 7.0.3's own source, not against a tutorial. `-s`/`-d`/`--workers` are group-level, and on `ketos train` `-s` means `--spec`; `-u NFD` is said out loud because ketos normalizes nothing unless told and **`NFKC`/`NFKD` would destroy `ᵋ` U+1D4B and `˙` U+02D9**; `--resize union` keeps the base codec and appends the inventory where `new` would refit the output layer to this corpus alone, and kraken's installed `vgsl.py` trainer implements only `fail`/`union`/`new` — the help advertises `add` and `both` and `recognition.py`'s own mismatch error suggests `add`, and both crash, the trap `train assemble zones` already records for `segtrain`. `-e` takes a manifest naming a dataset, never a dataset, hence `data/eval.mft`.
**Note** *ocr* — the loop, its measured state and the judgement in it are `.claude/skills/train-ocr/`. There is no `train install ocr` yet — `ocr` is absent from that action's pool; it waits on a first run, there being no checkpoint to score and no evidence about what an install ought to refuse.
```
TRACK      which model. One of: zones, fig, ocr
--scratch  train from random init: no -i, kraken's default spec — the one configuration
           in which the class-map permutation cannot arise [off]
           installed recognizer [off]
--batch N  *ocr only* — lines per forward pass in the reported command [8] — the first
           thing to lower if the run runs out of VRAM
--root --json --toon --pager
```

### train install TRACK CHECKPOINT
**Does** scores a checkpoint, **refuses a permuted class map**, then installs it into `models/bogoras-*/` with a manifest and the split it consumed.
**Reads** *zones* — the checkpoint, `gt/zones/`, the split lists.
**Reads** *fig* — the checkpoint, both stores, `train/bogoras-fig/data/*.lst`.
**Writes** *zones* — `models/bogoras-seg/` under `--commit`.
**Writes** *fig* — with `--commit`: `models/bogoras-fig/` — the weights, a manifest, and verbatim copies of the two split lists.
**Exit** *zones* — always 0; refuses a permuted map with an error.
**Exit** *fig* — 0; refuses by reporting rather than by exit code.
**Note** *zones* — **the preview costs what the commit costs — ~11 min — and that is not an oversight.** The score runs before the `--commit` check because it is a *precondition* of installing: the permutation refusal is derived from it and the manifest embeds it, so a preview is "run every check, print the numbers, stop before writing", not a cheaper mode. It cannot score `mz/zones/` instead, which holds a different model's output — a comparison whose two witnesses may be one. And there is no cheap subset: the permutation map is derived on the training pages, so the 580 cannot be skipped to reach the refusal. **The second run is free**: predictions are cached on the checkpoint's own sha256 (see `train score zones`), so the `--commit` that follows a preview replays in about five seconds.
**Note** *zones* — **it scores with `dp`, the same decoder `train score zones` shows you, and the manifest records which.** It scored `raw` until 2026-08-22 — not by choice but because `score`'s *function* default disagreed with its CLI default, so installing a model measured it undecoded (61.3% precision against 90.8% on identical weights) and wrote that into the manifest, where it silently failed to match what `train score zones` printed for the same checkpoint. Both defaults are now `dp`, a test holds them equal, and the manifest carries a `decode` field: a figure with a 30-point twin has to say which one it is. **Manifests written before that date hold `raw` scores and no `decode` key.**
**Note** *fig* — everything that makes a checkpoint trustworthy is a **precondition of installing it**, so the score runs first, the manifest is written before the weights, and the copy is last — `train install zones`'s shape and its reasoning.
**Note** *fig* — with two classes the permutation test degenerates to a **swap test**, and it is still worth running: `--resize new` renumbers the output layer, and a model that learned "caption" on the channel it calls "picture" scores plausibly on counts while being wrong about every box.
**Note** *fig* — **refuses if `train/bogoras-fig/data/*.lst` are gone.** The split a run consumed has to be frozen beside the model, or its scores belong to a division nobody kept. Manifest paths are relative to the repo root: it is committed, and a record of one machine's filesystem is no record.
```
TRACK        which model. One of: zones, fig
CHECKPOINT   the .safetensors a run wrote — `best_<score>.safetensors` in the
             run's own directory, ketos putting the accuracy in the filename
--name NAME  installed model name [the track's own]
--device DEV torch device [auto]
--jobs N     worker **processes** for the scoring pass; 1 keeps the
             single-process path [cores, capped by free VRAM]
--commit     copy the checkpoint and its split into models/; preview otherwise
--root --json --toon --pager
```

## scans

The source rasters: the geometry the PDFs declare, what `scans/` actually holds,
and the swap that installs a re-cut tree together with every coordinate keyed to
it.

**`scans/` is derived and it is `#mz`.** It was `pdftoppm -r 300` over the *page
box* once, and the boxes these scans were wrapped in are arbitrary — part 1's
master sits centred with 43 px of white padding at a *fractional* offset, part 2's
was already the box and poppler smeared 247 grey values out of a 2-value source,
and part 3's was jammed onto A4 so the render was **cropped** ~35 px a side. Part 3
was segmented and OCR'd on that raster for twenty months. `extract` cuts from the
PDF's own MRC layers instead: the 1-bit JBIG2 master, with the embedded JPEGs
pasted back nearest at their integral scale.

**The group exists because none of this was reachable.** The cut was
`tools/extract_scans.py`, a script outside the package that no test could import,
and the geometry it wrote to `data/pdf_images.json` had no verb that read it back
— so "how big is this page, and in which coordinate space" was answered by
`identify`, a PIL one-liner or a guess. The three reporting actions are that
answer, and `space` is the standing version of a check that was previously made
once, by hand, during a migration.

**Provenance travels two ways.** The manifest's `_sources` block digests each
source PDF, and every cut raster carries a PNG `tEXt` chunk naming the file it came
out of and that file's sha256 — `harness/provenance.py`'s vocabulary (`harness`,
`kind`, `step`, `label`, `version`, `in.*`), because a raster copied out of the
tree leaves the manifest behind. Nothing in the chunk is a timestamp or an absolute
path, so two runs over the same PDFs are byte-identical and the tree stays diffable
against itself. `audit` re-reads the PDFs and makes a fuss if one changed.

### scans extract [PP-NNN...]
**Does** read the PDFs' own embedded layers and derive each page's geometry — the master, its placement, and every photograph on it — refusing any page it cannot read honestly. With `--rasters`, also cuts the tree. The geometry is derived **per page, never per part**: `1-303`'s master is 2824x3897 among 357 neighbours at 2781x3866, so a constant would be wrong there and silently.
**Reads** `pdfs/`. **Writes** `data/pdf_images.json` on `--commit`; `DIR/` and `DIR/pdf_images.json` on `--rasters`. **Exit** 0 clean · 1 a page was refused.
```
--all         every page of every PDF in pdfs/
--rasters DIR also cut the tree into DIR — a sibling, never scans/ — with the
              manifest it was cut at alongside it. Needs --all
--commit      write data/pdf_images.json. Needs --all
--jobs N      worker **processes**; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```
**Emits** `extract` (`pages`, `bitonal`, `composite`, `rendered`, `photographs`, `refused`, `manifest`, `rasters`) and `refused` where there is one.
**Note** **`--commit` and `--rasters` require `--all`, and refs are report-only.** A manifest is a statement about the whole corpus; written from three refs it would be a file that looks complete and holds three pages, which is worse than no file. The tree has the sharper version: a three-page tree carries a three-page manifest, so it would pass `swap`'s audit against its own manifest and install itself as `scans/`.
**Note** **it never writes `scans/`.** `swap` does. A raster is cheap and a bad one costs a re-run, but a raster in `scans/` whose geometry differs from the space the stores are keyed to is the defect this group exists to make impossible.
**Note** the refusals, each of which was a way of producing something plausible: two full-page images, a master not at scale 1.0, a photo rect outside its master, a non-integral paste, a decode whose size disagrees with the placement, and **a page named in `MASTERLESS` that turns out to carry a master**. That last is new. The set of three RGB leaves was asserted in two files and checked in neither, and it is exactly the set of pages whose two coordinate spaces differ by a *scale* — so a wrong member is every coordinate on that page wrong by a factor.
**Note** the `render` field is a **historical** number: the size poppler produced, recorded so that a store's old coordinates can still be recognised. It is not master + offset — that arithmetic misses by the right-hand margin — and it is read, never computed.
**Note** **serial, and there is no `--jobs`.** The per-page cost is a PNG encode, which is the GIL-releasing work `parallel.pmap` is for, but a `pymupdf.Document` is not safe across threads and a per-PDF pool is three workers for three files of very different lengths.

### scans swap DIR
**Does** install a cut tree, and move everything keyed to its geometry with it: the six coordinate stores translated, the band ledgers y-shifted, the ink cache dropped, the painted farms and the review working set discarded. Reports by default; the report is the per-page shift between the two manifests, what each store would do, and what would be discarded.
**Reads** `DIR/`, `DIR/pdf_images.json`, `data/pdf_images.json`, the stores. **Writes** on `--commit`: `scans/`, the stores, `data/pdf_images.json`, `data/_migrated.json`. **Exit** 0 clean · 1 refused, nothing moved.
```
--commit  perform it
--root --json --toon --pager
```
**Emits** `swap` (the headline: rasters to install, pages shifted, stored files rewritten, derived files discarded), `shifts` (pages whose space changed), `stores`, `dependents`, `touched_up`, and `refusals` where there are any.
**Note** **the `dependents` table counts this run, not the dependency graph.** It listed every store as `translated` and every farm as `discarded` — true of what *depends on* the geometry, and printed directly above a `stores` block reading `migrated: 0`. A reader asking what a `--commit` would do got two answers in one report and the confident-looking one was wrong. Every row now carries `files` and `changes`, and `response` reads `—` where the answer is none; the `swap` block sums them so a no-op is legible without adding up a table. On a re-cut from the same PDFs the honest answer is 832 rasters installed, 0 pages shifted, 0 stored files rewritten.
**Note** **the shift is manifest-to-manifest, not the manifest's `offset`.** That field records where a master sat in the legacy pdftoppm space and is *spent* — the stores left that space and `data/_migrated.json` is the receipt. What a re-cut needs is `new placement − old placement`, per page. Reading `offset` would re-apply a shift already applied once.
**Note** **what "atomic" can honestly mean across six trees.** Not one syscall. Every translation is computed and digest-checked before anything is written, any refusal aborts the whole run with nothing moved, and the receipt records which manifest the stores are now in. That last is not ceremony: a zero shift leaves a page byte-identical, so "correctly untouched" and "not yet reached" cannot be told apart by looking. It is part 2's lesson — 2550x3525 before and after — generalised.
**Note** **where the two spaces are the same size and the shift is not zero, the run aborts.** No page box can say which side of the shift a file is on, and both guesses are wrong: "already" leaves every coordinate stale, "source" may shift a page twice. The render→master migration never met this because every page that moved also changed size.
**Note** **the dependents are composed from what already declares itself** — `migrate.STORES` for coordinates, and the farms whose own `reads` names `scans/` for pixels. That rule *excludes* the `select` leaf farms (`scans/plate/` and the rest), which are links by filename and unaffected by a shift; a filter on `kind` would have discarded them for nothing. And it names `review/*/crops` and its siblings rather than `review/*/`, which holds tracked adjudications.
**Note** **`gt/page-img/` and `gt/fig-img/` are reported and never touched.** They are a human's touch-ups cut from a raster, so a geometry change makes them stale — but nothing mechanical may rewrite an authored image, and a tool that regenerated one would overwrite the only copy of work no script can reproduce. The report names them as work a human owes.
**Note** the tree must carry `pdf_images.json` or it is refused: a directory of PNGs with no geometry cannot be placed, and naming a space for it would be the guess this group exists to refuse.

### scans info [PP-NNN...]
**Does** one page's geometry from the manifest and from the file on disk, with **whether the two agree** — master size, bit depth, colourspace, the placement, the recorded legacy render size, the leaf kind, pixels, mode, bytes, and what the raster says it was cut from. Every photograph's rect, native size, paste scale and ppi follow in their own table.
**Reads** `data/pdf_images.json`, `scans/`, `gt/zones/`'s split lists. **Writes** — **Exit** 0.
```
--all  every page the manifest holds
--jobs N      worker threads; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```
**Emits** `info`, and `photos` where the pages named carry any.
**Note** **this is the verb instead of `identify` or a PIL one-liner.** Neither can see the manifest, and the manifest is where a photograph's own resolution, the placement and the source digest live. The two halves are in one table on purpose: `agrees` is a fact neither source can state alone.
**Note** the photographs are their own table because a list-valued field degrades the whole outer table to the verbose form — `emit.py`'s rule.
**Note** `cut_from`/`cut_sha` are empty for a raster cut before the provenance chunk existed, which today is all of them.

### scans census [PP-NNN...]
**Does** the counts: bitonal, composite and rendered-at-own-size pages, photographs carried, master sizes and placements by population, and the bytes on disk.
**Reads** `data/pdf_images.json`, `scans/`. **Writes** — **Exit** 0.
```
--all  every page the manifest holds
--jobs N      worker threads; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```
**Emits** `census` and `classes`.
**Note** **one table of combinations, not three of marginals.** It printed master sizes and placements as separate distributions, and from those a reader cannot tell whether the single page at 2824x3897 is also the odd one placed at `(0, 0)` — it is, and it is `1-303`. The class is `(source file, colour, size, offset, photographs)`, which is `cut | sort | uniq -c` over the fields `pdfimages` reports, and the joint shape is what is worth reading: 16 classes over 832 pages, nine of them the ordinary body of one part and the rest exceptions.
**Note** **sorted by the class, not by its population.** Ordering by count interleaved the three parts and scattered the one-offs; sorted by key, each exception falls immediately after the class it is an exception to. The first page of a class breaks ties, so the order is total and two runs cannot differ.
**Note** **a class of five pages or fewer is named rather than counted.** A row reading `1 page` sends the reader away to find out which, and the singletons are the whole reason to look — the two covers, `1-303`, the foldout, `2-255`'s four photographs. `scans.NAME_AT_MOST` is the threshold.
**Note** **the counts are written down nowhere else, deliberately.** `CLAUDE.md` refuses to state them because a number in a file nothing regenerates goes stale; this is the command that answers instead. Today: 832 pages, 593 bitonal, 236 composite carrying 371 photographs, 3 rendered at their own size, 186 MB.
**Note** the `offsets` table is the shape of the whole problem in three rows — 358 pages at (21, 15), 272 at (0, 0), 202 at (−35, −9). One scan, three arbitrary paper sizes.

### scans audit [PP-NNN...]
**Does** the manifest against the tree on disk, and the manifest against its own sources: a page in one and not the other, a size that disagrees, a **mode** that does, a raster with no manifest entry, a source PDF whose digest has changed, and a raster whose embedded provenance names a different source than the manifest records.
**Reads** `data/pdf_images.json`, `scans/`, `pdfs/`. **Writes** — **Exit** 0 clean · 1 a gating finding.
```
--all  every page the manifest holds
--jobs N      worker threads; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```
**Emits** `audit` (`checked`, `findings`, `gating`) and `findings`.
**Note** **`gates` is a column, not a filter, and the split is the point.** A size or mode mismatch is a disagreement and gates. A source PDF this machine cannot see is *unverifiable*, not wrong — every worktree's `pdfs/` links dangle, as does a fresh clone's — and a raster cut before the provenance chunk existed is unwitnessed rather than defective. An audit that failed on those is one people learn to run with `|| true`.
**Note** **mode is checked against what the source is**, not against a list of modes seen: a bitonal page that came back 8-bit means something resampled it, which is the whole failure the tree was re-cut to undo.
**Note** `unwitnessed` is **one row with a count**, not one per page. A tree cut before the chunk existed is entirely unwitnessed, and 832 identical rows would bury every finding that is about a page — but the count is stated, because a silence there would read as "every raster is witnessed".
**Note** `swap` runs this same function over the tree it is about to install, against the manifest that tree carries. One check, two callers: a finding that read differently depending on who asked would be two checks.

### scans space [PP-NNN...]
**Does** which coordinate space each store's pages declare, read from each file's own page box against the manifest: `master`, the legacy `render`, or neither.
**Reads** the six coordinate stores, `data/pdf_images.json`. **Writes** — **Exit** 0 clean · 1 a page is not in master space.
```
--all  every page of every coordinate store
--jobs N      worker threads; 1 runs serially and builds no pool [cores, capped]
--root --json --toon --pager
```
**Emits** `space` (`files`, then a count per space) and `not_master`.
**Note** **this gates, where measurement usually does not.** The migration into master space is complete and has a receipt, so a page still declaring the old box will silently mis-place every coordinate on it. Reporting that at exit 0 would file a fault as a fact.
**Note** it walks `migrate.STORES` — the six real stores. `ocr/` and `zones/` are absent on purpose: they are the read views, and a view blends a ratified page and an unratified one under one name.
**Note** three answers and no fourth. `master` when the box is the master's own size, `render` when it is the recorded legacy size, and neither otherwise — a guess here would be a comparison between two coordinate systems presented as a fact.

### train score TRACK
**Does** compares a track's `mz/` store against its ground truth, per split and never blended.
**Reads** *zones* — `gt/zones/`, `mz/zones/` or `--model`, the frozen split lists.
**Reads** *fig* — both stores and the split lists.
**Writes** —
**Exit** *zones* — always 0 — measurement. Exit 2 if the frozen split lists are gone: without them the training pages cannot be told from the rest, and a comparison whose witnesses may be one witness must refuse.
**Exit** *fig* — always 0. Measurement never gates.
**Note** *zones* — **read the `independence` row before the recall figure above it.** A held-out set half of which is the model's own segmentation with the edges pulled straight measures how well the model agrees with itself, and the number cannot say so. `_independent` has been the rule `remark-eval` selects on since the set was drawn and nothing reported it afterwards; as of 2026-08-04 the frozen eval set is **64 independent of 138** (77 `geometry only`, 4 `identical`), i.e. the quota was filled past the independent pool. `no_prediction` reads 0 without `--model`, since the scored set is then the intersection of the two stores; with `--model` every keyed page is a candidate and the column is live.
**Note** *zones* — **`--model` is minutes, and a bare run is seconds.** Reading `mz/zones/` is ~0.1 s over the corpus; segmenting a checkpoint in memory is **~7 min under `dp`, ~11 min under `raw`** (measured warm against the installed model over 717 pages: 0.58 and 0.96 s a page), because that is what measuring a model *before* it is trusted costs. It draws a bar, and it ran silently until 2026-08-22, which is indistinguishable from a hung process. **Do not carry `ocr predict`'s ~14 s/page over to this verb** — that sweep traces baselines and this model is region-only, and the mistake was made here first, putting "~2.8 h" in this file for an eleven-minute run.
**Note** *zones* — **`--jobs` here means processes, and the pool is worth it because the sweep is CPU-bound with the card idle.** Measured with `/usr/bin/time -v`: 123% of one CPU over a 90 s run on a 16-core machine, GPU utilization indistinguishable from the desktop's own idle. Four workers do 206 pages where one does 73 in the same 100 s — **2.8×**, the same figure `ocr predict` measured for four processes. Each worker holds ~1.4 GB on the card, and the parent holds none: the cache key is the checkpoint's file hash, so nothing here loads a model unless it is going to segment with it.
**Note** *zones* — the predictions are **cached under `mz/zones/_pred_cache/`**, keyed on the checkpoint's sha256, the decoder, and (for `dp`) the config digest — so a re-run, or the `install` that follows, replays in about five seconds instead of segmenting again. `predictions_cached` in the report says how many pages came back that way. A stale entry is a miss, never a stale hit: each is stamped with its blot's mtime and size.
**Note** *fig* — **matched by area overlap, not by y.** `train score zones` pairs on vertical overlap because zones are bands; pairing figures that way would call two side-by-side pictures one match.
**Note** *fig* — **pictures and captions are scored apart.** They differ by an order of magnitude in area, so one blended figure recall would be carried by whichever class is commoner and would hide a model that finds every picture and no caption.
**Note** *fig* — **pages witnessed to have no figures are their own bucket.** Two thirds of the corpus is negatives, and a box predicted on one is a false positive with nowhere else to be counted; folding those into the picture precision would let a model that hallucinates on empty pages hide behind the pages that have some.
**Note** *fig* — per split and **never blended**, for `train score zones`'s reason: agreement on the trained-on pages is the editor's own judgement read back.

```
--model PATH       *zones only* — segment this checkpoint in memory instead of reading mz/zones/ [read mz/]
--decode {raw,dp}  *zones only* — [dp]
--device DEV       torch device [auto]
--jobs N           *zones only* — worker **processes** for the segmentation; 1 keeps the single-process path [cores, capped by free VRAM]
--min-iou F        *fig only* — area overlap at which a predicted box counts as found [0.5]
--root --json --toon --pager
```

## agents

Cache telemetry over a dispatched batch, and the contract the batch is dispatched
with. The only group that touches no corpus store: it reads Claude Code's task
transcripts, and writes one tracked file under `.claude/`. Nothing here gates.

### agents usage
**Does** per-agent cache reads and writes for one session's dispatched agents, then groups them into cohorts. **The opening total is the diagnostic** — `read + write` on an agent's first request is what its context cost to establish, whatever the cache did with it, so siblings dispatched with identical prompts must open at the same number. Two agents join one cohort when they agree on model *and* opening, which is exactly the condition under which they could have shared a cached prefix. Six readers dispatched together should appear as one cohort of six; appearing as six singletons means a byte varies ahead of the shared block, and the openings say how much. A large `tail` write is ordinary by contrast: content behind the prefix was going to be written anyway.
**Reads** `/tmp/claude-*/<project-slug>/*/tasks/*.output`. **Writes** — **Exit** always 0.
```
--session S  one session, by slug or id prefix — what tells two concurrent
             sessions apart when both are dispatching
--all        every session this project has transcripts for, not just the newest
--since T    only agents whose first request sorts at or after this: a duration
             back from now (30s, 5m, 2h, 1d) or an ISO date or stamp [no window]
--tasks DIR  the task-transcript directory [the newest session for --root's
             project that has any]
--plan {max20,max5,pro}  impute money as well as credits, against this subscription's
             published allowance — adds `pct_5h`, `pct_week` and `usd` to the
             cost section. One of `pro`, `max5`, `max20` [credits only]
--root --json --toon --pager
```
**Emits** seven sections, plus `also_dispatching` when it applies: `scope` (project, the session **names** in view, the agent types in them, and the agent count), `agents` (one row each — its `cohort`, type off `attributionAgent`, model, effort, TTL tier, `opening`, the `tail` written after it, terminal context `ctx`, `saved`, and the agent's `first` and `last` request stamps), `preamble`, `cohorts`, `classes`, `cost`, `warmth`.
**Note** **`cost` is the batch's bill, in credits, one row per cohort and an `ALL` over the scope.** Credits and not tokens, because the two rank batches differently: output costs five times input at every tier, so a fan-out that reads much and writes little is cheap in credits and dear in tokens. The token total that sums cache reads is the worst of the three — reads are free on a subscription and here run 34× the billed volume — and three chapters of this project were first reported off exactly that column, wrong by more than an order of magnitude in the flattering direction. `billed_in` is `in + write` (the rate does not distinguish them) and `free_read` is excluded from it, which is what the whole `read`/`write` split in this verb is for. `per_agent` is the column a dispatcher acts on, since an agent here is a page: it makes two batches of different sizes comparable, and it is what moves when the contract or the spec changes. `out_pct` says how much of the bill was output — the half a prompt change has to shift.
**Note** **an unpriced model gets no number, not a neighbour's rate.** `usage.rates` matches the family substring off the recorded model string, so `sonnet-5` and any successor carrying its family resolve; a family the table has never been told about reports `credits` as null with the model named in `note`, and the `ALL` row says how many agents it could not price so a total is never quietly partial. The rates differ by more than 2× between tiers, so a guess is not a small error and nothing downstream would re-open it.
**Note** **the `ALL` row is summed from the cohort rows, never re-costed over the pooled agents.** A scope can hold two models and one rate cannot be applied to both; costing the pool with a blank model reported a null total for a scope every row of which was priced. Its `per_agent` divides by the agents actually priced rather than the headcount.
**Note** the rates, allowances and list prices are one sourced block in `usage.py` (`CREDIT_DENOM`, `FAMILY_RATES`, `PLANS`), from <https://she-llac.com/claude-limits>. The published rates are all fifteenths, so the denominator is named once and the table holds numerators — a rate change is a row to edit rather than six decimals to re-derive. `usd` converts the monthly list price at 12/52 rather than a quarter: a week is not a month over four and the 8% gap is wider than most differences this table gets read for. **Nothing in `--plan` is measured** — it is arithmetic on that block, and the credits are the figure with a witness.
**Note** **`classes` is the batch's context decomposed into what it is made of** — one row per class per cohort, largest first, plus an `ALL` row carrying the sum the shares are taken against. `opening` is the shared prefix; `raster` an image read; `text` a file read; `command` a tool's stdout; `write` a Write or Edit; `message` a turn someone sent; `none` a reply that called nothing. Every request's growth belongs to exactly one class and the growths sum to the terminal context, so `pct` is a share of something real rather than of a total invented for the table. `mean` and `max` are what separate a class that is large because it is expensive from one that is large because it recurs: a fan-out where `raster` has a high mean is reading big crops, one where it has a high count is reading many.
**Note** **`refused` and `failed` are split out of `command`, and they are not the same finding.** A refused call never ran — a guard hook stopped it — so every token it cost bought nothing. A failed one ran and exited non-zero, which includes a gate doing its job: `proposal check` reporting an advisory lands in `failed` and is not waste. Only `refused` is unambiguously spend with no return, and it is the column to read when asking whether a standing brief and a guard allowlist agree. On the first batch measured this way, four readers spent 10 requests and 2,679 tokens on refusals — three of them trying `ls`, two `cat`, three a shell operator.
**Note** **`reply` is a column and not a class**, because it is orthogonal: every request has one and it belongs to no tool. Its `ALL` total is what the batch spent thinking and writing, as against what it read.
**Note** **requests are counted per `requestId`, not per record.** A request emits several usage records as it streams and the early ones carry a partial `output_tokens`; counting records ran `reqs` two to four times high and every sum with it.
**Note** **cohorts and preambles group by agent type**, not by model alone. Opening very nearly decides it — two types have different system prompts and so cannot open at the same total — but "very nearly" is not a grouping rule, and pooling two types' turn-1s reports a variant count for a batch that was fine.
**Note** the saving columns: `saved` is the prefix the warm siblings read instead of writing, `originated` what the batch made once, `if_all_cold` what it would have cost with no sharing, and `asymptote` the limit `(N-1)P / (N(P+W))` tends to, which is `P/(P+W)`. **An asymptote and not a ceiling, because it is never reached** — `(N-1)/N` is never 1, so even a batch where every sibling after the first opened warm reports a shortfall against it, and that shortfall is arithmetic rather than a defect to chase. `own` — the mean per-agent work beyond the prefix — sits beside it so the ratio is checkable rather than asserted: an asymptote near 50% means `opening` and `own` are near equal, which is a fact about the pass being measured and not a property of the arithmetic.
**Note** `ctx` is the agent's terminal context, which is the *shape* of the per-agent figure the harness itself reports — a terminal measure, not a sum, since an agent's context is re-sent every request — and lands within ~0.6% of it. It is **not** claimed as a reproduction; the exact composition is not established.
**Note** **`chars` is the one column not in tokens, and is signed because it is what a turn adds.** No per-message token count is recorded anywhere: `opening` covers the system prompt and the whole preamble undivided, and every preamble turn arrives before the first request, so there is no earlier measurement to diff against. A per-turn token figure would be a `chars/4` estimate beside nine measured counts, or a controlled experiment nobody has run — two agents of one type whose preambles differ in exactly one known way, with no memory write in between. That control matters: between two real batches the prompt shrank by 1,043 characters and the opening rose 154 tokens, because a reader had written a memory file and the memory index is in the system prompt.
**Note** **`preamble` is where a broken prefix is actually visible.** It is one row per user turn ahead of the first reply — the whole of what a launch order can affect — carrying that turn's label, its size, and how many *distinct* variants the agents in scope had of it. A cohort table says openings disagree; this says which turn disagrees, and since a prefix ends at the first differing byte, the first turn with more than one variant costs everything after it. A preloaded skill labels itself (`skill: read-moll-page`), so the question "what is the 21k?" is answered without opening a transcript.
**Note** **the default scope is one session, and `also_dispatching` says when that was a choice.** Two passes here fan out over pages — the Bogoras readers and the Moll ones — from different sessions, so both being out at once is ordinary. Bare `agents usage` reports the *newest* session, which with two batches running is a coin flip that can land differently between two runs of the command; every column would be right, about a batch you were not asking after. So any other session that has written within the subagent cache TTL is listed by id and quiet-time, and `--session` takes that id by prefix. It reports and never chooses: `scope` names the sessions actually in view rather than counting the directories searched, which under `--session` was every session the project has.
**Note** **the rows are ordered by `first`, not `last`.** Launch order is what the table is read for — one member of a cohort writes the shared prefix and the rest read it, so who opened first is who paid, and a stagger is a claim about `first` alone. Ordering by `last` let duration talk over launch order: an agent that opened first and ran long sorted below one dispatched minutes after it. Both stamps are in the row, so the gap between them is the agent's own span.
**Note** **the TTL is read, not assumed.** A request records which tier its write bought under `usage.cache_creation`, so `warmth` reports the measured clock rather than a constant taken from the documentation. Where agents in scope disagree the shortest wins: a prefix is warm only while every witness to it still is, and the optimistic reading would send a batch at a cold cache. `TTL` survives only as the fallback for a scope that wrote nothing, and says so in the row.
**Note** the system prompt is **not** in a transcript. It is inferred as `opening - preamble` and never reported as though it had been read, which is why `opening` is the figure this verb leads with.
**Note** **the cohorts are numbered, and the number is how a batch is named.** `c1` is the oldest cohort in scope and the newest has the highest number, matching the order `cohorts` prints in; the id appears on every `agents` row too, so which reader belongs to which fan-out is readable without matching openings by eye. **Scope-relative by construction** — the ids describe this invocation's grouping, so `--since` or `--all` renumbers them and nothing should store one. `agents transcript --cohort c4` is what they are for: a question about the batch rather than about one of its readers.
**Note** **a cohort of one claims nothing.** A lone agent had nobody to share with, so its opening is reported as `singleton — nothing to share` rather than as a shared prefix. Calling one agent's opening a shared prefix is the fabricated measurement this verb exists to catch, and it would be a poor thing for the verb to commit itself.
**Note** `missed` is `(agents - 1 - warm) x opening`: one member of a cohort must always write the prefix, so `agents - 1` reads is the ceiling. The gap is what staggering the first launch buys, and it is zero when every sibling after the first read what the first wrote.
**Note** **`warmth` is the only pre-flight signal there is.** The cache cannot be queried, so the age of the last request against the five-minute subagent TTL is the whole of what can be said — subagents cache on that clock even where the parent session holds a longer one.
**Note** **an unparseable `--since` is a usage error, not an empty result.** Comparison is lexicographic, so `5m` sorts *after* every ISO stamp there will ever be: before the relative form was supported, passing it filtered every agent out and printed an empty table at exit 0 — a wrong answer wearing the shape of a right one. The stamp is also truncated before comparison rather than carrying a `Z`, since transcript stamps have fractional seconds and `…:00Z` sorts after `…:00.5Z`.
**Note** the session is discovered from `--root`, whose path Claude Code slugs into the transcript directory name; the newest session *that has transcripts* wins, since a session that dispatched nothing has a `tasks/` directory too and picking it would report the empty batch as the batch.

### agents sync
**Does** refills the groundtruth-reader's transcluded blocks from the files they name, so the copy in its system prompt agrees with the source. Bare form reports which blocks have drifted and writes nothing.
**Reads** `.claude/agents/groundtruth-reader.md` and each `<!-- transclude: SRC -->` it names. **Writes** `.claude/agents/groundtruth-reader.md`, under `--commit`. **Exit** always 0; 2 if a transcluded source does not exist.
```
--commit     actually rewrite the agent file — bare form only reports which
             sources its blocks have drifted from
--root --json --toon --pager
```
**Emits** one `transclusions` row: the agent file, the count of `stale` blocks, the `sources` they came from, and whether this run wrote.
**Note** **the reader's contract has to be in its system prompt, and `keying_spec.md` has to stay one file.** The spec binds the collation pass and the human keying track too, so it cannot move into an agent definition; but a `Read` of it costs ~15k tokens per reader per page, behind the turn that varies, where nothing can share it. So it is copied in mechanically and `test_transclusion.py` fails when the checked-in copy and its source disagree — two copies with a gate between them, which is what this repo already does for `VERBS.md` and the click tree. What it forbids is two copies with a *comment* between them.
**Note** **`ocr queue` syncs too, and this verb exists because that is the wrong moment.** A spec edit made between batches leaves the agent file stale until the next dispatch, so the gate fails on a commit that has nothing to do with dispatching and the fix is a command whose other effect is to deal out a queue. `queue` keeps its write regardless: a batch dispatched from a stale contract is exactly the failure the gate exists to prevent, and there is nobody to ask at that point.

### agents transcript [AGENT ...]
**Does** one named agent's requests in order — or a whole cohort's under `--cohort` — with what each one added to its context and where that came from. **`added` is the column**: a request's whole context is `in + read + write`, so the difference between consecutive requests is what arrived between them. Reading down it catches a duplicated block, which no per-agent total can — a contract re-injected on resume showed up as +14,916 on request 2 of three separate readers, identical to the token, and was invisible in every summary. `note` and `detail` name the arrival from the tool the *previous* request called, since its result is what the growth is made of: `read raster moll-046.png`, `ran command … zoom moll-046:15,33`, `write file`. `via` says whether that growth was paid for — `read` is a context served whole from cache, `write` is the only kind that costs.
**Reads** `/tmp/claude-*/<project-slug>/*/tasks/*.output`. **Writes** — **Exit** always 0; 2 if no transcript matches an AGENT, if no cohort matches `--cohort`, or if neither AGENT nor `--cohort` is given.
```
AGENT...     agent id, or its leading characters — what `usage` prints
--cohort ID  every agent of one cohort — a batch, as `usage` groups it (c1, c2,
             …); exactly one of AGENT or this
--session S  one session, by slug or id prefix — scopes --cohort, whose ids are
             relative to the agents in view
--all        every session this project has transcripts for, not just the newest
             — scopes --cohort
--tasks DIR  the task-transcript directory [the newest session for --root's
             project that has any]
--root --json --toon --pager
```
**Emits** `transcript`, then the same `classes` breakdown `usage` prints per cohort — over whatever was named, so `--cohort` gives the batch's and a list of ids gives those agents'.
**Note** **`added` splits into `reply` and `result`, and the split is measured rather than apportioned.** What arrives between two requests is the agent's own reply — which stays in context — plus what its tool returned, and the reply's size is recorded on the earlier request, so subtracting it leaves the result exactly. The subtraction is checkable, not assumed: two readers refused an identical `ls` after replies of 4,843 and 4,634 tokens both came out at **138** for the refusal. That is the reason for the column — in the raw delta that call reads as +4,981, and 138 of it was the tool's, so `added` alone makes a reader that thought hard before a cheap call look like an expensive call. `result` is left signed: a negative would mean the decomposition does not hold there, and clamping it to zero would hide the one case worth seeing.
**Note** an AGENT matching nothing is a usage error, not an empty table: a mistyped id and an agent that never ran are different facts and only one of them is the caller's to fix. `--cohort` refuses the same way, naming the ids that are in scope.
**Note** **`--cohort` reuses `usage`'s own grouping rather than re-deriving one.** The cohort is already what the transcripts hold that is closest to "the batch you dispatched", and the per-request decomposition is already taken to build it — so this flag reads that walk instead of a second pass over the same files, which would be two paths to one number with two chances to disagree.
**Note** request 1 has no predecessor, so its `added` is the opening itself — the system prompt and the whole preamble in one sum, undivided because nothing in the record divides them.
