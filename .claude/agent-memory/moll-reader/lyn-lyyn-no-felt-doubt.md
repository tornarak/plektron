On moll-076, four headwords read at 1× on the full marked page as `-лын`
(`лыплявтылын`, `льумыткулын`, `люмн'ылын`, `ляплятылын`) — none of them felt
doubtful, the page is crisp letterpress and nothing about the crop looked
ambiguous. Zoomed together at 2×, all four were `-льын`
(`лыплявтыльын`, `льумыткульын`, `люмн'ыльын`, `ляплятыльын`). Zero of four
survived a closer look.

This is the same shape as [[gloss-side-faults]]'s stress-accent problem: the
error produces **no feeling of doubt** at reading time, so "zoom what's
doubtful" as a filter does not catch it — you have to zoom this specific
ending on principle, every time it appears, regardless of how legible it looks
at page scale. The skill prompt already names `-лын`/`-льын` as the single
most common error class in this book; this is a data point that it is not
exaggerating and that 1x confidence is not evidence here.

**The suffix is where it was found, not where it stops.** On moll-099 the same
drop happened three times *away* from the participle ending: `панэнальытван`
keyed `панэналытван`, its own printed plural `панэнальытванвыт` keyed to match,
and `панэнальыёчгын` keyed `панэналыёчгын`. None is a participle; the `ль`
sits mid-stem. What generalizes is not the suffix `-льын` but the **sequence
`ль` before `ы`** — impossible in Russian, ordinary in Chukchi — so a
Russian-shaped prior deletes the sign wherever it occurs, and the result is
always a legal-looking string.

**And it reaches the cross-reference targets too.** On moll-105 the gloss cell
`см. пылыльын` should read `см. пыльыльын` — the print sets `ль` twice, and the
first one lost its sign. That reader's own report says it checked every `-льын`
ending on the page; it did, and the ending here was right. The drop was earlier
in the word, in a cell nobody thinks of as a headword. A `см.` target is a
headword — it names an entry that has to be findable — so it earns the same zoom.

Two of the moll-099 three were caught only by the OCR witness, which keeps the sign
the reading dropped. That is worth knowing about your own confidence: on a page
where you have already corrected other letters, the `ь` you did not see still
does not announce itself.

**How to apply:** treat every `лы` in a headword at 1× as provisional, not just
a final `-лын`. Before finalizing the row, zoom it (batch several at once, it's
cheap) and specifically look for the small hook of `ь` between the `л` and the
`ы`. Do this even on a page that otherwise reads perfectly cleanly. If the
entry prints a `(мн. …)`, check the plural too — it inflects the same stem, so
it either corroborates the sign or exposes the drop, and keying both from the
same misreading is how a wrong stem gets two witnesses that are one. See
[[what-settles-a-letterform]] on why that corroboration is worth nothing.
